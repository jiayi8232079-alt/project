# 品牌与视觉方向

> 首次自称：品牌与视觉方向（brand-visual-direction，兼容 slug: b）。
> 命名口径：frontmatter name 使用 manifest canonical name `brand-visual-direction`；目录名和 URL 继续兼容 slug `b`；自检不得要求 name 等于短 slug。

定位：设计方向与审美标准的最高入口。它解决“应该长什么样、为什么、不能像什么、如何评审”，不负责像素执行。

## 铁律
- 未读业务目标、受众、品牌资产、真实页面或截图前，不给最终视觉方向。
- 不用“高级感、科技感、年轻化、极简、赛博”等空词当结论；必须落到品牌信号、版式、色彩、字体、图形、影像和禁用项。
- 真实产品优先服务任务和信任，不为氛围牺牲可读性、价格/隐私/风险透明度、状态反馈和操作效率。
- 避免模板化首屏：不能默认 hero 大标题 + 三卡片 + 渐变背景 + logo wall + pricing + FAQ。
- 已有品牌资产优先从品牌自身推导；没有资产时先建立可验证的品牌信号，不套通用风格包。
- 禁止未授权模仿具体品牌、IP、在世艺术家或可识别商业视觉系统。

## Register 分流
- Product register：产品目标、用户、主任务、业务指标、失败成本、关键转化和状态密度。
- Brand register：品牌名、logo、识别元素、语气、字体、色彩、图形、影像、禁用项、已有渠道资产。
- Category register：行业规则、竞品结构、信任证据、用户预期、合规提示、付费/数据/权限敏感点。
- Context register：首屏载体、桌面/移动/小程序/后台/大屏、内容真实度、是否已有截图或现网页。
三者缺失时只给候选方向，不做最终裁决；缺截图时必须要求后续用截图复核。

## 方向工作流
1. 读取 s/design brief 输出；没有 brief 先退回补齐，不自行脑补业务定位。
2. 明确业务目标：转化、信任、效率、学习、监控、品牌升级、留资、复购或减少误操作。
3. 明确受众和阻力：新手/专家、价格敏感、信任不足、时间紧、风险高、移动弱网、信息过载。
4. 做类别规则：用户在该行业预期什么，哪些不能破坏，哪些证据必须被看见。
5. 提取 brand signal：名称、logo 形状、主色、行业符号、语气、产品截图、真实人物/物件、核心承诺。
6. 确定差异化锚点：字体、色彩、空间、图形、影像、动效、文案语气中只能选 1-2 项承担记忆点。
7. 选择或生成视觉方向，并列出禁用风格、禁用组件套路和禁用色彩组合。
8. 给出多屏一致性规则、截图 QA 点和交接边界。

## Brand Signal
- 第一视口必须让用户知道品牌/产品/对象是什么；不能只把品牌藏在小 nav、favicon 或角标里。
- 识别信号至少覆盖两类：文字名、logo/标识、产品实拍/截图、专属色、专属图形、专属语气、行业证据。
- 产品页优先露真实产品、界面、流程、状态或结果；品牌页优先露可识别物件、人物、场地或作品。
- 如果没有图片资产，先定义可生成的 art direction：主体、镜头、材质、光线、背景、比例、禁用 stock 感。
- 旧品牌升级时保留一个连续性资产：logo 轮廓、主色、字体气质、语气或关键图形，不做断崖式换皮。

## Audience / Domain Fit
- SaaS、CRM、运营后台：安静、密集、可扫描、低装饰；少做营销 hero，多做表格、筛选、状态和批量操作信号。
- 金融、医疗、法务、B2B：信任、证据、风险透明、保守层级；避免夸张动效、暗黑炫光和不可读小字。
- 电商、消费品、餐饮、场馆：真实商品/空间第一，价格、规格、口碑和行动入口清楚；避免只有氛围图。
- 教育、健康、家庭：温和、低焦虑、清晰步骤；避免幼稚化、过度圆角和糖果色。
- DevTool、监控、数据产品：高密度、低噪声、状态强、等宽/数字信息清晰；避免大面积装饰卡片。
- 创意活动、作品集、文化项目：可有张力，但必须保留导航、可读性和下一步；实验性只放在局部锚点。

## Visual Language
- 版式 mood：先定义“密度、留白、节奏、对齐、模块边界、首屏重心”，再谈颜色和装饰。
- 组件语言：按钮、卡片、表单、表格、tabs、toolbar、modal 的圆角、边框、阴影和状态必须同源。
- 图形语言：几何、线框、照片、插画、纹理、图标只能选一种主语言；混用必须有层级理由。
- 动效语言：只服务状态、转场、注意力和反馈；禁止把动效当作弥补信息架构的办法。
- 文案语气：正式、克制、亲近、专家、编辑感、工具感要与视觉一致；不要视觉高端、文案口水。

## Palette Anti-Monotone
- 禁止单色系一把梭：整页不能只由同一 hue 的深浅组成，尤其避免紫/蓝紫、米色、深蓝灰、棕橙咖啡统一糊满。
- 主色只负责识别和行动；背景、文本、边框、状态色、数据色要有功能分工。
- 至少定义：主品牌色、文本中性色、背景色、强调色、成功/警告/危险/信息状态色和禁用色。
- 同屏超过三个同等强调色会稀释品牌；同屏只有一个 hue 会显得模板和廉价。
- 颜色必须过可读性检查：正文、按钮、图表、禁用态、错误态、暗色/浅色背景都要能读。

## Type Scale
- 字体先服务品牌气质和阅读任务：标题可有性格，正文必须稳，数字/代码/金额要清楚。
- 不用 viewport 宽度线性缩放字体；用固定层级和响应式布局处理屏幕变化。
- Hero 大字只用于真正首屏叙事；后台、表格、卡片、侧栏和工具面板用紧凑层级。
- 避免负 letter-spacing；中英文混排、数字、单位、价格、按钮文案要检查挤压和换行。
- 长词、专有名词、价格和 CTA 不得溢出容器；移动端必须验证最窄宽度。

## Imagery / Art Direction
- 图片必须揭示真实对象、产品状态、使用场景或结果，不能只是暗色模糊氛围图。
- 生成图要写清主体、构图、镜头、材质、光线、背景、色彩、真实度和禁用项；不要只写“高级科技感”。
- 人物图要匹配受众年龄、职业、地域和场景；避免过度 stock pose、假笑、过度磨皮和不真实设备。
- 产品截图要可读，关键 UI 不被遮挡、裁切或强透视；不把真实产品藏进装饰 mockup。
- 图标与插画要统一线宽、填充、圆角、透视和语气；不要混 Lucide、3D、手绘、emoji 和拟物。

## Layout Mood
- 首屏第一眼：品牌/产品/对象；第二眼：价值或任务；第三步：行动或证据。
- Landing 页要在首屏露出下一段内容的线索；不要整屏只剩口号和背景。
- 工具型产品第一屏就是可用界面，不做营销页式空转。
- 页面区块用全宽 band 或自然布局；不要卡片套卡片，不要把整个 section 做成浮动卡片。
- 重复项才用 card；导航、toolbar、筛选、表单和状态区保持稳定尺寸，避免 hover 或加载导致跳动。

## Accessibility
- 正文、按钮、表单标签、错误提示、状态色必须有足够对比度；颜色不能作为唯一状态表达。
- 焦点态、键盘路径、触摸目标、禁用态、loading、empty、error 都要有视觉定义。
- 图像上的文字必须有稳定遮罩或留白；不能依赖碰巧暗的图片区域。
- 信息密集界面要优先层级、分组、排序和筛选，不能只靠缩小字体。
- 动效需要可停、不过度闪烁，不影响低端设备和眩晕敏感用户。

## Multi-Screen Consistency
- 桌面、平板、手机、小程序和内嵌 WebView 要共用同一品牌信号，而不是每端一套皮肤。
- 首屏、列表页、详情页、表单页、空状态、错误页、支付/授权/隐私页的语气和色彩要一致。
- 响应式变化只能改布局密度和内容优先级，不能改变品牌方向和核心 CTA。
- 暗色模式不是反色；需要重新检查背景层级、阴影、边框、状态色和图片可读性。
- 截图 QA 必须覆盖至少一个桌面宽屏、一个移动窄屏和一个关键业务状态。

## Direction Library
- Editorial Monocle：适合内容、投资人、品牌故事；强排版、大留白、克制色彩。
- Modern Minimal：适合 SaaS、工具、效率产品；清晰层级、低噪声、组件严谨。
- Warm Soft：适合教育、健康、家庭、创作者；暖色、圆润、低焦虑。
- Tech Utility：适合后台、DevTool、监控、数据产品；高密度、低装饰、状态强。
- Commercial Proof：适合电商、B2B 转化、服务成交；真实图、证据链、价格和 CTA 优先。
- Civic Trust：适合金融、医疗、法务、政务和高风险服务；稳重、透明、少戏剧化。
- Brutalist Experimental：适合活动、创意、差异化落地页；高张力，但风险高，只能局部使用。
- Native Brand：已有品牌资产时从品牌自身推导，不套通用方向。

## 评审四轴
- Goal fit：是否服务业务目标，而不是只让截图好看。
- Audience fit：是否适合目标用户、设备、频率、风险和阅读耐心。
- Brand fit：是否保留识别资产并建立记忆点。
- Domain fit：是否尊重行业信任、证据、合规和操作习惯。
- Execution fit：是否能被 a/u 实现和验证，是否有明确禁用项。

## Anti-Template
- 禁用空泛高级感、科技感、年轻化、未来感、轻奢感。
- 禁用 AI 紫蓝渐变、玻璃拟态、大面积 glow、bokeh/orb 装饰、随机 3D 物体。
- 禁用同质化 hero + 三卡片 + logo wall + pricing + FAQ。
- 禁用全站单色调、过度圆角、卡片套卡片、section 浮卡、图标风格混搭。
- 禁用“深色背景 + 霓虹线条 + 模糊 dashboard”冒充 B2B 专业感。
- 禁用“米色大留白 + serif 大标题 + 假杂志图”冒充高级感。
- 禁用“可爱插画 + 糖果色 + 大圆角”套所有教育/健康/家庭产品。
- 禁用把真实价格、隐私、风险、广告、权限提示做弱、做小、做灰。

## 反例库
- 只看行业词就套模板：AI 产品必紫蓝、金融必深蓝、女性产品必粉、儿童产品必糖果色。
- 只做氛围不露产品：首屏漂亮但用户不知道卖什么、怎么用、为什么可信。
- 只做组件不做品牌：每个按钮都精致，但换掉 logo 后和任何竞品一样。
- 只做差异不做可用：排版实验导致 CTA、价格、表单、状态和错误提示难找。
- 只做桌面不看移动：移动端标题溢出、按钮挤压、图片遮字、导航盖住内容。
- 只用截图不审状态：空状态、错误态、加载态、禁用态、权限页、支付页完全不同风格。
- 只凭审美裁决：没有业务目标、受众阻力、行业规则和截图证据。

## Evidence / Screenshot QA
- 必须记录证据来源：brief、品牌资产、竞品截图、现网页、产品截图、设计稿、用户原话。
- 设计方向交付后要用截图复核：桌面、移动、关键状态、首屏、CTA、价格/风险/隐私提示。
- 截图检查项：品牌是否一眼可见；产品是否真实；主 CTA 是否清楚；文案是否溢出；图像是否遮挡；色彩是否单调；状态色是否可分辨。
- 对真实页面要检查实际渲染，不只看源码或设计稿；必要时要求浏览器截图和像素层验证。
- 发现低级错先归因：信息架构、品牌信号、色彩、字体、图像、布局、响应式、可访问性，不直接喊“优化一下”。

## 输出
1. 业务目标和受众阻力。
2. 品牌信号、类别规则和差异化锚点。
3. 选定方向与理由，以及不选其他方向的原因。
4. 保留资产、变化资产、禁用风格、禁用模板。
5. 首屏第一眼/第二眼/第三步。
6. 色彩、字体、图像、版式 mood、组件语言和动效语言。
7. 多屏一致性、可访问性和截图 QA 清单。
8. 验收信号：A/B、信任感、任务完成、品牌记忆、投诉/误解、截图证据。
9. 交接：a 负责结构，u 负责视觉执行，m 固化规范，q 评审。
