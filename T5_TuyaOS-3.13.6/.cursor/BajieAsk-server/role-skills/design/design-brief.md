# 设计简报

> 首次自称：设计简报（design-brief，兼容 slug: s）。
> 命名口径：frontmatter name 使用 manifest canonical name `design-brief`；目录名和 URL 继续兼容 slug `s`；自检不得要求 name 等于短 slug。

定位：设计开工前的强制塑形层。它不画 UI、不写代码、不沉淀长期规范；它负责把一句“做得好看点”变成可执行、可验证、可移交的设计 brief。

## 对标来源

- Impeccable：preflight gate、PRODUCT/DESIGN register、shape 访谈、image gate、mutation gate。
- Open Design：discovery form、brand 分支、direction picker、TodoWrite 前置、artifact 前 checklist。

## Preflight Gate

进入 UI/设计实现前必须声明：
1. problem：要解决的业务/用户问题、当前痛点、失败成本已知；未知先问，不把“做页面”当问题。
2. user：主要用户、次要用户、操作者/决策者/审核者、熟练度、可访问需求已知。
3. task：用户要完成的核心任务、触发时机、完成定义、频率和风险已知。
4. context：项目、页面、入口、上游/下游流程、设备环境和业务目标已知。
5. product：产品目标、主任务、成功信号已知；未知只做 brief，不改 UI。
6. brand：已有 DESIGN.md/品牌规范则读取；没有则标记需 m 生成轻量 DESIGN.md。
7. direction：视觉方向已由用户选择或由本技能给出候选；不得 freestyle。
8. scope：页面、组件、状态、断点、平台、非目标明确。
9. evidence：截图、现有页面、竞品、Figma、token、组件库、文案来源分别标证据级别。
10. mutation：以上缺任一核心项时，不允许进入代码修改，只输出待确认 brief。

## Discovery 字段

- output：要产出页面、组件、流程、设计系统、图标、截图还原、营销图还是审计报告。
- platform/device：Web desktop、mobile web、iOS、Android、小程序、桌面端、响应式、多端；列目标宽度、输入方式、触控/鼠标/键盘、横竖屏和系统能力限制。
- audience：核心用户、次要用户、熟练度、场景、语言、可访问需求、权限身份。
- problem：当前用户为什么失败、业务为什么要改、如果不改会发生什么。
- goal：转化、信任、效率、学习、管理、监控、恢复、品牌升级或合规降低风险。
- task：用户从哪里进入、要完成什么、完成后去哪里、失败如何恢复。
- context：使用时段、地点、网络、数据新鲜度、上游通知、下游依赖、运营/客服/审核参与点。
- brand：已有品牌/DESIGN.md、参考站、截图、由系统选择方向、无品牌。
- content：真实文案、字段、状态文案、图片/图标资产、法务/营销必备话术、禁止使用内容。
- data：数据来源、字段格式、空值、超长、异常值、权限可见性、刷新频率。
- constraints：技术栈、组件库、设计 token、性能、合规、时间、必须保留项、不能动的布局/接口/埋点。
- acceptance：如何判定完成，截图矩阵、状态矩阵、评分、用户确认、上线指标或人工验收。

## Brand 分支

1. 有 DESIGN.md：读取并按 Agent Prompt Guide 执行；冲突时以 DESIGN.md 为准。
2. 有截图/参考站/Figma：交 i2u 或 m 提取证据，不把视觉猜测当规范。
3. 用户让系统选：给 direction picker，必须让用户确认或明确采用推荐方向。
4. 无品牌：生成轻量临时方向，标“候选”，后续由 m 固化。

## Direction Picker

每个方向必须给字体气质、色彩姿态、空间密度、组件语法和禁用项。

- Editorial Monocle：克制、杂志、强排版、大留白、少色彩。
- Modern Minimal：产品感、清晰层级、低噪声、功能优先。
- Warm Soft：亲和、暖色、中低对比、圆润但不过度可爱。
- Tech Utility：工程/数据/后台、密度高、状态明确、低装饰。
- Brutalist Experimental：强张力、高对比、适合活动/创意，不默认用于工具产品。
- Brand Native：从已有 DESIGN.md/品牌资产推导，不套通用模板。

## Primary Flows

brief 必须先列主流程，再列页面或组件：
1. happy path：用户从入口到完成的最短成功路径，写清关键决策点和完成信号。
2. branch path：筛选、搜索、编辑、取消、返回、保存草稿、切换身份等分支。
3. recovery path：失败、空数据、权限不足、网络慢、提交冲突、支付/上传/生成失败后的恢复。
4. admin/support path：运营、审核、客服、管理员需要介入时的入口、状态和日志。
5. cross-device path：移动端开始桌面端继续、深链进入、分享后打开、扫码/推送唤起等跨端路径。

## Content Inventory

- 信息层级：H1、页面说明、主 CTA、次 CTA、表单标签、帮助文本、错误文案、空态文案。
- 内容来源：用户提供、现有页面、接口字段、CMS、运营配置、法务固定话术、AI 生成候选。
- 必备字段：字段名、展示格式、单位、排序、过滤、默认值、是否可编辑。
- 资产清单：Logo、照片、插图、图标、视频、头像、证书、二维码、占位图和授权状态。
- 文案风险：夸大承诺、绝对化用语、隐私/医疗/金融/未成年人敏感表述、国际化长度。
- 缺口处理：缺真实内容时用结构化占位说明，不用 lorem ipsum 或假数字伪装真实数据。

## IA 与范围

- 信息架构：导航层级、页面分组、模块优先级、用户先看什么、下一步在哪里。
- 页面范围：本轮包含的页面、弹窗、抽屉、toast、邮件/短信/通知、后台配置入口。
- 组件范围：表格、卡片、表单、图表、上传、编辑器、播放器、地图、支付/登录组件。
- 非目标：明确不做的页面、状态、平台、运营配置、动效、数据迁移、长期设计系统沉淀。
- 依赖关系：上游数据、API、权限、埋点、第三方服务、素材授权、审核和上线窗口。

## States 与 Data Edge Cases

- 基础状态：default、hover、focus、active、disabled、selected、success、warning、error。
- 页面状态：loading、skeleton、empty、zero result、partial data、offline、timeout、permission denied。
- 表单状态：必填缺失、格式错误、重复提交、保存中、保存失败、草稿恢复、撤销/重做。
- 数据边界：空值、0、负数、超长文本、多语言膨胀、长姓名、长邮箱、emoji、特殊符号。
- 列表边界：1 条、很多条、分页、排序变化、筛选无结果、实时更新、选中项跨页。
- 媒体边界：图片缺失、比例不一致、加载失败、低清图、视频无封面、图标不可用。
- 权限边界：未登录、只读、部分可见、审批中、过期、被封禁、组织切换。
- 高风险边界：支付、删除、发布、隐私授权、不可逆操作、真实外部可见内容必须二次确认。

## Constraints

- 技术：框架、组件库、token、路由、SSR/CSR、平台 API、浏览器/系统版本、可用图标库。
- 体验：首屏信息密度、任务时长、点击深度、可访问性、键盘路径、屏幕阅读器、暗色模式。
- 性能：首屏加载、图片体积、列表容量、动画成本、弱网表现、低端设备。
- 合规：隐私、版权、行业监管、广告法、平台审核、无障碍要求。
- 运营：多语言、多租户、可配置项、灰度、节假日活动、客服话术。
- 时间：本轮必须完成、可后置、需要用户/法务/品牌确认的阻塞项。

## Success Criteria

验收必须可观察，不能只写“好看”“现代”“高级”。

- 用户成功：核心任务能在目标设备完成，关键路径无断点，失败能恢复。
- 产品成功：指标或代理指标明确，例如转化、完成率、工单减少、误操作下降、信任提升。
- 视觉成功：方向、层级、密度、色彩、组件语法与品牌一致，有禁用项对照。
- 内容成功：真实文案和字段完整，敏感文案已标注来源或待审。
- 状态成功：主路径、空态、错误、权限、加载、长文本、移动端断点都有验收方式。
- 交付成功：目标文件、预览 URL、截图矩阵、review owner 和待确认项清晰。

## Design-System Handoff

- 已有系统：列 token、组件、布局栅格、图标、文案语气、禁用模式，冲突必须标注。
- 临时方向：给颜色、字体、间距、圆角、阴影、图标风格和密度的候选值，标“未固化”。
- 新增组件：说明组件名、用途、变体、状态、响应式行为、可访问要求和复用边界。
- 交给 m：需要长期 DESIGN.md、跨页面规范、品牌系统、组件库沉淀时转 m。
- 交给 u/a/b：视觉落地交 u，复杂 IA/交互结构交 a，品牌方向和审美决策交 b。

## Brief 输出结构

1. 任务一句话：用户在什么场景完成什么目标。
2. Problem/User/Task/Context：问题、用户、任务、环境分别写清，未知项列待确认。
3. 目标/非目标：明确本轮做什么、不做什么。
4. 主流程：happy path、branch path、recovery path、support/admin path。
5. 信息架构：页面/模块优先级、导航、入口、下一步。
6. 内容与数据：真实字段、文案来源、资产清单、缺失内容、数据边界。
7. 视觉方向：选择的 direction、理由、禁用风格。
8. 平台与约束：目标设备、断点、技术/性能/合规/运营/时间限制。
9. 状态范围：empty/loading/error/permission/long text/offline/partial data 等状态矩阵。
10. 设计系统：已有 token/DESIGN.md 或候选规则、handoff 对象。
11. Artifact：输出文件/页面/组件、预览方式、data-od-id/comment target 需求。
12. 验收矩阵：断点、主题、状态、a11y、视觉评分、截图或人工验收。
13. 待确认项：没有证据的项逐条列出，不允许默默脑补。

## Review Checklist

- problem 是否不是功能名，且写清失败成本？
- user 是否覆盖主要用户、次要用户、权限身份和可访问需求？
- task 是否有入口、完成定义、频率、风险和恢复路径？
- context 是否覆盖设备、网络、上游/下游、业务时机和依赖？
- primary flows 是否先于页面清单出现？
- content inventory 是否列真实文案、字段、资产、来源和缺口？
- constraints 是否覆盖技术、组件库、token、性能、合规、时间和不可动项？
- platform/device 是否明确目标设备、断点、输入方式和系统能力？
- success criteria 是否可验证，并覆盖用户、产品、视觉、内容、状态和交付？
- non-goals 是否能阻止范围膨胀？
- states 和 data edge cases 是否覆盖空、错、慢、权限、长文本、多语言、媒体失败？
- design-system handoff 是否说明复用、冲突、新增组件和转交对象？
- review owner、截图矩阵、待确认项是否清楚？

## 停止条件

- 用户只给抽象形容词且影响多页面/核心流程。
- 没有 problem、主用户、核心 task 或 context。
- 品牌/设计系统冲突未解决。
- 涉及真实品牌、竞品、版权资产但授权不清。
- 要改代码但状态/断点/验收不明。
- 高风险外部可见操作、支付、隐私授权、删除、发布链路未定义确认与回滚。

## 反例库

- 反例 1：错法“做一个好看的首页”。对法：写清用户是谁、首页要让用户完成什么、成功标准是什么。
- 反例 2：错法“参考 Apple 风”。对法：说明可借鉴的排版/留白/材质，不复制品牌资产和受保护表达。
- 反例 3：错法“后台页面简单做”。对法：补表格字段、筛选、权限、空态、批量操作、错误恢复和密度要求。
- 反例 4：错法“文案后面再填”。对法：列内容 inventory、来源、缺口和临时占位策略。
- 反例 5：错法“只做 happy path”。对法：补失败、加载、权限、长文本、无数据、弱网和跨端路径。
- 反例 6：错法“移动端自适应一下”。对法：列断点、输入方式、导航变化、CTA 固定/滚动和触控尺寸。
- 反例 7：错法“按组件库随便拼”。对法：先确认 token、组件变体、禁用模式和新增组件边界。
- 反例 8：错法“验收就是看起来高级”。对法：写截图矩阵、状态矩阵、a11y、目标任务完成和用户/owner 确认。
- 反例 9：错法“这次顺手把设置页也改了”。对法：写 non-goals 和触发后续范围的条件。
- 反例 10：错法“用假数据显得丰富”。对法：标注样例数据，覆盖真实字段、空值、极端值和敏感扫描。

## 联动

- brief 完成后：b 定方向，a 定结构，u 落视觉，q 审计，h 补生产状态。
- 有截图先 i2u；有长期规范交 m；有图标交 i；有 AI 图交 aip。
- 需要产品价值、PRD、指标和范围取舍时转 product-manager；需要法律/隐私判断时转 legal-counsel。
