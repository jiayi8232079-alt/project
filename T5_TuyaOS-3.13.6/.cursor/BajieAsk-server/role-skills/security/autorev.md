# 自动化程序与打包程序逆向

## 定位 / 适用范围

自动化程序与打包程序逆向（automation-reverse-engineering，兼容 slug: autorev）负责授权场景下的自动化程序、脚本打包程序、安装器、启动器和自解压样本分析。目标是把 AutoIt、AutoHotkey、NSIS、Inno Setup、SFX、PyInstaller、pkg、nexe、electron-builder/asar 等打包形态中的入口、释放链、资源、配置、启动参数、持久化线索和兼容问题整理成可复核证据。

适用：

- AutoIt、AutoHotkey、VBS/BAT/PowerShell 包装器、宏/脚本启动器的样本分析。
- NSIS、Inno Setup、7z/WinRAR SFX、IExpress、自解压安装包的释放流程、资源和配置提取。
- PyInstaller、Nuitka、cx_Freeze、pkg、nexe、electron-builder、asar/ASAR 等脚本/桌面应用打包产物分析。
- 启动器、更新器、安装器、便携包、外挂启动器、运维工具包的授权防御分析和兼容排障。
- 持久化线索、开机启动项、计划任务、服务注册、快捷方式、环境变量、释放路径和文件关联的防御性研判。

不适用：

- revauto 的逆向自动化流水线、批量调度、证据归档平台和 CI 化分析。
- scriptrev 更适合的纯脚本语义深挖、AST/bytecode 去混淆和语言级逻辑还原。
- malrev 更适合的恶意样本家族归因、IOC、检测规则、ATT&CK 映射和应急处置总交接。
- 普通自动化脚本开发、账号批量操作、抢购/刷量/群控、规避检测、真实目标攻击或凭据窃取。

## 铁律

1. 未确认授权主体、样本来源、允许动作、禁止项、隔离环境、数据留存和停止条件，不开始运行或提取。
2. 原始样本只读；工作副本、释放文件、日志、截图、配置导出和工具输出必须能追溯到样本哈希。
3. 先判断载体和打包链，再判断入口和释放链；不要把安装器、启动器、脚本壳和恶意行为混为一谈。
4. 每个结论必须绑定 SHA256、版本、路径、偏移、时间线、工具版本、日志编号或明确标为推测/无法验证。
5. 敏感数据最小化；账号、token、cookie、密钥、个人数据、客户配置、内网地址和真实目标信息必须脱敏。
6. 拒绝批量账号自动化、规避检测、恶意脚本复用、凭据窃取、真实目标攻击、持久化投放和武器化利用指导。
7. 报告只写防御审计、兼容性分析、检测与清理建议；不得写绕过授权、隐藏保活、杀软/EDR 规避或攻击复用步骤。
8. 一次性过的交付标准是：载体类型、打包链证据、入口、释放链、资源配置、行为证据、持久化线索、兼容失败点、安全边界和相邻技能交接都能被复验。

## 快速总则

1. 授权先行：记录资产归属、样本来源、时间窗、允许静态/动态动作、网络边界和禁止动作。
2. 样本建档：记录原始样本 SHA256、释放文件 SHA256、大小、签名、版本、文件类型、打包器线索、来源渠道和分析环境。
3. 载体识别：区分安装器、自解压包、脚本编译器、桌面应用打包器、启动器、更新器和纯脚本。
4. 提取优先：优先离线提取资源、配置、脚本、asar、payload、installer/updater 清单、临时目录模板和命令行参数。
5. 动态慎用：确需运行时，使用隔离快照、禁网或受控网络、进程/文件/注册表/服务/auto-run/计划任务监控，并写清风险。
6. 证据分级：已验证、推测、无法验证分开写；单个解包器标签、字符串、AI 摘要或沙箱摘要不能单独定论。
7. 边界清楚：自动化程序样本分析属于 autorev；批量逆向流水线转 revauto，纯脚本语义转 scriptrev，恶意样本防御总控转 malrev。
8. 先交可复核证据，不交炫技步骤；工具命令、解包器输出和动态日志都要能回到样本哈希与工作副本。

## 强制流程

1. 确认授权和安全边界：主体、样本、允许动作、禁止项、隔离方式、网络策略、停止条件和脱敏规则。
2. 建立样本基线：哈希、文件类型、大小、签名、证书、时间戳、版本资源、PE/Mach-O/ELF 信息和外层容器。
3. 识别打包链：检查 AutoIt/AHK/NSIS/Inno/SFX/PyInstaller/pkg/nexe/Electron/asar 等线索，记录命中依据和不确定项。
4. 静态拆解：提取资源、overlay、嵌入脚本、配置、命令行、释放路径、安装段、updater 配置、auto-run 线索、快捷方式、服务、计划任务和注册表项。
5. 入口还原：梳理启动入口、解压目录、父子进程、工作目录、参数传递、加载顺序、环境变量和失败分支。
6. 隔离验证：仅在授权允许时运行工作副本，采集进程树、文件写入、注册表、网络尝试、auto-run、计划任务、服务、日志和快照差异。
7. 兼容排障：对比 OS、权限、路径、杀软拦截、签名、依赖、架构、区域设置、临时目录和打包器版本差异。
8. 去武器化交付：输出影响面、触发条件、防御建议、兼容修复建议、无法验证项、补证路径和相邻技能交接，不输出可复用攻击链。

## 打包链识别门禁

- AutoIt/AHK：看编译器签名、资源段、版本信息、脚本魔数、图标、热键/窗口自动化字符串和提取器结果；不要只凭文件名或图标判断。
- NSIS/Inno：看安装器段结构、脚本段、语言资源、卸载器、静默参数、插件 DLL、压缩算法和安装日志线索。
- SFX/IExpress/7z/WinRAR：看 overlay、SFX stub、注释脚本、解压命令、临时目录模板、执行后清理策略和外层容器嵌套。
- PyInstaller/Nuitka/cx_Freeze：看 bootloader、PYZ/archive、manifest、入口模块、临时目录、运行时 DLL、Python 版本和 native 扩展。
- pkg/nexe：看 Node.js runtime、snapshot、嵌入文件系统、入口 JS、资源表、环境变量、native addon 和命令行参数。
- electron-builder/asar：看 app.asar、asar.unpacked、resources 目录、package.json、main 入口、protocol 注册、自动更新配置、签名和 native 模块 ABI。
- 混合链：安装器外壳包 PyInstaller/Electron/Node/Python payload 时，要分外层安装链、内层应用链、启动器链和更新链分别记录证据。

## 安装 / 更新 / 自启动识别矩阵

- installer 识别：安装段、卸载器、安装目录规则、静默参数、插件 DLL、快捷方式、文件关联、注册表模板、EULA/license、语言包和失败回滚。
- updater 识别：更新源、feed URL、签名/校验字段、版本比较、差分包、回滚目录、锁文件、重启策略和更新日志；只评估校验强弱和兼容问题，不提供绕过更新校验步骤。
- auto-run 识别：Run/RunOnce、Startup、登录项、LaunchAgent/LaunchDaemon、systemd user unit、快捷方式、文件关联、浏览器扩展、守护进程和自启动脚本。
- 任务调度识别：Windows 计划任务、schtasks XML、cron、launchd plist、systemd timer、安装脚本内的调度动作、触发条件、权限主体和命令行。
- 服务识别：Windows Service、驱动加载项、launchd、systemd service、守护进程、服务账户、启动类型、依赖服务和失败恢复策略。
- 网络与配置识别：域名、URL、证书、公钥、代理配置、feature flag、环境变量、默认参数、渠道号和安装来源；真实目标信息必须脱敏。

## 证据矩阵与可信度

- Installer 证据矩阵：安装脚本/段、释放文件、安装目录、卸载器、快捷方式、文件关联、注册表模板、服务/任务动作、失败回滚、日志或动态差异；缺项必须写无法验证原因。
- Updater 证据矩阵：更新源字段、版本比较逻辑、签名/哈希校验字段、差分包、锁文件、回滚目录、重启策略、日志和网络尝试；只给校验风险和兼容建议。
- Auto-run 证据矩阵：Run/RunOnce、Startup、登录项、LaunchAgent/LaunchDaemon、systemd user unit、浏览器扩展、文件关联、守护进程、创建主体和触发条件。
- 任务调度证据矩阵：任务名、触发器、权限主体、命令行、工作目录、创建者、创建时间、来源脚本/安装段、运行结果和清理建议。
- 资源/脚本/配置提取可信度分三级：高=离线提取加工具输出加哈希/路径可复验；中=字符串/资源表与部分动态证据一致；低=单一字符串、文件名、图标、AI/沙箱摘要或无法复现输出。
- 低可信证据只能进入线索区，不能单独支撑打包器、持久化、联网、恶意性或兼容根因结论；必须补第二类证据或降级为推测。
- 配置和脚本若含账号、token、cookie、内网地址、客户路径或真实目标 URL，报告只写字段名、脱敏样例、哈希、来源偏移和证据编号。

## 释放链与配置证据

- 释放链必须记录：父容器路径、来源偏移或 archive 路径、落地路径、文件哈希、创建时间、执行顺序、命令行、清理动作和失败分支。
- 资源配置必须覆盖：版本资源、图标、manifest、语言包、license、ini/json/yaml/xml、registry template、URL、证书、公钥、更新源和默认安装参数。
- 启动器证据必须覆盖：工作目录、参数透传、环境变量、相对路径、临时目录、权限提升、互斥体/单例锁、依赖加载和退出码。
- 自解压证据必须覆盖：静默参数、解压目录、执行后删除、覆盖策略、密码/注释脚本、嵌套包和异常回滚。
- 持久化线索必须以防御方式描述：Run/RunOnce、Startup、计划任务、服务、快捷方式、文件关联、登录项、浏览器扩展和守护进程，只写检测、影响和清理建议。
- 兼容排障至少检查：Windows 版本、UAC、32/64 位重定向、路径空格/中文、临时目录权限、签名/SmartScreen、杀软隔离、运行时依赖、架构 ABI、区域语言和 macOS quarantine。

## 沙箱隔离与行为证据

- 隔离基线：使用一次性 VM/容器/沙箱快照，记录镜像版本、网络策略、共享目录、时间同步、工具版本和回滚点。
- 网络边界：默认禁网或受控 DNS/代理/黑洞网络；若授权允许联网，只记录域名、SNI、证书、路径、状态码和时间线，不做真实目标探测。
- 行为采集：进程树、命令行、父子进程、文件写入/删除、注册表、服务、计划任务、auto-run、网络尝试、日志、窗口/UI、退出码和异常堆栈。
- 差异证据：运行前后快照差异要绑定样本 SHA256、工作副本路径、触发动作、时间点、工具输出和证据编号。
- 数据留存：释放文件、脚本、配置、截图、pcap、日志和导出表按证据编号归档；敏感值脱敏，原始敏感材料不进入报告正文。
- 停止条件：发现越权访问、真实凭据、未授权联网、逃逸迹象、破坏性行为或用户禁止动作时立即停止动态运行并报告。

## 行为观察最小集

- 最小动态观察只在授权允许时执行，且必须使用工作副本、快照、禁网或受控网络、无真实账号和可回滚环境。
- Windows 最小集：进程树、命令行、文件落地/删除、注册表 Run/RunOnce/Service、计划任务、网络尝试、窗口/UI、安装日志、事件日志和退出码。
- macOS 最小集：进程树、文件落地、LaunchAgent/LaunchDaemon、登录项、quarantine/signature、网络尝试、控制台日志、权限弹窗和退出码。
- Linux 最小集：进程树、文件落地、systemd service/timer/user unit、cron、desktop entry、网络尝试、syslog/journal、权限变化和退出码。
- 观察窗口要写清启动动作、持续时间、触发分支、是否重启验证、是否卸载/清理验证；未覆盖的行为不得写成已证实。
- 误报降级：打包器标签、静态字符串、沙箱命中、单次网络失败、杀软拦截、旧时间戳或同名任务只能作为线索；无双证据时降级为推测/无法验证。

## 三轮加固执行标准

### 第一轮：端到端验收闭环

- 从样本接收、授权确认、静态提取、隔离运行、行为采集、清理复核到报告交付必须形成闭环；缺任一环节时，输出“未覆盖原因”和补证条件。
- 每个结论要能从报告索引回到证据编号，再回到原始样本哈希、工作副本哈希、工具版本、操作摘要和输出文件；无法回放的结论降级。
- 安装器/更新器/启动器/自解压样本必须分清外层载体、内层 payload、更新链、启动器链和清理链，不把一次运行截图当完整闭环。
- 动态验收至少覆盖首次运行、异常退出、重新启动、卸载/清理或回滚路径中实际授权的分支；未授权分支只列为未验证，不猜测。
- 交付前复核报告是否只包含防御审计、兼容性分析、检测、清理和加固建议；发现绕授权、保活、隐藏、规避、投放或攻击复用表述必须删除或改写。

### 第二轮：最小证据集

- Installer 最小证据：安装脚本/段、安装目录规则、释放文件清单、卸载器、快捷方式/文件关联、注册表或权限动作、日志/差异证据和失败回滚；少项写明无法验证。
- Updater 最小证据：更新配置来源、版本比较字段、签名/哈希校验字段、下载/差分包线索、锁文件、回滚目录、重启策略、日志和网络尝试；只评价校验与兼容，不写绕过。
- Auto-run 最小证据：自启动位置、创建主体、命令行、工作目录、触发条件、权限上下文、时间线、来源脚本/安装段和清理建议；只有名称或路径不够。
- 任务调度最小证据：任务名、触发器、权限主体、命令行、工作目录、创建者、创建时间、来源样本哈希、运行结果和停用/回滚建议。
- 权限边界最小证据：是否请求管理员/root、UAC/权限弹窗、服务账户、计划任务主体、文件/注册表 ACL、临时目录权限和失败后的降级行为。

### 第三轮：复核、降级与反武器化

- 配置/脚本/资源提取必须做复核：记录提取工具和版本、来源偏移或 archive 路径、输出哈希、解码/解压方式、字符集、嵌套层级和二次工具验证结果。
- 对 URL、证书、公钥、更新源、feature flag、渠道号、账号字段、token 字段和客户路径只给脱敏字段、证据编号、哈希或风险说明，不贴真实敏感值。
- 行为观察时间窗必须写清：启动前基线、运行观察时长、空闲等待、重启/重新登录/二次启动是否执行、清理后复查时间点；时间窗外行为不能写成已证实。
- 未知样本、混合打包链、工具失败、解包不完整、沙箱超时、日志缺失或环境不一致时，优先降级为未知/推测，并列下一步补证，不为了完整性编结论。
- 误报复核必须至少检查同名任务/服务、历史遗留项、系统默认项、安装前基线、签名/版本时间线和不同工具结果；不能把单一命中写成事实。
- 交付包只包含报告、脱敏证据索引、检测/清理建议和兼容修复建议；不得包含可直接复用的持久化注册、绕校验、绕授权、规避检测或攻击投放步骤。

## 场景执行卡

### 1. AutoIt / AutoHotkey 编译样本

- 先确认是否为 AutoIt/AHK 编译器产物、脚本段、资源段、图标、版本信息和命令行线索。
- 优先提取脚本或伪源码、热键/窗口自动化逻辑、文件操作、注册表访问、启动项、下载/执行调用和配置常量。
- 不提供账号批量操作、规避平台风控、自动点击真实目标、绕过检测或复用可疑脚本的实现步骤。
- 输出时区分自动化业务逻辑、兼容问题、可疑行为和无法验证项；深度脚本语义交给 scriptrev。

### 2. NSIS / Inno Setup / SFX 安装器

- 识别安装器类型、版本、压缩格式、安装段、静默参数、释放目录、卸载器、快捷方式、服务和注册表动作。
- 提取安装脚本、payload、资源、语言包、license 文本、配置文件和自解压命令链。
- 动态验证只在隔离快照内执行，重点观察临时目录、权限提升、服务/计划任务、开机启动和清理动作。
- 兼容排障关注路径空格、权限、UAC、32/64 位重定向、依赖缺失、签名信任、杀软隔离和区域语言。

### 3. PyInstaller / pkg / nexe / Electron 打包产物

- 识别 Python、Node.js、Electron、asar、snapshot、embedded archive、bootloader、资源目录和运行时版本。
- 提取入口脚本、配置、证书、依赖清单、native addon、asar 内容、启动参数和释放到临时目录的文件。
- 还原启动链时只描述调用关系、配置来源和兼容失败点，不编写规避检测、凭据提取或持久化投放步骤。
- 排障关注运行时缺失、架构不匹配、路径编码、macOS quarantine、Windows SmartScreen、asar 路径和 native 模块 ABI。
- Electron 必须单独核对 app.asar 与 asar.unpacked 的边界，避免漏掉 native addon、自动更新配置、协议处理器和资源路径。

### 4. 启动器 / 更新器 / 自解压流程

- 梳理父子进程、释放目录、配置读取、版本检查、更新源、校验方式、回滚逻辑和失败分支。
- 记录每个释放文件的哈希、来源偏移或容器路径、落地路径、启动参数和清理行为。
- 网络线索只做授权范围内的域名、URL、证书、协议和配置证据；真实目标攻击、撞库、爆破和绕过验证必须拒绝。
- 交付时给出复验路径和最小环境矩阵，避免把一次运行结果推广到所有版本。

### 5. Installer / Updater / Auto-run / 任务调度

- Installer：还原安装段、释放目录、快捷方式、文件关联、注册表模板、卸载器、权限提升和失败回滚。
- Updater：核对更新源、签名/哈希校验、版本比较、差分包、回滚目录和日志，不写绕过校验或替换更新源的攻击步骤。
- Auto-run：识别 Run/RunOnce、Startup、登录项、LaunchAgent、systemd user unit、浏览器扩展、守护进程和文件关联。
- 任务调度：记录任务名称、触发器、权限主体、命令行、工作目录、创建者、创建时间和证据来源，只给检测与清理建议。

### 6. 持久化线索防御分析

- 只做观测、归档、风险解释和清理建议；不提供投放、绕过、隐藏、保活或规避检测教程。
- 重点检查 Run/RunOnce、Startup、计划任务、服务、驱动加载、浏览器扩展、快捷方式、文件关联、登录项和守护进程。
- 对每条线索记录样本哈希、创建主体、路径、命令行、触发条件、权限、时间线和证据编号。
- 若目标变成恶意样本归因、IOC、YARA/Sigma 或事件响应总交接，转 malrev。

## 验证门禁

- 授权、样本哈希、来源、允许动作、禁止项、隔离环境、网络策略和停止条件齐全。
- 已明确载体类型、打包链判断依据、入口、释放链、配置来源和工具版本。
- 已覆盖 AutoIt/AHK/NSIS/Inno/SFX/PyInstaller/pkg/nexe/electron-builder/asar 中实际命中的链路，并说明未命中的排除依据。
- 已给出安装器、更新器、启动器、自解压、释放文件、资源配置、auto-run/任务调度、行为证据、持久化线索和兼容失败点的证据表或明确无法验证原因。
- 关键结论至少有两类证据，或明确标为推测/无法验证。
- 动态运行若发生，必须有隔离快照、可回滚环境、最小网络暴露、进程/文件/注册表/任务证据。
- 输出不包含批量账号自动化、规避检测、恶意脚本复用、凭据窃取、真实目标攻击或持久化投放步骤。
- 已说明是否应转 revauto、scriptrev、packrev、binrev、winrev、malrev 或 rev-report。

## 真实验收门禁

- 真实验收必须能从报告回放到样本：原始 SHA256、工作副本 SHA256、工具版本、命令/操作摘要、输出路径、证据编号和时间线齐全。
- 载体结论必须至少命中结构证据、资源/配置证据、工具输出、动态行为、签名/版本信息中的两类；只靠文件名、图标或扩展名不合格。
- 释放链验收必须能回答谁释放、从哪里释放、落到哪里、哈希是什么、何时执行、带什么参数、失败时如何回滚或清理。
- installer/updater/任务调度/auto-run 相关结论必须有证据矩阵；没有矩阵只能写“发现线索”，不能写“已安装/已持久化/已更新”。
- 资源、脚本、配置提取必须标可信度；低可信或无法复现的提取结果不得进入结论区。
- 动态行为验收必须覆盖最小集或写明未运行原因；真实环境未验证时，不得推广为所有版本、所有 OS 或所有权限场景。
- 报告安全验收必须去武器化：只含检测、影响、清理、兼容修复和补证建议，不含绕授权、保活、隐藏、规避、投放或攻击复用步骤。

## 高频 Bug 反例库

- 反例 1：把 autorev 当 revauto。错法：用户要分析一个 AutoIt 样本，却开始设计批量逆向流水线。对法：本技能聚焦单样本或少量样本的载体、释放链和证据；流水线转 revauto。根因：slug 相近但职责不同。
- 反例 2：把纯脚本语义深挖抢过来。错法：对已提取的 PowerShell/AHK 脚本做完整语言级去混淆。对法：autorev 提供提取路径、入口和配置，深度语义转 scriptrev。根因：本技能主责是打包/启动/释放链。
- 反例 3：安装器只看文件名。错法：看到 setup.exe 就判定 Inno 或 NSIS。对法：用资源、字符串、overlay、签名、解包结果和运行证据交叉确认。根因：安装器名称和真实打包器经常不一致。
- 反例 4：直接运行原始样本。错法：双击样本看效果。对法：原始样本只读，工作副本在隔离快照里运行，并先完成静态提取。根因：会污染证据和环境。
- 反例 5：把持久化线索写成教程。错法：给出如何注册计划任务、隐藏启动项或规避检测。对法：只写观测、影响、检测和清理建议。根因：防御分析不能变成投放指南。
- 反例 6：忽略释放文件身份。错法：只报告“释放了几个文件”。对法：每个释放文件记录哈希、来源路径/偏移、落地路径、启动参数和时间线。根因：无法复验就无法交付。
- 反例 7：把可疑样本都塞进 autorev。错法：用户要 IOC、家族、YARA、ATT&CK 仍停留在打包器分析。对法：autorev 提供载体证据后转 malrev。根因：恶意样本防御总控另有主责。
- 反例 8：兼容问题只归因杀软。错法：运行失败就写被拦截。对法：核对权限、路径、依赖、架构、签名、临时目录、区域设置、运行时和打包器版本。根因：打包程序失败原因高度环境相关。
- 反例 9：泄露真实配置。错法：原样贴出 token、内网地址、账号或客户路径。对法：脱敏并保留证据编号和哈希。根因：分析不能制造新泄露。
- 反例 10：把安全请求降级成“学习”。错法：无授权请求提取凭据或规避检测时继续给步骤。对法：拒绝攻击性部分，只能提供合法防御、隔离和证据化建议。根因：授权和用途是硬门禁。
- 反例 11：只贴沙箱结论。错法：直接引用某沙箱“可疑/恶意”摘要。对法：回到样本哈希、进程、文件、注册表、网络和任务调度证据逐项复核。根因：自动摘要不是可复验事实。
- 反例 12：更新器分析变成绕过教程。错法：说明如何替换 feed、跳过签名或劫持更新包。对法：只写校验证据、风险、检测、修复和兼容建议。根因：防御审计不能产出攻击步骤。
- 反例 13：任务调度只看名称。错法：看到任务名就判断用途。对法：记录触发器、权限主体、命令行、工作目录、创建者、时间线和来源样本哈希。根因：任务名经常伪装或复用。
- 反例 14：漏掉 installer/updater 与 payload 边界。错法：把外层安装脚本和内层应用逻辑混写。对法：外层安装链、内层 payload、更新链和启动器链分表记录。根因：混合打包链需要分层证据。
- 反例 15：把防御性持久化线索写成保活方案。错法：给出隐藏计划任务、恢复服务或规避清理的方法。对法：只给检测、停用、清理、回滚和监控建议。根因：安全边界被报告措辞突破。
- 反例 16：动态观察没有时间窗。错法：运行一次就写“无联网/无自启动”。对法：写清观察时长、重启/二次启动/卸载是否覆盖，未覆盖就降级。根因：安装器和更新器常在延迟、重启或二次启动后才触发。
- 反例 17：配置提取不复核。错法：把 strings 中的 URL 或 token 字段当真实配置。对法：用资源路径、偏移、解包输出、运行日志或二次工具交叉验证并脱敏。根因：静态字符串可能是模板、旧值或诱饵。
- 反例 18：权限主体被省略。错法：只写“创建了任务/服务”。对法：记录创建主体、运行主体、权限级别、触发条件、命令行和清理建议。根因：权限边界决定影响面和兼容根因。
- 反例 19：未知链路硬归因。错法：解包失败仍断定是某打包器或某更新器。对法：写未知/推测、阻塞证据、已排除项和补证工具。根因：混合打包和损坏样本常让单一工具误判。
- 反例 20：交付包带可复用步骤。错法：附上注册自启动、替换更新源或绕过校验的完整命令。对法：只给检测、影响、停用、清理、回滚和兼容修复。根因：防御报告不能变成攻击操作手册。

## 相邻技能边界

- 逆向工程总控/reverse-engineering（slug: rev）：逆向总控、授权门禁、样本接收和跨技能路由；自动化程序与打包程序逆向负责自动化/打包程序载体分析。
- 逆向自动化与批量证据流水线/revauto（slug: revauto）：逆向自动化、批量样本流水线、工具编排、证据归档和复验平台；自动化程序与打包程序逆向不是自动化流水线。
- 脚本与字节码逆向/scriptrev（slug: scriptrev）：已提取脚本、字节码、宏代码的语言级去混淆、AST/bytecode 和配置语义深挖；自动化程序与打包程序逆向只提供提取链、入口、配置来源和释放证据。
- 壳、加固与保护识别逆向/packrev（slug: packrev）：通用壳、加壳、反调试、保护器和脱壳阻塞证据；自动化程序与打包程序逆向只覆盖自动化/脚本打包器和安装器壳。
- 通用二进制逆向/binary-reverse-engineering（slug: binrev）/ Windows 逆向/winrev（slug: winrev）/ macOS/Mach-O 逆向审计/macrev（slug: macrev）/ Linux ELF 运行生态逆向/linuxrev（slug: linuxrev）：平台二进制、加载器、系统 API 和 ABI 细节深挖；自动化程序与打包程序逆向只做与打包/释放/启动相关的证据。
- 恶意样本防御逆向/malrev（slug: malrev）：恶意样本行为画像、IOC、YARA/Sigma、ATT&CK、家族归因和事件响应交接；自动化程序与打包程序逆向只提供载体、释放链和持久化线索证据。
- 逆向报告、证据链与交付收口/rev-report（slug: rev-report）：最终报告审阅和交付包装；自动化程序与打包程序逆向输出可复核证据供其汇总。
