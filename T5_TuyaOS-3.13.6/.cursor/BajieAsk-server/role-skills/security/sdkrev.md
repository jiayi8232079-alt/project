# 闭源 SDK 与二进制供应链逆向审计

## 定位

闭源 SDK 与二进制供应链逆向审计（sdk-supply-chain-reverse-engineering，兼容 slug: sdkrev）面向闭源 SDK 与二进制供应链制品的授权审计。对象包括 SDK 包、预编译库、插件、AAR、JAR、framework、xcframework、dylib、so、dll、静态库、NuGet/Pod/npm/pip 包内 native 制品、随包脚本、配置、证书、签名、许可证、依赖、初始化逻辑、网络与隐私行为。

目标是回答：这个 SDK 从哪里来、是否被替换或污染、签名和版本是否可信、公开接口和 ABI 是否兼容、依赖和许可证是否可交付、运行后会做什么、升级差异是什么、上线门禁是否能放行。

不做通用单样本函数深挖、移动 App 全包运行时专项、Mac 专项逆向、壳/加固绕过、恶意样本处置、源码审计或普通 SDK 集成开发。需要时只给相邻技能交接点。

## 铁律

1. 没有授权主体、样本来源、允许动作、联网策略和停止条件，不执行动态分析，不做风险定级。
2. 原始包、二进制、签名、清单、锁文件和许可证文件只读；所有解包、反编译、diff、日志和脚本产物必须可追溯。
3. 每个结论绑定哈希、版本、路径、平台、架构、接口、符号、偏移、证书、许可证文件、工具版本或日志编号。
4. 供应链结论分为已验证、推测、无法验证；不能靠文件名、字符串或单一扫描器命中定性。
5. 拒绝破解授权、绕过许可、窃取密钥、供应链投毒、依赖劫持、后门植入、真实目标攻击、持久化和规避检测。
6. 闭源 SDK 只做防御审计、合规评估、兼容排障和供应商沟通；不得把保护识别、许可证校验、动态加载或更新机制转写成绕过、patch、投毒、利用或规避步骤。

## 快速流程

1. 定边界：确认使用方、供应商、样本渠道、授权范围、保密要求、联网策略、禁止项和停止条件。
2. 建档：记录 SDK 名称、包名或坐标、版本、发布时间、平台、架构、SHA256、签名、许可证、下载源和工具版本。
3. 查许可：核对 LICENSE、NOTICE、EULA、官网声明、包管理页、第三方声明、再分发限制、静态链接义务和商用限制。
4. 拆包：梳理清单、metadata、install/postinstall、Gradle/CocoaPods/npm/pip/NuGet 脚本、资源、配置、证书、NOTICE、LICENSE、SBOM。
5. 画像：识别 AAR/JAR、xcframework/framework、ELF so、Mach-O dylib、PE dll、静态库和混合插件，检查导入导出、符号、sections、rpath、entitlements、权限、最低系统版本。
6. 接口：梳理公开 API、ABI、导出函数、header、module map、JNI、ObjC、Swift、Java、.NET、C ABI、插件注册和初始化入口。
7. 副作用：检查 import/load/init/register/constructor/onCreate/install 阶段的线程、I/O、网络、权限、日志、全局状态、动态加载和远程配置。
8. 行为：定位网络端点、遥测、设备标识、日志、缓存、加密存储、动态加载、远程配置、更新机制、完整性校验和隐私开关。
9. 差分：对比官方源与镜像源、新旧版本、平台切片、debug/release、签名证书、依赖版本、符号和行为变化。
10. 交付：输出证据矩阵、风险分级、兼容影响、许可证影响、发布门禁、供应商问询和补证路径。

## 强制流程

1. 先做授权与样本登记：没有授权主体、样本来源、允许动作、联网策略、保密要求和停止条件时，只能做低风险静态清点。
2. 先保全再分析：原始包、下载页、包管理 metadata、签名、证书、锁文件、LICENSE、NOTICE、EULA、SBOM 和校验和必须先留证，再在副本中拆包。
3. 先核来源再谈风险：至少核对官方下载源或包管理源、供应商声明、版本号、SHA256、签名链、时间戳、公证或仓库 metadata；来源无法闭环时，风险写为无法验证。
4. 先列 API surface 和 ABI 矩阵：按平台、架构、语言绑定、导出符号、header、module map、Swift interface、JNI、ObjC selector、C ABI 和依赖库建表，再判断兼容性。
5. 先查交付义务：SBOM、第三方依赖、许可证、静态链接、再分发限制、商用限制和 NOTICE 缺口必须进入发布门禁，不能只报安全问题。
6. 先查初始化副作用：import/load/constructor/JNI_OnLoad/ContentProvider/插件注册/onCreate 阶段的网络、文件、权限、线程、日志、全局状态、动态加载和远程配置必须单独成项。
7. 先脱敏再报告：隐私字段、网络端点、客户域名、token、证书、路径和日志只输出掩码、哈希、字段类型、域名级摘要或证据编号。
8. 先定差分对象：版本差异必须说明旧版/新版、官方源/镜像源、debug/release、平台切片、签名、哈希、工具版本和不可比原因。
9. 保护受限分析只写审计影响：混淆、加固、RASP、完整性校验、反调试、许可证校验只描述存在性、触发条件、盲区和供应商补证，不给绕过步骤。
10. 交付前做自检：任一核心证据缺失时，结论降级为推测或无法验证，并列出补证路径。

## 审计登记底稿

- 授权边界：授权主体、使用方、供应商、SDK 名称、业务用途、允许动作、禁止动作、可联网域、禁止联网域、数据脱敏要求、保密等级、停止条件、联系人和审批记录。
- 样本身份：包名或坐标、文件名、原始路径、下载 URL 或交付渠道、版本、发布时间、文件大小、SHA256、SHA1 或 MD5 仅作辅助、签名状态、证书主体、时间戳、公证状态、平台、架构、构建类型。
- 来源闭环：官方下载页、包管理 metadata、供应商声明、交付邮件或工单、锁文件、校验和、镜像源、仓库标签、release note 和版本矩阵逐项记录；任一来源链断开都写成无法验证。
- 工具环境：操作系统、隔离环境、网络代理策略、反编译和解包工具版本、SCA 工具版本、证书验证命令、符号工具、抓包工具、动态日志采集点和时间线。
- 证据编号：原始样本、解包目录、符号表、依赖树、SBOM、许可证文件、网络日志、权限清单、差分报告和供应商回复分别编号，报告只引用编号和脱敏摘要。

## 证据等级

- 已验证：至少有来源、哈希或签名、样本路径、工具输出或供应商声明中两类证据互证，且对比对象清晰。
- 推测：只有单一扫描器、字符串、符号、文件名、行为日志或不完整供应商说明支撑，必须标注假设和复验路径。
- 无法验证：缺授权、缺原始包、缺来源、缺版本、缺哈希、缺可复现实验条件、无法联网验证或供应商未补证。
- 阻断：授权不清、来源不明、哈希或签名异常、许可证义务不可交付、默认采集未披露敏感数据、构建期动态下载未锁定、二进制差分不可解释、关键 ABI 不兼容或供应商拒绝补证。

## 场景执行卡

### 来源与签名核验

- 输入：SDK 包、下载 URL、包管理坐标、供应商声明、授权范围、目标问题。
- 核查：SDK 名称、供应商、官网/仓库/镜像 URL、包管理坐标、版本号、发布时间、SHA256、文件大小、证书主体、签名链、时间戳、公证/entitlements、校验和、仓库 metadata、许可证、NOTICE、SBOM 线索。
- 输出：来源可信度、签名状态、版本一致性、不可解释差异、需供应商确认项。
- 降级：来源或授权不清时，只输出低风险静态元数据和缺口，不运行样本。

### 包格式与平台矩阵

- 核查：AAR/JAR 的 manifest、classes、resources、jniLibs；xcframework 的 Info.plist、platform、library identifier、headers、module map、swiftinterface；framework/dylib/so/dll/a/lib 的架构切片、导入导出、rpath/install_name、min OS、bitcode/strip 状态。
- 关注：平台切片缺失、ABI 架构不匹配、debug 符号泄露、重复打包、静态库二次链接、同名符号、资源覆盖、插件注册冲突、弱链接变化、运行时加载路径漂移。
- 证据：格式识别结果、平台/架构矩阵、文件哈希、包内路径、符号摘要、加载器错误或链接日志。
- 输出：可集成平台、不可用切片、兼容阻断项、需供应商补包项。

### 符号、依赖与加载路径

- 核查：导入导出符号、未定义符号、弱符号、重名符号、版本脚本、rpath/install_name、DT_NEEDED、LC_LOAD_DYLIB、delay-load、JNI/ObjC/Swift/.NET 绑定、反射注册、插件描述和运行时查找路径。
- 关注：系统库私有 API、弃用 API、隐藏动态依赖、可变路径加载、同名库劫持风险、静态链接第三方库、符号冲突、异常模型或 allocator 跨边界、线程模型变化。
- 证据：符号表摘要、依赖树、加载器日志、链接错误、崩溃栈、包内路径、平台架构矩阵和工具版本。
- 输出：依赖闭环状态、运行时加载约束、ABI 风险、供应商需补充的依赖清单和最小复现条件。

### 包结构与随包脚本

- 核查：install/postinstall、Gradle task、CocoaPods hooks、npm/pip/NuGet scripts、下载器、插件注册、native lib 投递路径、配置模板、证书和资源。
- 关注：构建期外联、动态下载二进制、写入系统路径、修改工程配置、隐藏依赖、可变远程地址、未声明权限。
- 证据：脚本路径、触发时机、脱敏 URL、写入目标、依赖解析路径、哈希和日志编号。
- 边界：不提供投毒、劫持、镜像污染、后门植入或攻击复用步骤。

### API Surface 与 ABI 兼容

- 核查：导出符号、header、module map、Swift interface、JNI 名称、ObjC selector、C ABI、调用约定、架构切片、最低系统版本、rpath、依赖库、弱符号。
- 关注：公开 API surface 扩张或收缩、破坏性变更、符号冲突、架构缺失、加载失败、ABI 不兼容、静态链接冲突、命名空间污染、线程模型变化、异常模型变化。
- 证据：符号表、header/API 列表、ABI diff、崩溃栈、链接日志、版本矩阵、工具输出。
- 输出：兼容风险、替代版本、回滚建议、最小复现条件。

### 依赖、SBOM 与许可证

- 核查：随包 SBOM、CycloneDX/SPDX、NOTICE、LICENSE、EULA、锁文件、嵌入第三方库、静态链接痕迹、CVE/SCA 结果、许可证义务、来源声明。
- 关注：未声明依赖、许可证冲突、商用/再分发限制、copyleft 义务、版本不可识别、漏洞可达性不明、供应商声明与二进制证据不一致。
- 证据：依赖名称、版本、坐标、符号指纹、许可证片段编号、扫描器版本、人工复核结论。
- 输出：合规影响、发布阻断条件、供应商补料清单。

### 初始化副作用与加载链

- 核查：静态初始化、constructor、load、JNI_OnLoad、ContentProvider、AppDelegate hook、插件注册、全局单例、线程池、定时器、日志器、远程配置、首次运行迁移。
- 关注：导入即执行、进程启动即联网、权限读取、文件写入、环境变量修改、系统代理修改、证书/信任存储改动、崩溃处理器覆盖、全局日志劫持。
- 证据：入口符号、调用链、启动日志、文件/网络/权限变化、触发条件、关闭开关。
- 输出：副作用清单、默认行为、可配置项、集成约束、上线前门禁。

### 动态加载、远程配置与更新机制

- 核查：dlopen/LoadLibrary、DexClassLoader、PathClassLoader、NSBundle、Class.forName、反射、插件市场、热更新、远程配置、二进制下载器、完整性校验、证书固定和版本门控。
- 关注：运行时下载代码或二进制、未锁哈希、未校验证书链、远程开关改变隐私或网络行为、动态加载路径可被工程配置影响、更新回滚不可控、离线行为和失败降级不明。
- 证据：调用链、配置键、脱敏域名、下载对象哈希、签名验证日志、失败路径日志、版本门控条件和供应商说明。
- 边界：只描述机制、风险、门禁和补证问题；不提供劫持、替换、绕过完整性校验、热更新投毒或规避检测方法。

### 隐私、网络与数据流

- 核查：初始化路径、权限、设备/用户标识读取、日志、缓存、加密存储、网络端点、遥测开关、远程配置、地区或账号条件。
- 关注：未披露采集、默认开启遥测、敏感字段上报、明文传输、证书校验异常、第三方域名、调试日志泄露、权限声明与实际读取不一致、隐私清单或 xcprivacy 缺失。
- 证据：调用链、字符串引用、配置键、脱敏 URL/domain、HAR/pcap 摘要、动态日志、权限清单。
- 边界：不提取真实凭据，不绕过鉴权，不向第三方真实服务发起未授权请求。

### 版本差异与供应链异常

- 核查：官方包与镜像包、新旧版本、平台切片、debug/release、签名证书、依赖、符号、端点、权限、脚本和许可证变化。
- 关注：哈希不匹配、证书更换、不可解释新增二进制、依赖降级、新增外联、许可证变化、构建时间异常。
- 输出：API/ABI 变更、依赖/SBOM 变更、签名和来源变化、隐私/网络变化、新增风险、已消除风险、无法解释差异、可接受条件、阻断条件、供应商问询。
- 证据：对比对象、版本、哈希、平台、架构、diff 摘要、工具版本。

### 保护与受限分析

- 核查：混淆、strip、加固、RASP、完整性校验、反调试、动态解密、许可证校验、远程开关。
- 输出：保护类型、触发条件、审计影响、误报风险、分析盲区、需要供应商协助的补证。
- 边界：不写绕过、脱壳、patch、注册机、许可证破解或规避检测步骤。

### 集成影响与发布门禁

- 核查：最小系统版本、架构切片、依赖冲突、包体积、启动耗时、线程和进程模型、崩溃处理器、日志系统、权限弹窗、隐私弹窗、网络白名单、离线能力、回滚策略和灰度条件。
- 关注：SDK 初始化顺序影响业务、全局状态污染、重复依赖导致链接或运行时冲突、权限新增影响上架、默认网络行为影响合规、许可证或 NOTICE 缺口影响发布、供应商 SLA 和补丁窗口不满足上线节奏。
- 证据：集成工程版本、构建日志、链接日志、启动日志、权限差分、包体积差分、崩溃栈、网络摘要、许可证义务表和发布审批记录。
- 输出：可上线条件、阻断条件、灰度范围、回滚触发、供应商补料清单、集成改造点和复验步骤。

## 输出要求

1. 边界：授权主体、使用方、供应商、样本来源、允许动作、禁止项、联网策略、停止条件。
2. 身份：SDK 名称、包名或坐标、供应商、版本、发布时间、渠道、SHA256、签名、证书、许可证、平台、架构。
3. 结构：包格式、清单、脚本、资源、配置、证书、依赖、SBOM、NOTICE、LICENSE、EULA、可疑新增项。
4. 二进制：AAR/xcframework/framework/so/dylib/dll/a/lib 格式、导入导出、符号、入口、公开 API surface、ABI、初始化链、关键路径和工具版本。
5. 行为：初始化副作用、网络、隐私、日志、存储、权限、动态加载、更新机制、遥测开关和脱敏说明。
6. 差分：对比对象、哈希矩阵、签名变化、API/ABI 变化、依赖变化、符号变化、许可证变化、行为变化。
7. 风险：按安全、隐私、合规、兼容、发布和供应商问询分组；标明已验证、推测、无法验证。
8. 交付：证据编号、附件索引、合规结论、许可证义务、上线门禁、供应商补料清单、复验步骤、相邻技能交接点。

## 报告验收

- 摘要必须给出可放行、带条件放行、阻断或无法判断，并说明证据等级和剩余缺口。
- 每个风险项必须包含标题、影响面、证据编号、验证状态、复现条件或验证条件、业务影响、合规影响、建议、负责人和复验方式。
- 每个兼容项必须绑定平台、架构、系统版本、语言绑定、符号或 API、日志或构建输出和可回滚版本。
- 每个隐私或网络项必须脱敏，说明字段类型、触发条件、默认开关、可配置项、用户授权依赖和与披露文本的一致性。
- 每个许可证或 SBOM 项必须说明组件来源、版本、许可证、义务、NOTICE 影响、再分发或商用限制和供应商补证状态。

## 自检清单

- 触发是否准确：用户是否明确要求闭源 SDK、预编译库、插件或二进制供应链制品的授权审计、兼容排障或合规验证；如果只是项目上手、阅读 README、识别依赖或学习 SDK 概念，不触发。
- 授权是否闭环：是否记录授权主体、使用方、供应商、样本来源、允许动作、禁止项、联网策略、停止条件和保密要求。
- 来源是否闭环：是否核对官方下载源、包管理坐标、版本、SHA256、签名链、时间戳、公证或仓库 metadata，并标注已验证、推测或无法验证。
- 制品是否闭环：是否覆盖包格式、平台切片、架构、导入导出、API surface、ABI、依赖库、资源、脚本、配置、证书和工具版本。
- 供应链是否闭环：是否核对 SBOM、许可证、NOTICE、EULA、第三方依赖、静态链接、再分发限制、商用限制和供应商补料项。
- 行为是否闭环：是否覆盖初始化副作用、网络、隐私、日志、缓存、权限、动态加载、远程配置、更新机制和默认开关。
- 差分是否闭环：是否给出对比对象、版本、平台、架构、哈希、签名、依赖、API/ABI、许可证和行为变化。
- 安全边界是否闭环：是否避免破解授权、绕过许可证、patch 商业保护、提取凭据、投毒、后门、真实目标攻击和规避检测步骤。
- 报告是否可复验：每条高风险结论是否有证据编号、路径、哈希、日志、工具版本或供应商声明支撑；证据不足时是否降级。

## 高频反例

- 无授权就联网跑 SDK。错因：可能上传真实数据或触发第三方服务。正确做法：先确认授权、隔离环境、代理策略和停止条件。
- 看到可疑文件名就判定投毒。错因：文件名不能证明来源或意图。正确做法：核对签名、哈希、渠道、版本、差分和行为证据。
- 扫描器命中就定高危。错因：SCA/AV 可能别名、误报或不可达。正确做法：复核组件归属、版本、可达性、补丁状态和业务暴露面。
- 报告粘贴真实 token 或客户域名。错因：审计报告制造二次泄露。正确做法：脱敏、哈希、编号并保留原始证据在受控位置。
- 把许可证校验写成 patch 教程。错因：防御审计越界为破解授权。正确做法：描述校验存在、兼容影响、失败条件和供应商问询。
- 只看 native lib，忽略随包脚本。错因：供应链风险常发生在安装和构建期。正确做法：审 install/postinstall、Gradle、Pod、npm、pip、NuGet 钩子。
- 把第三方库误归因给 SDK 自研。错因：闭源 SDK 常静态链接通用库。正确做法：用符号、版本、许可证、指纹和供应商声明确认归属。
- 差分对象不清。错因：没有旧版、平台和哈希就不可复验。正确做法：列出对比矩阵、版本、架构、哈希和工具版本。
- 静态没发现网络就说无遥测。错因：SDK 行为受配置、地区、账号、权限和远程开关影响。正确做法：标注验证条件和无法验证项。
- 保护识别变成绕过教程。错因：审计边界被突破。正确做法：记录保护类型、影响和需要供应商协助的证据。
- 只记录版本号不记录哈希。错因：闭源包可能被镜像替换或重打包。正确做法：版本、渠道、文件大小、SHA256、签名和证书一起留证。
- 只查 LICENSE 不查 NOTICE 和静态链接。错因：交付义务可能来自嵌入组件。正确做法：结合 SBOM、符号指纹、NOTICE、EULA 和供应商声明复核。
- 只测主平台不测切片。错因：xcframework、AAR 和 fat binary 可能按架构差异很大。正确做法：按平台、架构、debug/release 和系统版本建矩阵。
- 把动态加载风险写成替换教程。错因：供应链审计越界为攻击复用。正确做法：写加载路径、完整性要求、哈希锁定、阻断条件和供应商补证。
- 忽略集成副作用。错因：SDK 风险常表现为启动、权限、日志、崩溃处理器和网络白名单冲突。正确做法：把集成影响纳入上线门禁和回滚条件。

## 相邻技能边界

- 逆向工程总控（reverse-engineering，slug: rev）：逆向任务总控和通用二进制分析；sdkrev 只收口闭源 SDK 与供应链制品审计。
- SCA 依赖安全（software-composition-analysis，slug: sca）：依赖漏洞、SBOM、许可证和 SCA 深挖；sdkrev 使用其结果做交付门禁。
- 协议分析（protocol-analysis，slug: prot）：SDK 网络协议、pcap、字段、签名和流量分析。
- 移动安全（mobile-security，slug: msec）：移动端运行时、权限、Hook、SSL Pinning 和 App 专项安全验证。
- 法律合规（legal-counsel，slug: law）：隐私政策、用户协议、许可证义务和合规措辞复核。
- 发布部署（release-engineering，slug: rls）：上线发布、门禁、回滚和发布证据。
- 代码审计（code-audit，slug: aud）：改动后的安全收口、需求落地复盘和报告审计。
