# 授权私有协议逆向

## 定位 / 适用范围

授权私有协议逆向（private-protocol-reverse-engineering，兼容 slug: protrev）只处理授权范围内的私有协议逆向、互操作建模、兼容排障和防御验证。

适用场景：

- 从 pcap、设备日志、客户端日志、服务端日志或二进制帧样本还原协议结构。
- 接收 hex dump、base64 payload、串口/总线日志、Wireshark export、应用 trace、崩溃前后帧和 parser 失败样本并统一建档。
- 分析握手、登录前协商、心跳、重连、状态迁移、错误码、断线恢复和版本协商。
- 梳理 sequence、ack、request_id、session_id、stream_id、窗口、去重和乱序处理。
- 建立字段字典、消息类型表、状态机图、schema 推断和 fixtures。
- 推断 protobuf、thrift、flatbuffers、TLV、varint、length-prefix 或 custom binary schema。
- 在本地授权仿真环境做最小重放、兼容验证、回归样本验证和 parser/codec 排障。

不适用场景：

- 泛抓包教学、公开 API 调试、普通接口设计、普通后端协议实现。
- 移动安全攻击、SSL Pinning/MITM 绕过、签名伪造、X-Sign/X-Gorgon/X-Bogus 等接口攻击逆向。
- 文件格式逆向以 fmtrev 为主；加密算法、签名、KDF、密钥路径以 cryptrev 为主。
- 未授权第三方服务分析、凭据获取、接口伪造、生产重放、批量请求或绕过访问控制。

## 铁律

1. 未确认授权主体、资产范围、允许动作、禁止动作、样本来源、数据留存和停止条件，不开始协议逆向。
2. 只读保留原始 pcap、日志、dump 和帧样本；所有裁剪、脱敏、标注、解码和 replay 输入必须使用工作副本。
3. 每个字段、状态、消息类型、版本差异和兼容结论必须绑定证据：样本编号、时间戳、偏移、帧号、哈希、版本或日志行。
4. replay 只允许在本地、隔离、授权的仿真环境中做最小验证；禁止对真实第三方或生产服务重放。
5. 敏感数据最小化；token、cookie、密钥、账号、设备标识、用户数据、业务订单和客户字段必须脱敏。
6. 拒绝接口伪造、重放滥用、凭据窃取、MITM 绕过、攻击第三方服务、批量请求和规避风控。
7. 不把推断字段、推断 schema、兼容猜测或本地仿真结果包装成官方协议；所有不确定项必须标注可信度和补证路径。
8. TLS、证书、签名、反重放、风控和访问控制只做合规边界记录与证据化分析；不得提供绕过、伪造、降级或滥用步骤。

## 快速总则

1. 先定边界：确认协议归属、系统角色、客户端/服务端版本、网络环境、采集方式和授权时间窗。
2. 先建证据账：为 pcap、日志、二进制帧、客户端版本、服务端版本、配置和 fixtures 建编号。
3. 先分层：传输层、会话层、帧层、消息层、字段层、状态层、业务语义分开，不把字段猜测写成事实。
4. 先找稳定锚点：magic、length、version、flags、message_type、request_id、seq、ack、crc/checksum、timestamp。
5. 先做字典：消息类型、字段名、字段类型、取值枚举、出现条件、方向、版本范围、证据编号同步维护。
6. 先用最小 fixtures 验证：每个结论至少能被一个正例和一个差异样本支撑；不足时标为推测。
7. 先保护边界：遇到签名、加密、证书、Pinning、访问控制时，只记录阻塞和转交 cryptrev/安全审查，不写绕过步骤。
8. 先隔离网络：任何 replay、mock server、simulator、codec round-trip 只绑定本机或封闭测试网，禁止指向公网、生产域名或第三方地址。

## 强制流程

1. 授权确认：记录 owner、目标系统、资产清单、客户端/服务端角色、允许采集点、允许样本、允许环境、禁止项、第三方边界、撤销条件、停止条件和数据处理要求。
2. 样本建档：记录 SHA256、大小、来源、采集时间、采集工具、采集人、协议版本、客户端/服务端版本、平台、环境和脱敏策略。
3. 时间线归并：按连接、会话、方向、帧号、日志时间、业务动作把 pcap/日志/二进制帧对齐。
4. 帧层切分：识别 magic、length、header、payload、checksum、compression、fragment、batch 和 endian。
5. 消息层归类：按 direction、message_type、opcode、method、event、error、request/response pair 建消息表。
6. 状态机还原：从握手、认证前协商、ready、heartbeat、reconnect、error、close 还原状态、事件、守卫条件、超时、重试和回退路径。
7. 序列与确认：定位 seq、ack、request_id、session_id、stream_id、retry、窗口、幂等键和乱序处理。
8. schema 推断：区分 protobuf/thrift/custom/TLV/varint/JSON-in-binary；记录字段编号、类型、可选性、默认值、取值反例和版本漂移。
9. fixtures 验证：构造脱敏最小样本、解码期望、round-trip 期望、错误样本和版本差异样本。
10. 重放风险评估：确认目标 allowlist、网络隔离、请求数量、幂等性、nonce/timestamp/session 处理、日志留存和停止开关；不满足则只做离线 fixtures。
11. 本地仿真：只在授权隔离环境验证 parser/codec/兼容路径；禁止对真实服务做攻击性重放或批量请求。
12. 兼容排障：把失败现象映射到版本协商、能力位、字段缺省、状态迁移、seq/ack、超时重试、schema 漂移或 checksum/压缩/加密边界。
13. 真实验收：逐条核对授权矩阵、抓包链路、时序对齐、状态机、字段可信度、重放风险、TLS/证书/签名边界、互操作矩阵和测试样本；缺任一项不得报完成。
14. 交付收口：输出证据索引、字段字典、状态机、兼容矩阵、未验证假设、风险边界、反例库和下一步补证。

## 场景执行卡

### 1. pcap / 日志 / 二进制帧归并

- 输入：pcap/pcapng、客户端日志、服务端日志、dump、hex frame、base64 payload、Wireshark export、业务动作记录和版本信息。
- 动作：先记录采集链路、采集点、过滤条件、时钟来源和丢包/截断情况；再按会话和时间线对齐，用方向、长度、opcode、request_id 和日志关键词建立帧索引。
- 证据：保留原始编号、脱敏副本、帧号、时间戳、偏移、哈希、日志行和业务动作编号。
- 产出：抓包链路图的文字说明、连接时间线、会话表、帧索引、样本覆盖说明和缺失证据清单。
- 易错：只看单侧日志会误判状态；pcap 时间和应用日志时间要记录时钟偏差。

### 2. 帧格式与字段字典

- 输入：多版本、多方向、多动作的帧样本。
- 动作：优先定位 magic、length、version、flags、message_type、seq、ack、checksum、payload 边界。
- 证据：每个字段给出样本编号、偏移、长度、编码、取值范围、出现条件和反例样本。
- 产出：字段字典、消息类型表、枚举表、未知字段列表、版本差异表。
- 易错：不要把业务值当协议字段；高熵 payload 先标记疑似压缩/加密，再转 cryptrev 或补样本。

### 3. 证据分级与字段可信度

- 输入：字段猜测、状态迁移、schema 草案、日志对照、版本差异和失败样本。
- 动作：按已证实、强推断、弱推断、未知四档标注，禁止把单样本、单方向、单版本观察写成定论。
- 证据：已证实必须有字段/日志/状态或多样本交叉；弱推断必须列出反例缺口和待采样动作。
- 产出：字段可信度表、未验证假设、补样本清单、不能用于实现的高风险假设。
- 易错：字段名可以为了讨论临时命名，但交付时必须标注“推断命名”，不能冒充官方术语。

### 4. 握手、心跳、重连和状态机

- 输入：连接建立、正常心跳、断网重连、版本不兼容、错误关闭等样本。
- 动作：梳理状态、触发事件、发送方向、前置条件、后置状态、超时、重试次数、错误码和恢复路径。
- 证据：每条状态迁移绑定帧号、日志行、时间差、版本和触发动作。
- 产出：状态机图的文字等价描述、状态迁移表、超时/重试参数、异常路径。
- 易错：认证、授权、加密协商和业务 ready 是不同状态，不要合并成“登录成功”。

### 4.1 TLS / 证书 / 加密边界

- 输入：证书链、TLS 版本、握手元数据、服务端日志、客户端错误日志、授权测试证书说明和高熵 payload 标记。
- 动作：只记录协商版本、证书主题/颁发链、SNI/ALPN、失败原因、证据缺口和合法替代观测路径。
- 证据：证书指纹、日志行、错误码、时间戳、测试环境说明和 owner 授权记录。
- 产出：TLS/证书边界说明、无法观测字段、需转 cryptrev/安全审查的事项、合规采集建议。
- 易错：不要写 Pinning 绕过、MITM 绕过、私钥提取、伪造证书、降级 TLS 或把真实信任链改成测试信任链的步骤。

### 5. 序列号、ACK 和请求响应配对

- 输入：并发请求、乱序响应、丢包重试、断线恢复和批量消息样本。
- 动作：定位 seq、ack、request_id、session_id、stream_id、窗口、去重键和 retry 标志。
- 证据：用至少两个并发或异常样本证明配对规则，无法证明时标为推测。
- 产出：配对规则、重传规则、幂等条件、乱序处理、兼容风险。
- 易错：时间相邻不等于请求响应配对；必须有字段、日志或状态证据支撑。

### 6. 版本协商与兼容排障

- 输入：新旧客户端、新旧服务端、功能开关、降级失败、错误码和灰度日志。
- 动作：比较 version、capability、feature flags、schema 字段出现条件、默认值和拒绝原因。
- 证据：版本矩阵、差异帧、错误日志、服务端响应、回归 fixtures。
- 产出：兼容矩阵、版本门槛、字段兼容策略、迁移建议和回归样本。
- 易错：不要只按版本号判断能力；能力位、配置和灰度策略可能覆盖版本号。

### 7. protobuf / thrift / custom schema 推断

- 输入：payload 样本、已知业务动作、日志字段、客户端符号、字符串常量和错误样本。
- 动作：识别 wire type、field id、varint、zigzag、length-delimited、required/optional/repeated 或自定义 TLV。
- 证据：字段猜测必须由多个样本、业务动作变化、日志或解析失败差异支撑。
- 产出：schema 草案、字段可信度、未知字段、fixtures、round-trip 风险和待补样本。
- 易错：不要伪造官方 .proto/.thrift；只能标明“推断 schema”和证据强度。

### 7.1 签名 / 校验 / 反重放分析边界

- 输入：签名字段位置、校验失败日志、nonce/timestamp/request_id、服务端拒绝原因和授权样本差异。
- 动作：只分析字段参与关系、失败条件、反重放语义、兼容阻塞和需要补证的观测点。
- 证据：失败帧、错误码、时间窗、字段变化对照、日志行和版本矩阵。
- 产出：签名边界说明、反重放风险、不可复现项、合法实现方需要提供的接口或测试凭证需求。
- 易错：不要输出签名算法复刻步骤、签名伪造、nonce 预测、风控绕过、批量重放或访问控制降级方案。

### 8. 本地授权仿真与 fixtures

- 输入：脱敏样本、字段字典、状态机、parser/codec、兼容问题和授权测试环境说明。
- 动作：构造最小正例、边界例、错误例、版本差异例，在本地隔离环境验证解码、编码、状态迁移或兼容行为。
- 证据：记录 fixture 名称、来源样本、预期结果、实际结果、工具版本和失败日志。
- 产出：fixtures 清单、回归验证表、兼容结论、无法验证项、仿真环境隔离说明。
- 易错：仿真不等于生产可用；禁止把本地 replay 方法用于真实服务或批量请求。
- 测试样本最小集：正常握手、正常业务请求、心跳、断线重连、错误码、并发/乱序、版本差异、字段缺省、checksum/length 错误、高熵 payload 边界和至少一个拒绝样本。

### 8.1 模拟器 / 客户端互操作

- 输入：官方或 owner 授权客户端、模拟器、mock server、codec、fixtures、版本矩阵和网络隔离说明。
- 动作：明确互操作目标是解析一致、状态迁移一致、错误处理一致或兼容诊断一致，不追求伪装真实客户端。
- 证据：客户端版本、模拟器版本、fixture 来源、请求数量、目标地址、日志、失败差异和回滚方式。
- 产出：互操作矩阵、通过/失败条件、差异解释、不可兼容项、需要 owner 提供的契约或测试端点。
- 易错：不要生成可对真实服务使用的伪客户端、自动化批量请求器、凭据复用流程或风控规避脚本。

### 9. parser / codec 兼容排障

- 输入：解析失败日志、旧版可用样本、新版失败样本、round-trip 差异、checksum/length 错误和状态机停滞点。
- 动作：先判定失败层级，再比较字段缺省、未知字段、能力位、endian、压缩、长度、checksum、seq/ack 和版本门槛。
- 证据：每个修复建议必须绑定失败 fixture、差异帧、日志行、版本矩阵和复验结果。
- 产出：最小复现样本、兼容风险说明、回归 fixture、修复建议和不可兼容项。
- 易错：不要为了兼容而放宽认证、签名、访问控制或重放保护；安全失败不能降级成协议兼容问题。

## 验证门禁

- 授权、样本来源、允许动作、禁止动作、停止条件和数据处理要求齐全。
- 授权矩阵必须列 owner、资产、采集点、环境、时间窗、允许动作、禁止动作、交付物边界和撤销条件；只写“已授权”不通过。
- 抓包链路必须列采集点、工具版本、过滤条件、时钟偏差、丢包/截断情况、脱敏步骤和原始样本哈希；链路不可复盘不通过。
- 原始 pcap/日志/dump/帧样本只读留存，工作副本有编号和脱敏说明。
- 字段字典覆盖 magic/length/version/message_type/seq/ack/checksum 等核心锚点，未知字段明确列出。
- 状态机至少覆盖握手、ready、heartbeat、reconnect/error/close 中与问题相关的路径。
- 状态迁移表必须包含 from/to、事件、方向、前置条件、超时、重试、失败分支和证据编号；只有口头流程不通过。
- 关键结论至少有两类证据；不足时必须标为推测或无法验证。
- 字段可信度必须分已证实、强推断、弱推断、未知；弱推断不得进入实现建议，未知不得命名成事实字段。
- fixtures 可复验，包含正例、差异样本和至少一个失败/边界样本。
- 本地仿真环境已说明网络隔离、目标地址、数据脱敏、日志留存和停止条件。
- replay 或模拟器验证已绑定本地/隔离 allowlist，明确请求数量、幂等性、反重放风险和停止开关。
- TLS、证书、签名、加密、反重放和访问控制边界已列明；无法合规观测的内容标为阻塞或转交。
- 模拟器/客户端互操作只验证授权范围内的 parser、codec、状态机或兼容问题，不伪装真实客户端访问生产服务。
- 输出不包含接口伪造、重放滥用、凭据窃取、MITM 绕过、攻击第三方服务、批量请求或绕过步骤。
- 报告必须包含反例库或拒绝项清单，说明哪些结论被样本反驳、哪些动作因授权或安全边界被停止。

## 输出要求

1. 授权范围：owner、资产、样本、允许动作、禁止动作、环境、时间窗、停止条件。
2. 样本索引：pcap/日志/dump/帧样本编号、SHA256、版本、来源、脱敏策略和证据目录。
3. 协议画像：传输方式、帧结构、消息类型、方向、状态机、序列/ACK、版本协商和错误处理。
4. 字段字典：字段名、偏移/编号、类型、编码、出现条件、取值、版本范围、证据和可信度。
5. schema 推断：protobuf/thrift/custom 识别依据、schema 草案、未知字段、fixtures 和 round-trip 风险。
6. 兼容结论：触发条件、影响范围、版本矩阵、回归结果、失败证据和修复建议。
7. 风险控制：replay allowlist、隔离方式、请求上限、幂等性、反重放处理、停止开关和日志留存。
8. 边界说明：敏感数据处理、TLS/证书/签名边界、未验证假设、不能做的动作、相邻技能联动和补证路径。
9. 报告验收：结论可追溯到证据编号，未知项有补证路径，fixtures 可复验，反例和拒绝项明确，交付物不含密钥或绕过步骤。
10. 测试样本：样本矩阵、fixture 名称、来源证据、期望结果、失败样本、版本样本、互操作样本和不可复验原因。

## 安全边界

- 只支持授权私有协议互操作、兼容排障、防御验证、供应链审计、事件复盘、CTF/教育和合法研究。
- replay 只能用于本地授权仿真和 fixtures 验证；不能用于真实服务、第三方系统、生产环境或批量请求。
- 只描述保护机制造成的观测阻塞、证据缺口和合法替代观测；不提供 MITM 绕过、Pinning 绕过、签名伪造或访问控制绕过。
- TLS/证书只允许使用 owner 授权的测试环境、服务端日志、合法导出的握手元数据或测试证书材料；不得提取私钥、安装 rogue root、诱导第三方流量或降级连接。
- 签名算法只做边界分析、字段依赖、失败原因和兼容阻塞记录；不复刻可用签名、不生成伪造请求、不提供可绕过风控的参数组合。
- 不提取、不展示、不验证凭据；不帮助获取 token、cookie、私钥、会话、设备指纹或用户隐私数据。
- 不生成可直接攻击真实服务的伪客户端、重放器、流量放大器、绕过器或批量请求器。
- 不把字段字典、schema、重放脚本或兼容结论用于攻击第三方服务、接口滥用、批量注册、刷量、爬取或风控规避。

## 高频 Bug 反例库

- 反例 1：无授权就分析真实服务。错法：拿 pcap 直接复现请求。对法：先确认 owner、范围和本地仿真边界。根因：协议逆向不能变成越权访问。
- 反例 2：把抓包等同于 protrev。错法：只要求抓包、签名逆向或 MITM 绕过也触发本技能。对法：泛抓包/签名攻击转 protocol-analysis 或拒绝。根因：protrev 聚焦授权私有协议建模。
- 反例 3：只有一个样本就定字段。错法：看到固定字节就命名字段。对法：用多动作、多版本或反例样本确认。根因：常量、padding 和业务值容易混淆。
- 反例 4：忽略 seq/ack 配对。错法：按时间相邻配请求响应。对法：用字段、日志和并发样本证明配对。根因：并发和乱序会打破时间假设。
- 反例 5：把加密 payload 硬拆字段。错法：对高熵数据强行编字典。对法：标记疑似加密/压缩并转 cryptrev 或补证。根因：字段层证据不足。
- 反例 6：伪造官方 schema。错法：把推断 .proto 当官方协议。对法：标注推断、证据和可信度。根因：逆向 schema 不是权威规范。
- 反例 7：replay 到生产验证。错法：为了验证 ACK 或接口行为打真实服务。对法：只在本地授权仿真环境使用 fixtures。根因：重放可能造成滥用和数据污染。
- 反例 8：报告没有 fixtures。错法：只给字段表不给复验样本。对法：输出脱敏最小正例、差异例和失败例。根因：无法回归就无法交付兼容结论。
- 反例 9：兼容修复绕过安全。错法：为了旧端成功而关闭签名、ACK 或重放检查。对法：把安全失败列为阻塞或转 cryptrev/安全审查。根因：兼容不能覆盖访问控制边界。
- 反例 10：本地仿真连到真实域名。错法：mock/replay 复用生产 base URL 验证。对法：绑定 loopback、隔离网段或离线 fixtures。根因：仿真边界不清会变成真实服务重放。
- 反例 11：授权范围只写“已授权”。错法：不列 owner、资产、采集点、允许动作和停止条件。对法：用授权矩阵约束样本、环境和交付物。根因：边界不明会让逆向结果不可验收。
- 反例 12：TLS 受阻就教绕过。错法：给 Pinning 绕过或伪证书步骤。对法：记录证据缺口，改用 owner 日志、测试证书或转安全审查。根因：合规观测不能变成拦截第三方流量。
- 反例 13：签名失败就复刻签名。错法：推导可用签名参数并重放请求。对法：只说明签名字段依赖、失败条件和需要合法接口支持。根因：签名分析边界不能越过访问控制。
- 反例 14：模拟器伪装真实客户端。错法：让模拟器连生产服务验证互操作。对法：只在本地 mock、离线 fixtures 或授权测试端点验证。根因：互操作诊断不是规避风控。
- 反例 15：报告结论不可追溯。错法：给“字段 A 应该是用户 ID”但无样本编号。对法：每条结论绑定帧号、偏移、日志行、版本和可信度。根因：没有证据链就无法复盘。
- 反例 16：只有成功样本。错法：全是 happy path，没有错误码、版本差异和失败帧。对法：补齐拒绝样本、边界样本和版本差异样本。根因：协议兼容结论必须能解释失败。
- 反例 17：抓包链路不可复盘。错法：只有导出的帧，没有采集点、过滤条件和时钟偏差。对法：补采集链路、工具版本、丢包说明和原始哈希。根因：证据链缺口会污染字段和状态推断。
- 反例 18：弱推断进实现。错法：把单样本字段用于 parser/codec 修复。对法：弱推断只进补证清单，不能进实现建议。根因：可信度分级是交付门禁，不是装饰。

## 相邻技能边界

- 协议分析（protocol-analysis，slug: prot）：泛抓包、代理配置、签名算法逆向、移动接口攻击、设备指纹对抗、验证码/风控对抗不归 protrev；无授权或攻击性请求直接拒绝。
- API 工程（api-engineering，slug: api）：普通 API 端点、请求响应格式、错误码、版本设计、OpenAPI/SDK 契约和后端实现归 api；只有授权私有协议逆向、证据化建模和兼容排障才用 protrev。
- 文件格式逆向（file-format-reverse-engineering，slug: fmtrev）：文件 magic/header/offset table/checksum/parser、离线私有文件格式和 round-trip 文件格式建模归 fmtrev。
- 密码学逆向（cryptography-reverse-engineering，slug: cryptrev）：加密算法识别、签名、KDF、密钥路径、随机数、IV/nonce 和加密兼容审计归 cryptrev；protrev 只记录加密造成的协议观测边界。
- 逆向工程总控（reverse-engineering，slug: rev）/ 二进制逆向（binary-reverse-engineering，slug: binrev）/ 动态调试逆向（debug-reverse-engineering，slug: debugrev）：二进制函数、调用链、动态调试、符号、反汇编和运行时补证归这些技能；protrev 只消费其输出形成协议证据。
- 逆向模糊测试（fuzz-reverse-engineering，slug: fuzzrev）/ 测试验证（test-engineering，slug: tst）：parser fuzz、协议兼容回归、fixtures 自动化和覆盖率验证可联动；protrev 负责协议模型和证据字典。
- 代码审计（code-audit，slug: aud）：最终交付前的安全边界、证据完整性、误触发和实现风险复核可转 code-audit。
