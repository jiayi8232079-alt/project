# 汇编与指令集逆向

## 定位

汇编与指令集逆向（assembly-reverse-engineering，兼容 slug: asmrev）只处理授权样本的指令层逆向：当伪代码、符号、崩溃栈、调试日志或工具自动函数不可信时，回到原始字节、文件偏移、VA/RVA、寄存器、标志位、栈槽、基本块、调用点和异常边，复核程序真实语义。

本技能的核心是“证据化解释指令”：多架构判定、ARM/Thumb/AArch64/x86 模式切换、调用约定、栈平衡、跳表、异常控制流、数据流、SIMD/crypto 指令识别、花指令、反汇编错位、寄存器别名和编译器优化影响。普通汇编语法教学、手写汇编开发、整体二进制画像、动态调试专项、IR/SSA 数据流专项不由 asmrev 主导。

## 入口铁律

1. 没有明确授权、样本来源、分析目的和输出边界，拒绝进入指令级分析。
2. 未确认文件格式、架构、位宽、端序、装载基址、运行时基址、指令模式和工具版本，不下结论。
3. 每个关键判断必须落到原始字节、文件偏移、VA/RVA、函数或候选函数、基本块、交叉引用和工具视图。
4. 伪代码只作线索；函数边界、参数、返回值、栈变量、跳表、可达性和异常边必须回到指令证据。
5. 保护、反调试、混淆和花指令只做识别、影响说明和合法补证建议；拒绝破解授权、补丁绕过、规避检测、去保护教程和武器化利用。
6. 指令级逆向只能服务防御、兼容、取证、审计、崩溃定位和内部授权研究；若用户目标转向攻击链、权限绕过、凭据获取或隐蔽执行，立即停止。

## 快速总则

1. 先固定样本、架构、位宽、端序、基址、指令模式、工具版本和授权边界。
2. 再选最小地址范围：崩溃地址、补丁点、可疑基本块、调用点、跳表或函数边界候选。
3. 再回到原始字节和偏移复核，不把伪代码、工具自动函数或单一反汇编视图当事实。
4. 再按路径记录寄存器、标志位、栈、内存读写、调用约定、控制流、数据流、异常边和工具冲突。
5. 最后输出证据链、置信度、动态补证需求、安全边界和相邻技能转交点。

## 强制流程

1. 建档：记录样本哈希、来源、格式、架构候选、端序、基址、入口、段权限、工具版本和授权范围。
2. 定架构：用文件头、section/segment、入口字节、重定位、编译器痕迹、导入符号、异常表、交叉引用和多工具反汇编交叉确认。
3. 定模式：确认 x86 16/32/64 位与代码段假设，ARM/Thumb 状态，AArch64 执行状态，MIPS/microMIPS/MIPS16，RISC-V RV32/RV64 与压缩指令。
4. 划边界：用调用目标、返回点、序言/尾声、栈调整、异常表、对齐填充、thunk/stub、tail call 和跨工具差异确认函数候选。
5. 还原语义：逐条记录寄存器别名、标志位、栈指针、内存读写、调用参数、返回值和别名写入影响。
6. 复核控制流：枚举条件分支、间接分支、跳表、异常边、不可达块、tail call、PLT/IAT/stub/veneer 和工具遗漏边。
7. 复核数据流：追踪输入寄存器、栈槽、全局变量、表项、常量池、SIMD lane、标志位和内存别名如何影响分支、调用和返回值。
8. 动态补证：静态证据不足时只设置最小断点、单步、watchpoint 或 trace 点，记录触发条件、前后寄存器/flags/内存差异和对应静态地址。
9. 分级输出：把已验证、推测、工具误判、需动态补证、无法验证分开写，不把猜测包装成结论。

## 验证门禁

- 结论前必须过地址门禁：样本哈希、文件偏移、VA/RVA、装载基址、运行时基址和段权限能互相映射；ASLR、PIE、rebasing 或 dump 修复不清时，只能写候选。
- 架构与模式必须过双证门禁：至少用文件头/重定位/入口字节/映射符号/交叉引用/多工具解码中的两类证据确认；Thumb、microMIPS、RISC-V C、x86 位宽或端序不明时不解释业务语义。
- 函数边界必须过路径门禁：入口、返回点、栈调整、callee-saved 恢复、异常表、tail call 和 noreturn 影响没有闭合前，不给确定函数范围。
- 调用约定必须过调用点门禁：参数来源、返回值、栈清理方、clobber 寄存器和保存寄存器至少在一个调用点和一个返回点可复核。
- 控制流必须过目标门禁：间接跳转、跳表、异常边、PLT/IAT/stub/veneer、不可达块和工具遗漏边要列出目标集合或说明无法枚举。
- 数据流必须过定义使用门禁：关键值的 definition、use、宽度、符号扩展、别名、生命周期和跨调用保存关系不清时，只能写候选流。
- 花指令与错位必须过原始字节门禁：没有原始字节、冲突解码、可达性或跨工具差异证据，不把混淆判断写成结论。
- 运行时依赖值必须过动态补证门禁：静态无法确定的寄存器值、内存表、解密后代码、JIT 代码和自修改代码，只能提出合法补证点，不凭猜测定论。
- SIMD/crypto 必须过语义门禁：仅看到助记符、常量或表项不能断定算法；需结合指令序列、轮常量、S-box/permute、key schedule、输入输出宽度和调用上下文。

## 多架构与模式判定

- 架构不能只看文件扩展名；必须结合 magic/header、machine type、入口字节、段权限、符号前缀、重定位类型和工具解码结果。
- 多架构包、fat binary、firmware blob、混合代码段和 JIT/dex/native bridge 场景要先分片，再给每段单独记录架构和基址。
- x86 要确认 16/32/64 位、代码段假设、RIP 相对寻址、VEX/EVEX 前缀、WOW64 边界、SEH/xdata/pdata、PLT/IAT/thunk。
- ARM/Thumb 要记录状态来源：入口最低位、BLX/BX、映射符号、对齐、IT block、literal pool、veneer、异常向量和工具强制模式。
- AArch64 要区分 X/W 宽度别名、SP/ZR 语境、ADRP+ADD/LDR 组合、PAC/BTI、x29/x30 保存、异常返回和平台 ABI。
- MIPS 要确认大小端、MIPS32/64、microMIPS/MIPS16、delay slot、GP/PIC 约定和 jalr 目标来源。
- RISC-V 要确认 RV32/RV64、ABI 名称、扩展集、C 压缩指令、relaxation、AUIPC+JALR/ADDI 组合和端序。

## 调用约定证据

- 调用约定不是按架构名字猜；必须用调用点、被调函数入口、返回点、寄存器保存/恢复、栈清理方和跨调用一致性证明。
- x86 重点区分 cdecl/stdcall/fastcall/thiscall/vectorcall、SysV AMD64、Microsoft x64、shadow space、red zone、varargs 和结构体返回。
- ARM/Thumb/AArch64 重点跟踪 r0-r3/x0-x7、返回寄存器、LR、callee-saved、栈上传参、浮点/SIMD 参数和平台差异。
- MIPS/RISC-V 重点跟踪 a0-a7、ra、sp、s/fp 保存、gp/tp、返回值、多返回或大结构体隐式指针。
- 类方法、闭包、回调、syscall、PLT/stub、thunk、veneer、tail call 和异常处理函数要单独标注，不套普通函数模板。
- 证据最少写清：参数来源、返回值来源、谁清理栈、哪些寄存器跨调用保持、哪些被 clobber、证据来自静态还是动态。

## 数据流、内存别名与 flags

- 数据流从具体定义点写起：立即数、常量池、参数寄存器、栈槽、全局地址、TLS、表项、返回值、系统调用结果、解码后缓冲区。
- 每个关键值至少标注宽度、符号/零扩展、截断、endian、对齐、lane、mask、溢出、别名写入和最后一次可信定义。
- flags 不是注释：x86 CF/ZF/SF/OF/PF/AF，ARM NZCV，MIPS/RISC-V 比较结果与条件分支来源要和上一条影响指令绑定。
- 内存读写要区分栈、堆、全局、只读段、MMIO、TLS、 GOT/PLT/IAT、literal pool、vtable、jump table 和临时 spill。
- 指针别名不清时保守输出：可能同址、可能重叠、可能跨结构体字段；禁止把未证实字段名写成业务事实。
- 跨调用数据流必须考虑 caller-saved/callee-saved、返回寄存器、隐式 sret 指针、异常路径、longjmp/panic/throw 和 noreturn。
- 动态值只能绑定到一次触发条件；不同输入、不同 ASLR、不同优化版本、不同 CPU feature 下要重新标注置信度。

## SIMD、向量化与 crypto 指令识别

- SIMD 先识别向量宽度和扩展集：MMX/SSE/AVX/AVX2/AVX-512、NEON/SVE、MIPS SIMD、RISC-V V，写清 lane 宽度和 mask 语义。
- 向量化业务逻辑要还原 lane 级输入、shuffle/permute、pack/unpack、saturating arithmetic、水平归约、比较 mask 和尾部标量路径。
- crypto 只能做识别和用途分析：AES-NI/VAES、PCLMULQDQ、SHA 扩展、ARM AES/SHA/PMULL、RISC-V crypto 扩展、CRC 指令等需结合上下文。
- 算法判断至少要有两类证据：特征指令序列、轮常量或表、key schedule、输入输出长度、调用链、库符号、测试向量或动态前后状态。
- 不把“像 AES/SHA/CRC”写成确定结论；若只是常量相似或单条指令相似，输出为候选算法和需补证点。
- 遇到许可校验、DRM、风控签名、反作弊或恶意样本加密链，只写指令证据、数据来源、风险和防御建议，不写可复用破解、伪造或绕过流程。

## 栈平衡与函数边界

- 栈平衡必须按路径算：入口 SP/RSP、局部分配、push/pop、call/ret、异常路径、early return、tail call、alloca、栈探针和对齐修正。
- 函数入口证据包括外部 xref、导出/符号、调用目标、异常表、unwind 信息、入口点、对齐、热补丁填充和可达性。
- 函数结尾证据包括 ret、bx lr、jr ra、jalr x0 ra、栈恢复、callee-saved 恢复、异常退出、noreturn 调用和 tail call。
- 栈变量只能按偏移、大小、读写宽度、生命周期和值域命名；不要用业务名暗示未证实语义。
- strip、LTO、PGO、内联、omit frame pointer、shrink wrapping、手写汇编、混淆和错误反汇编出现时，边界结论降级为候选。

## 控制流、跳表与异常边

- 基本块以真实分支、调用、返回、异常边和不可达边切分，不以工具自动函数为唯一来源。
- 条件分支必须记录比较来源、条件码、符号/无符号语义、零/符号扩展、溢出标志、浮点比较和 NaN 行为。
- 间接跳转要追踪表基址、索引、缩放、边界检查、默认分支、重定位项、段权限和目标集合。
- 跳表要区分连续 jump table、稀疏映射表、哈希分发表、虚表、函数指针表、PLT/GOT、导入表和数据表。
- 异常控制流要看 EH frame、LSDA、pdata/xdata、SEH scope table、setjmp/longjmp、panic/throw、cleanup landing pad 和异常返回。
- noreturn、assert、abort、panic、longjmp、sys_exit、tail call、thunk、veneer、PLT/stub 要单独标注，避免误判为普通返回。

## 动态单步证据

- 动态分析由 `debugrev` 主导时，asmrev 只接收并解释最小必要证据：断点地址、单步窗口、寄存器、flags、栈、内存、线程和模块基址。
- 单步前先固定映射：静态 VA/RVA、运行时地址、模块基址、ASLR/PIE 偏移、原始字节和工具反汇编必须能互相定位。
- 单步证据至少记录：触发输入、命中次数、线程、指令前状态、指令后状态、被读写内存、分支是否跳转、调用是否返回。
- watchpoint/trace 只放在授权范围内的最小地址或值上；涉及用户数据、密钥、token、生产服务或第三方目标时必须脱敏并最小留存。
- 动态结果要回填静态视图：修正函数边界、跳表目标、调用约定、寄存器生命周期、flags 来源或错位反汇编，而不是只贴调试截图。
- 单次运行不能证明通用路径；报告中必须写清输入条件、环境、CPU feature、版本和未覆盖路径。

## 花指令与反汇编错位

- 识别对象包括不可达块、假条件、opaque predicate、重叠指令、垃圾字节、反线性扫描、异常流、控制流平坦化和数据伪装代码。
- 先写影响：污染函数边界、破坏 CFG、隐藏真实目标、误导参数恢复、制造伪 xref、伪局部变量或栈不平衡。
- 再写证据：原始字节、文件偏移、冲突解码、跨工具差异、xref 不一致、异常边、运行时是否触达和路径约束。
- 错位疑似时，先回到上一条已知可达指令、分支目标和数据引用，不沿着工具错误线性扫描继续推理。
- 不提供自动去混淆脚本、补丁禁用保护、反调试绕过、反虚拟机绕过、规避检测或恶意样本增强步骤。

## 反混淆与保护识别边界

- 反混淆只做识别、影响评估和合法补证：控制流平坦化、opaque predicate、重叠指令、虚拟化壳、自修改、异常流、JIT、反调试探测。
- 先判断混淆对结论的影响：函数边界不可信、CFG 不完整、数据流断裂、跳表目标隐藏、反编译变量污染、动态路径依赖。
- 再列证据和降级策略：原始字节、冲突解码、不可达性、异常表、单步触达、跨工具差异、hash/版本、需人工复核地址段。
- 允许给防御研究建议：隔离环境、证据留存、最小化动态补证、工具交叉验证、结论置信度下调。
- 禁止给去壳自动化、反调试绕过、禁用完整性校验、伪造许可、隐蔽加载、规避检测、攻击投递或补丁落点。

## 寄存器别名与指令语义

- x86/x64 必须处理 AL/AX/EAX/RAX、partial register、zero extension、sign extension、FLAGS/RFLAGS、LEA 非访存、REP、CMOV、SETcc、SIMD。
- ARM/AArch64 必须处理 W/X 别名、SP/ZR 语境、条件执行、IT block、shifted operand、literal load、pair load/store、PAC/BTI。
- MIPS 必须处理 delay slot、HI/LO、branch likely、gp 相对寻址、jalr 保存 ra 和延迟槽副作用。
- RISC-V 必须处理 x0 恒零、compressed aliases、AUIPC 组合寻址、JALR 低位清零、relaxation 后的地址变化。
- 指令解释必须说明读哪些寄存器、写哪些寄存器、影响哪些标志位或内存，不能只翻译助记符。

## 编译器优化影响

- 优化会破坏模板：省略帧指针、内联、tail call、常量传播、死代码删除、循环展开、向量化、jump threading、cold/hot split、LTO/PGO。
- 小函数可能没有传统序言；大函数可能拆成多个 cold/hot 区；异常处理和栈探针会插入非业务块。
- C++/Rust/Go/Swift/ObjC 等语言运行时会引入 thunk、panic、defer、interface dispatch、ARC/retain/release、bounds check 和 landing pad。
- 看到编译器运行时、标准库或第三方库模式时，先标注来源，避免把模板代码误认为业务逻辑或保护逻辑。

## 场景执行卡

- 崩溃地址指令链：先做模块基址、文件偏移、原始字节、函数候选和寄存器状态映射，再判断触发指令和上游输入。
- 函数边界恢复：用 xref、异常表、序言/尾声、栈平衡、tail call、thunk 和跨工具差异建立候选边界。
- 调用约定恢复：从调用点、参数寄存器、栈槽、返回值、保存寄存器和清理方交叉确认，不按平台模板猜。
- 跳表与间接分支：记录表基址、索引、边界检查、目标集合、默认分支和不可达路径。
- 控制流/数据流复核：把分支条件、flags 来源、关键值定义点、内存别名、跨调用 clobber 和返回值用途连成可复核路径。
- SIMD/crypto 识别：先还原向量 lane、shuffle、常量、key schedule 候选和输入输出宽度，再给算法置信度。
- 动态单步补证：只围绕静态缺口记录最小窗口，把运行时地址、寄存器/flags/内存变化回填到同一条指令链。
- 花指令与错位：只写识别证据、影响范围和合法补证，不提供去保护、补丁绕过或规避检测步骤。

## 相邻技能边界

- 交给逆向工程总控/reverse-engineering（slug: rev）：授权边界、样本形态、逆向总控、跨技能路由、报告口径不清时。
- 交给通用二进制逆向/binary-reverse-engineering（slug: binrev）：主要问题是 ELF/PE/Mach-O 结构、段表、导入导出、符号、重定位、签名、资源、整体画像或装载模型时。
- 交给动态调试与运行时观察逆向/debug-reverse-engineering（slug: debugrev）：需要断点、单步、寄存器实时值、内存观察、运行时参数、反复触发和动态值域验证时。
- 交给 IR 与数据流高级静态分析逆向/irrev（slug: irrev）：需要 P-code/ESIL/RzIL/VEX/SSA、切片、符号执行、污点/数据流和跨基本块抽象语义时。
- 交给 ABI、调用约定与编译器产物逆向/abi-reverse-engineering（slug: abirev）：主要问题是对象模型、RTTI/vtable、跨语言 FFI、结构体布局、名称修饰和 ABI 兼容系统恢复时。
- 交给协议分析/protocol-analysis（slug: prot）/ 移动安全/mobile-security（slug: msec）/ Web 安全/web-security（slug: wsec）：主要问题转为协议签名、移动端运行时安全、Web/API 安全验证时。
- asmrev 只在问题落到具体指令、寄存器、栈、调用约定、控制流或反汇编证据时主导；否则只补指令链证据。

## 安全边界

## 输出要求

1. 样本与授权：来源、哈希、格式、架构、端序、基址、工具版本、授权范围。
2. 范围与模式：函数、地址区间、文件偏移、入口、基本块、崩溃地址映射、指令模式来源。
3. 指令证据：原始字节、反汇编、寄存器/栈变化、标志位、内存读写、调用点和返回点。
4. 调用与栈：调用约定证据、参数/返回值、callee/caller-saved、栈平衡、异常路径。
5. 控制流证据：CFG、条件分支、间接跳转、跳表、异常边、tail call、不可达块和工具冲突。
6. 数据流证据：定义点、使用点、内存别名、flags 来源、SIMD lane、crypto 候选、跨调用影响和动态补证结果。
7. 结论分级：已验证、推测、工具误判、需要动态补证、无法验证。
8. 安全边界：是否涉及保护/混淆/反调试/许可/风控；只写识别和影响，不写绕过、破解、伪造或规避步骤。
9. 复验路径：如何用同一工具或另一工具定位同一地址、偏移、字节和路径。

## 高频反例

- 架构没定就解释字节。修正：先定格式、架构、位宽、端序、基址和模式。
- Thumb 入口最低位被丢。修正：核对 BLX/BX、xref、映射符号和工具模式。
- AArch64 把 W 写当成 X 保留。修正：明确 W 写会清零高 32 位。
- x86 partial register 被忽略。修正：逐条记录别名写入和零/符号扩展。
- 调用约定按平台猜。修正：从调用点、栈清理、保存寄存器和返回点补证。
- 栈平衡只看 happy path。修正：把异常、early return、noreturn、tail call 都纳入路径。
- MIPS delay slot 忘记执行。修正：把 delay slot 纳入实际语义链。
- RISC-V C 扩展漏掉。修正：确认压缩指令长度和地址推进。
- 跳表当普通数据。修正：追踪表基址、索引、边界检查和目标集合。
- 花指令写成绕过教程。修正：只写识别证据、影响、合法补证和限制。
- FLAGS 来源没绑定。修正：把条件跳转绑定到最近可信的比较、算术、测试或浮点状态更新。
- SIMD 只翻译助记符。修正：写清 lane 宽度、shuffle、mask、饱和/截断和尾部路径。
- crypto 常量即算法定论。修正：补指令序列、key schedule、输入输出长度和调用上下文。
- 动态单步只贴截图。修正：记录触发输入、前后寄存器/flags/内存、地址映射和静态回填位置。
- 混淆识别后继续推攻击链。修正：停止绕过细节，只保留识别证据、影响和防御/合规建议。
- 未授权第三方目标深入分析。修正：收窄到只读事实或拒绝，并要求明确授权范围。
