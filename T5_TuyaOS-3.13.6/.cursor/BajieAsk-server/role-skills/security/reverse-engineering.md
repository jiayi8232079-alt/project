# Reverse Engineering实战排障版

> 定位：把逆向工程收敛成“授权清楚、样本可信、入口明确、静态/动态互证、结论可复核”的排障闭环。覆盖二进制、移动包、固件、协议片段、恶意样本、预编译依赖和跨语言运行时。
> 铁律：先授权和样本指纹，再静态分析与动态分析；先证据后结论；只写防御、审计、复现、互操作和加固验证口径，不输出可直接滥用的绕过、窃密、持久化、投毒或入侵步骤。

## 快速总则：授权 / 样本 / 入口 / 证据

1. 授权：记录授权主体、目标范围、样本来源、允许动作、禁止动作、时间窗口、数据留存和停止条件；授权不清只做低风险资料整理。
2. 样本：先记录 SHA256、大小、来源、签名、证书、版本、渠道、平台、架构、编译器/SDK 线索，原始样本只读，工作副本可追溯。
3. 入口：按形态识别 ELF、PE、Mach-O、APK、AAB、IPA、DEX、JAR、WASM、固件、dump、pcap、私有格式；再找 main、导出、JNI、Activity/Service、URL Scheme、IPC、插件点、更新器。
4. 工具：Ghidra/IDA/radare2 做二进制；JADX/javap 看 DEX/JVM；Frida/gdb/lldb 做授权运行时观察；strings/symbols/readelf/otool/dumpbin 做低侵入基线。
5. 证据：每个结论绑定哈希、文件偏移、函数/类/方法、基本块、symbols、strings、反汇编、反编译、控制流、调用图、日志、抓包、断点或内存摘要。
6. 互证：关键结论至少用静态、动态、环境差异、外部资料中的两类证据互证；证据不足只写“推测/无法验证”。
7. 脱敏：token、cookie、私钥、账号、设备标识、用户数据和恶意样本 C2 凭据只保留类型、哈希、掩码和证据编号。
8. 风险：同时评估安全、权限、数据、兼容、许可证、SBOM、发布、回滚和法务边界；逆向结论不等于修复完成。

## 场景执行卡

### 1. 样本接收与指纹建档

- 适用：二进制、APK/IPA、固件、可疑样本、崩溃包、闭源 SDK、协议片段。
- 动作：建只读原样本和工作副本；记录 SHA256、签名、架构、编译器、壳/加固线索、SBOM/许可证来源、隔离环境和清理策略。
- 证据：file/header、readelf/otool/dumpbin 摘要、证书、manifest/Info.plist、工具版本、授权记录。
- 兜底：样本来源、授权、版本或许可证边界不明时停止动态执行，只列缺口。

### 2. 静态结构、strings、symbols 与依赖归属

- 动作：先跑 strings、symbols、导入导出、资源、配置、依赖、段/节、rpath/load command、签名、证书；标记网络、加密、存储、日志、授权、更新、反调试入口。
- 证据：字符串、符号表、导入表、资源路径、类名、方法名、交叉引用、第三方库指纹和版本。
- 防遗漏：区分业务代码、SDK、开源库、编译器产物、壳层、packer stub、Swift/ObjC runtime、JVM/DEX 桥接和 Flutter/RN/WASM/Unity 资源。

### 3. 反汇编、反编译、控制流与调用图

- 动作：从入口和 sink 建调用图，再看控制流、状态字段、边界条件、错误分支、解析器、校验逻辑；反汇编与反编译互证，必要时回到字节偏移。
- 证据：函数地址、基本块、xref、CFG、调用图、伪代码位置、输入输出样本、工具版本。
- 兜底：反编译错乱、LTO/PGO/LLVM 优化、Swift ABI/泛型、ObjC runtime、JVM inline 或混淆导致不可靠时标区域并补动态证据。

### 4. 动态分析、调试与运行时观察

- 动作：先无修改运行，收集日志、文件、网络、进程、模块加载；再用 gdb/lldb/Frida 做最小断点、参数观察、返回值记录和崩溃栈复核。
- 证据：设备/系统/模拟器/真机、Root/Jailbreak 状态、命令、触发步骤、断点、寄存器/堆栈、日志时间线、内存摘要。
- 约束：不输出绕过授权、规避检测、解除证书绑定、禁用 RASP、破解商业软件或攻击第三方的可复用步骤。

### 5. 混淆、加壳、packer 与保护识别

- 动作：识别段/节异常、入口跳转、动态加载、资源加密、符号缺失、反调试、完整性校验、RASP、商业加固和工具误报；先判断证据可信度。
- 证据：壳特征、节表、loader 行为、动态加载日志、崩溃点、保护提示、工具差异。
- 边界：只描述保护类型、触发条件、分析影响和授权验证边界；不提供可直接规避检测或移除保护的流程。

### 6. 移动 APK / IPA / DEX / Native / Swift / ObjC

- 动作：Android 看 Manifest、DEX/JADX、native so、签名、资源、WebView/Deep Link、targetSdk、加固；iOS 看 Info.plist、entitlements、Mach-O、framework、Swift/ObjC symbols、Privacy Manifest。
- 证据：包名/Bundle ID、版本、签名、权限、入口组件、类/方法、so/framework、日志、设备系统版本。
- 联动：漏洞验证、隐私合规、移动端证书/TLS/权限和 MASVS 归 mobile-security；深度二进制归本技能。

### 7. 协议、格式、序列化与互操作还原

- 动作：分层识别明文、编码、压缩、序列化、加密、签名、长度、版本、校验；字段分为已证实、推测、未知。
- 证据：偏移、字段边界、pcap/HAR 编号、内存片段、解析前后对照、成功/失败样本。
- 联动：抓包、签名参数、协议文档、重放边界交 protocol-analysis；外部 RFC/格式规范交 research。

### 8. 恶意样本与可疑行为防御分析

- 动作：隔离环境中画像持久化、网络、文件、进程、凭据访问、横向行为、IOC、供应链来源；归因保持保守。
- 证据：哈希、域名/IP、路径、注册项/LaunchAgent/服务、进程树、时间线、脱敏日志、YARA/规则命中编号。
- 约束：不提供投放、隐蔽、持久化、绕过检测、凭证提取、真实目标利用或破坏性操作内容。

### 9. 版本、平台、工具链和 ABI 差异排障

- 动作：建立 OS、CPU、ABI、编译器、NDK/JDK/Xcode、Swift ABI、LLVM、系统 WebView、厂商 ROM、EDR/AV、模拟器/真机差异矩阵；不要把工具解析差异当程序行为。
- 证据：环境矩阵、工具版本、日志、崩溃栈、同入口对比、二进制 diff 摘要。
- 兜底：缺少目标环境时标“无法验证”，不得用本地环境替代结论。

### 10. 报告交付、复核与整改交接

- 动作：按证据强度分级，写影响范围、触发条件、复现路径、验证路径、数据处理、剩余不确定项、许可证/SBOM、发布/回滚影响。
- 证据：附件索引、哈希、截图编号、日志编号、函数/偏移、工具版本、时间线。
- 交接：代码修复、测试、发布、安全门禁分别联动对应技能，最终由 code-audit 收口。

## 高频坑 / 防遗漏

### 高频坑

1. 未确认授权、样本来源、允许动作就动态执行。
2. 不记录 SHA256、版本、渠道、平台、架构、工具链，导致无法复核。
3. 只看反编译，不看 strings、symbols、资源、导入表、配置和运行证据。
4. 把混淆、packer、加固、LTO/LLVM 优化造成的伪代码错乱当真实逻辑。
5. 把第三方 SDK、开源库、壳层、编译器 runtime 误判为自研恶意逻辑。
6. 静态和动态不互证，只凭单工具截图下结论。
7. 把 Base64、gzip、Protobuf、序列化误判为加密。
8. 动态分析只写“观察到返回值”，不写入口、输入、断点、环境和时间线。
9. 日志、dump、抓包保留明文凭据、设备标识或个人数据。
10. 恶意样本归因过度，把相似 IOC 当确定家族。
11. 把保护识别写成绕过授权、规避检测或破解商业软件步骤。
12. 忽略 SBOM、许可证、预编译依赖来源、制品签名和供应链边界。
13. 忽略 Swift ABI、ObjC runtime、JVM/DEX、JNI、WASM 或混合栈桥接。
14. 忽略旧版本、旧客户端、发布/回滚、签名和协议兼容影响。

### 防遗漏清单

- 授权：主体、范围、目标、允许动作、禁止动作、时间窗口、停止条件是否齐全？
- 样本：哈希、来源、版本、签名、平台、架构、渠道、许可证/SBOM 是否记录？
- 静态：strings、symbols、导入导出、资源、配置、依赖、证书、壳/packer 是否检查？
- 动态：触发步骤、输入、日志、断点、堆栈、网络、文件变化、设备状态是否留证？
- 证据链：每个结论是否能回到函数、偏移、类名、报文、日志或截图？
- 数据：敏感字段是否脱敏，临时 dump/capture 是否受控并可清理？
- 差异：版本、平台、工具链、ABI、运行环境是否单独列矩阵？
- 风险：安全、权限、数据、兼容、许可证、发布、回滚影响是否按证据分级？

## 输出要求

1. 场景卡：说明属于样本建档、静态分析、动态分析、反汇编/反编译、保护识别、协议还原、移动包、恶意样本、差异排障或报告交付。
2. 授权与边界：列授权范围、禁止项、样本来源、允许动作、停止条件和未确认项。
3. 环境与工具：列平台、架构、系统版本、工具链、Ghidra/IDA/radare2/JADX/Frida/gdb/lldb/strings/symbols 等实际版本。
4. 入口与路径：列文件、函数、类、偏移、Activity/Service、IPC、协议字段、触发步骤和验证路径。
5. 证据链：每个发现绑定样本哈希、工具输出、日志、抓包、截图、控制流、调用图或内存证据。
6. 结论分级：已验证、推测、无法验证分开写；语气不得超过证据。
7. 风险判断：说明安全、权限、数据、兼容、许可证、发布或回滚风险，以及影响范围和触发条件。
8. 脱敏与留存：说明日志脱敏、敏感数据处理、临时文件清理、证据保留位置和可复核附件索引。
9. 联动技能：需要 research、protocol-analysis、mobile-security、web-security、devsecops、test-engineering、code-audit 时说明原因。
10. 下一步：只列最小补证、复验或加固验证动作，不输出越权利用、绕过检测或攻击步骤。

## 高频 Bug 反例库

- 反例 1：无授权就执行样本。错法：拿到可疑 PE 直接运行观察网络行为。对法：先确认授权、隔离环境和允许动作，未确认只做静态建档。根因：逆向工程第一风险是越权和证据污染。
- 反例 2：样本身份缺失。错法：报告写“该 APK 有问题”，没有 SHA256、版本、渠道和签名。对法：所有结论绑定样本哈希、包名、版本、签名和来源。根因：没有样本指纹就无法复核或比较差异。
- 反例 3：只看反编译。错法：JADX/Ghidra 伪代码看似通顺就判定算法逻辑。对法：结合 strings、symbols、反汇编、调用图和运行日志互证。根因：反编译受混淆、优化和动态加载影响。
- 反例 4：第三方库误归因。错法：把开源 SDK 的网络上报函数写成目标应用自研后门。对法：用包名、符号、依赖、特征字符串、许可证和版本确认归属。根因：二进制包含大量第三方和编译器代码。
- 反例 5：编码误判加密。错法：看到 Base64、gzip 或 Protobuf 就写“加密通信”。对法：先分层识别编码、压缩、序列化、加密和签名。根因：格式层次混淆会导致风险判断错误。
- 反例 6：动态分析无触发条件。错法：只写“Frida 观察到函数返回 true”。对法：记录设备、系统、版本、入口、输入、断点、参数和时间线。根因：运行时证据没有上下文就不可复现。
- 反例 7：符号表缺失就停止。错法：symbols 被 strip 后宣布无法分析。对法：改用 strings、导入表、交叉引用、控制流、日志和行为证据缩小范围。根因：逆向常面对无符号和优化二进制。
- 反例 8：保护识别写成绕过。错法：把反调试、RASP、加壳处理写成可直接规避检测步骤。对法：只写保护类型、触发条件、分析影响和授权验证边界。根因：技能目标是防御/审计，不是破坏保护。
- 反例 9：日志泄敏。错法：报告贴完整 Authorization、cookie、设备 ID、用户路径。对法：日志脱敏，只保留必要片段、哈希、字段名和证据编号。根因：逆向过程常接触敏感数据，留存本身有风险。
- 反例 10：工具版本差异未说明。错法：IDA 和 Ghidra 结果不一致，却只选一个截图当结论。对法：记录工具版本、解析差异和人工复核结果。根因：工具链差异会影响反编译、类型恢复和控制流识别。
- 反例 11：移动包只看 Java/Kotlin。错法：APK 只看 DEX，不看 native so、manifest、资源、签名和 WebView 入口。对法：DEX、native、资源、权限、入口组件和动态加载一起建图。根因：移动逻辑常跨 JVM/DEX、Native、JS 和配置。
- 反例 12：恶意样本归因过度。错法：看到相同域名就确定为某家族。对法：把 IOC、行为、代码相似度、时间线和置信度分开写。根因：归因需要多证据，单点相似只能作为线索。
- 反例 13：Swift/ObjC runtime 误读。错法：把 selector、桥接 thunk、泛型特化函数当业务入口。对法：结合符号、类元数据、调用图、崩溃栈和运行日志识别真实入口。根因：Apple ABI 和 runtime 会生成大量非业务结构。
- 反例 14：SBOM/许可证边界漏查。错法：闭源 SDK 出现可疑代码就直接要求修改自研逻辑。对法：先查组件来源、许可证、供应链、版本和是否可替换。根因：预编译依赖风险归属和整改路径不同。

## 2024-2026 新坑速查

- AI 辅助混淆：AI 生成无意义控制流、字符串扰动和假特征会诱导误归因；必须回到调用图、运行证据和样本 diff。
- RASP 与商业加固升级：移动端和桌面端更常见运行时完整性检查；只识别影响和授权验证边界，不写绕过流程。
- LLVM/LTO/PGO 优化：控制流折叠、内联、尾调用、异常表和符号剥离会让反编译伪代码偏离真实路径。
- Swift ABI 与 ObjC runtime：Swift 泛型特化、async/await、桥接 thunk、selector 和元数据会干扰入口识别。
- JVM/DEX 混淆：R8/ProGuard、multidex、动态 dex、JNI 桥接、Kotlin 协程状态机会让类名和调用顺序失真。
- ARM64e、Pointer Authentication、Hardened Runtime、SELinux、Android scoped storage 会改变调试和日志可见性。
- Flutter、React Native、WASM、Unity、Electron/Tauri 混合栈增多；需同时看 native、字节码、资源、JS/WASM 和桥接层。
- 供应链二进制审计升温：预编译依赖、闭源 SDK、postinstall 产物、CI 制品需记录 SBOM、许可证、来源、哈希、签名和构建链。
- LLM 生成恶意样本和脚本变体增多；家族归因不能只依赖字符串相似度或注释风格。
- 隐私与日志监管更严：dump、capture、崩溃日志、设备标识都要最小化留存和日志脱敏。
- Apple notarization、Android targetSdk、系统 WebView、厂商 ROM、EDR/AV 规则会影响动态分析结果，环境矩阵必须写清。
- 工具链快速演进：Ghidra/IDA/radare2/JADX/Frida/gdb/lldb 版本差异可能改变反编译、符号恢复和 hook 稳定性。

## 与相邻技能的边界

- reverse-engineering：负责授权样本、二进制、反汇编、反编译、运行时观察、控制流、调用图、证据链、保护识别和逆向排障结论。
- research：负责外部资料、工具文档、格式规范、CVE/公告、许可证和第三方行为确认；逆向证据不足时先查权威来源。
- protocol-analysis：负责授权抓包、pcap/HAR、签名参数、协议字段、长连接、重放边界和协议文档；本技能提供二进制和运行时入口证据。
- mobile-security：负责 Android/iOS 安全评估、隐私合规、证书/TLS/权限、运行时防护和漏洞验证；本技能负责 APK/IPA/Native/DEX/Swift/ObjC 深度逆向证据。
- web-security：负责 Web/API/浏览器漏洞、认证授权、XSS/CSRF/SSRF/注入和修复验证；本技能只处理 Web 相关二进制、混合容器和客户端逆向证据。
- devsecops：负责 SAST/DAST/SCA、SBOM、许可证、Secrets、CI/CD、制品签名、provenance 和供应链门禁；本技能提供样本、哈希、闭源 SDK 和二进制风险线索。
- test-engineering：负责复现矩阵、回归、自动化验证、设备/版本/弱网/CI 证据和无法验证项；逆向结论需要回归时必须联动。
- code-audit：负责最终需求对账、影响面追踪、安全质量收口和剩余风险判断；涉及代码改动或远端技能更新后按其口径收口。
