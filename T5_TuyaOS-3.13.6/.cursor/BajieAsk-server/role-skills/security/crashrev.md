# 崩溃分析与漏洞可达性逆向

## 定位 / 适用范围

崩溃分析与漏洞可达性逆向（crash-reverse-engineering，兼容 slug: crashrev）负责把授权崩溃样本从“程序崩了”推进到“现场可复核、根因有证据、可达性有边界、影响判断保守、修复能复验”。

适用场景：

- crash dump、core、minidump、Apple crash/ips、Windows Error Reporting、sanitizer 报告分析。
- Linux core dump、Windows minidump/full dump、macOS/iOS ips/crash、Android tombstone、容器 coredump、云端 crash 收集平台导出的防御性样本。
- ASAN、UBSAN、TSAN、LSAN、Valgrind、Dr. Memory 等崩溃或内存错误报告复核。
- 栈复原、符号化、模块基址/偏移归一、寄存器、stack/heap 现场和崩溃点内存窗口复核。
- 输入最小化、crash bucketing、重复崩溃归并、稳定性和可达性判断。
- parser、协议、文件格式、闭源库、客户端组件、服务端本地复现环境的防御性 crash triage。
- 修复前后复现、防御复验、回归样本交付和安全影响说明。

不适用场景：

- 武器化 exploit、shellcode、ROP/JOP、堆风水、缓解绕过、真实目标利用步骤。
- 未授权第三方目标、线上目标打崩、批量扫描、DoS 放大或漏洞武器化验证。
- 只读学习逆向/调试概念、普通应用异常修复、fuzz harness 设计和长期 fuzz 策略。
- 从 dump 中提取 token、私钥、凭据、用户数据、商业源码或其他非必要敏感信息。

## 铁律

1. 没有授权、样本来源、目标版本、允许动作和停止条件，不运行未知样本。
2. 原始样本、dump/core、日志和复现输入先哈希留痕，分析副本和原件分开。
3. 崩溃结论必须绑定版本、输入、触发动作、模块、偏移、栈、寄存器/内存摘要和工具版本。
4. 崩溃可达性不等于可利用性；利用可能性只能保守描述证据和不确定项。
5. 不输出 exploit 构造、绕过 ASLR/DEP/CFI/Sandbox 的步骤、ROP/shellcode 或真实目标攻击路径。
6. dump/core/minidump 可能包含密钥、token、路径、用户数据和内存片段，默认脱敏和受控留存。
7. 先做只读现场复核和最小复现，再做任何会改变样本、环境或状态的操作。
8. intake 阶段先分清输入类型：dump/core/minidump、sanitizer 日志、复现输入、符号包、模块清单和运行日志缺一项都要标记证据缺口。
9. 缺符号、优化构建、栈破坏或跨平台地址差异时，只能降级为模块偏移/稳定帧/输入字段级结论，不能伪装成源码级根因。
10. 安全边界优先于完整性：用户要求 exploit、绕过、真实目标打崩或敏感数据提取时，停止该部分并改给防御性 triage 与修复验证。

## 快速总则

1. 建档：授权边界、程序版本、样本 SHA256、输入来源、命令/动作、系统、架构、符号状态、工具版本。
2. Intake：把原始输入、dump/core/minidump、sanitizer 报告、符号文件、模块列表、日志和环境快照分组，逐项标记已拿到/缺失/不可外发。
3. 复现：确认稳定性、触发步骤、线程条件、环境矩阵、ASLR 基址、依赖版本和是否需要隔离网络。
4. 归一：将崩溃地址映射到模块基址、文件偏移、函数/基本块、源码行或反编译位置。
5. 复核：同时看异常码/信号、当前线程、调用栈、寄存器、stack/heap 内存窗口、对象生命周期和最近输入处理点。
6. 分类：空指针、OOB 读写、UAF、double free、integer overflow、栈溢出、assert、timeout、race、OOM。
7. 分桶：按根因证据聚合，不只按栈顶字符串聚合；同栈不同输入字段要保留差异。
8. 判断：分清可达性、影响和可利用性不确定项；风险表述优先讲影响、缓解和修复，不讲利用路线。
9. 交付：给最小样本、复核路径、影响范围、防御建议、修复前后证据和回归门禁。

## 强制流程

1. 授权与目标确认
   - 确认样本归属、分析授权、目标版本、平台架构、允许运行环境、是否可联网和停止条件。
   - 记录是否涉及生产数据、用户隐私、第三方组件或受监管数据。
   - 明确禁止项：不对未授权目标复现，不在线上打崩，不做 exploit 生成，不提取与根因无关的敏感数据。
   - 若授权范围只允许离线分析，则只读解析 dump/core/minidump 和日志，不运行样本或连接外网。

2. 现场保全
   - 收集原始输入、dump/core/minidump、sanitizer 日志、程序日志、符号文件、模块列表和运行命令。
   - 记录哈希、时间线、工具版本、环境变量、依赖版本、容器/VM 镜像和崩溃次数。
   - 对 core/minidump 标记采集方式、完整度、线程数量、模块清单、内存区段、是否裁剪、是否来自生产环境。
   - 对 sanitizer 报告保留原始日志、二进制哈希、编译器/运行时版本、符号化链路和复现输入哈希。
   - 标记缺失材料：无模块列表、无符号、无原始输入、无最小输入、无编译选项、无复现命令时，不输出满置信度结论。

3. 复现与最小化
   - 先复现原始崩溃，再最小化输入和步骤。
   - 每次裁剪只改一个维度：字段、长度、结构、顺序、编码、压缩层或外部依赖。
   - 最小化结果必须仍触发同一 bucket 或说明 bucket 变化。
   - 复现记录包含命令/点击路径/API 调用摘要、环境差异、随机种子、超时、线程数和崩溃频率。
   - 无法复现时只能输出“现场线索 + 缺口 + 下一步取证”，不能输出确定 root cause 或影响评级。

4. 栈复原与地址归一
   - 符号化栈帧，确认栈是否被破坏、是否缺符号、是否被尾调用/内联/优化影响。
   - 将 PC/IP、LR/RA、SP、BP/FP、崩溃地址映射到模块、偏移、函数、源码/反编译位置。
   - 缺符号时保留模块偏移、build id/PDB UUID/dSYM UUID、二进制哈希和可信稳定帧，不能只写绝对地址。
   - 符号来源必须记录版本和可信度：本地符号包、构建产物、符号服务器、dSYM/PDB、split debug、debuginfod 或第三方库符号。
   - 多平台样本要分别保留地址归一结果，不能把不同 ABI、优化级别或补丁版本的栈强行合并。

5. Stack / Heap / 寄存器与内存复核
   - 记录关键寄存器、访问地址、读写方向、内存权限、对象边界、堆块/栈帧状态。
   - 栈侧复核参数、返回地址、帧指针、栈溢出痕迹、栈金丝雀/保护页、异常展开和信号处理路径。
   - 堆侧复核 allocator、chunk/header 状态、分配/释放栈、对象大小、邻接对象、UAF/double free/OOB 边界和 quarantine 证据。
   - 对 ASAN/UBSAN 报告，复核 shadow 信息、对象分配/释放栈、溢出方向、类型转换和误报可能。
   - 对 race、timeout、OOM，记录线程、锁、调度、资源上限和重试稳定性。
   - 区分 crash point、corruption point、trigger point 和 root cause；证据不足时用假设列表，不把受害指令写成根因。

6. Bucketing 与根因归并
   - bucket key 优先组合：缺陷类型、模块偏移、输入字段、调用链尾部稳定帧、sanitizer 类型。
   - 只按崩溃地址、栈顶函数或错误字符串归并时，必须标记低置信度。
   - 同一个 root cause 的多个样本要保留代表样本、最小样本和边界样本。
   - triage 先给优先级：可复现性、外部可控入口、默认暴露面、权限边界、影响资产、是否已有修复和回归成本。
   - root cause 必须指出错误条件、缺失校验/生命周期缺陷/算术边界/状态机错误、触发字段和证据链。

7. 可达性与影响判断
   - 可达性证据至少包含触发入口、前置条件、最小输入、触发频率和环境限制。
   - 影响范围区分：本地崩溃、远程输入可触发、认证后触发、文件打开触发、服务端解析触发、批处理链路触发、数据泄露线索。
   - 单独列出缓解措施状态：ASLR/DEP/NX/CFI/栈保护、沙箱、权限边界、崩溃重启策略和输入限流；只说明它们如何降低影响，不说明绕过方法。
   - 可利用性只做防御性高层判断，不给利用构造、内存布局调优或绕过缓解步骤；证据不足时写“未证明可利用”。
   - 若需要补证，只设计非武器化实验：复现稳定性、边界条件、错误返回、符号化、日志和 sanitizer 复跑。

8. 防御复验
   - 修复前确认原样本能触发；修复后确认原样本不崩。
   - 增加边界样本、相邻字段样本、回归样本和 sanitizer/符号化复跑。
   - 输出剩余风险：未覆盖平台、缺符号、不可复现、非确定性、样本脱敏导致证据缺口。
   - 修复验证必须同时看正确拒绝/降级、错误码/日志、资源释放、性能退化和相邻 parser/协议字段。
   - 报告验收前核对：证据可复核、结论不过度、敏感信息已脱敏、反例已排除、回归门禁可执行。

## 场景执行卡

### 1. Dump / Core / Minidump

- 先查：文件类型、哈希、系统版本、程序版本、模块列表、符号状态、崩溃线程。
- 必做：异常码/信号、PC/IP、崩溃地址、模块基址、文件偏移、调用栈、线程摘要、寄存器快照、内存映射和敏感片段脱敏状态。
- 易漏：ASLR 后只记绝对地址；栈损坏后仍按栈顶下结论；缺符号不保留二进制哈希；minidump 被裁剪却当完整内存分析。
- 产出：现场摘要、归一化地址、可信栈段、未知栈段和复核命令/工具版本。

### 2. ASAN / UBSAN / Sanitizer 报告

- 先查：sanitizer 类型、报错位置、分配/释放栈、输入、编译选项、符号化是否完整。
- 必做：复核对象生命周期、边界、类型、整数转换、shadow 信息、运行时选项、抑制规则和是否同一输入稳定触发。
- 易漏：把 sanitizer 输出原文当最终根因；不验证触发字段；忽略优化和符号化缺失。
- 产出：缺陷类型、触发字段、对象证据、最小样本、修复前后报告差异。

### 3. 栈复原与寄存器/内存现场

- 先查：栈帧完整性、调用约定、返回地址、栈指针、帧指针、寄存器保存规则。
- 必做：区分崩溃点、破坏点和输入处理点；检查访问地址权限、附近内存、对象边界。
- 易漏：把最后崩溃的读写指令当根因；忽略 earlier corruption；没有说明寄存器含义。
- 产出：崩溃指令解释、关键寄存器表述、内存窗口摘要、疑似破坏来源。

### 3.1 符号缺失 / 优化构建 / 栈损坏

- 先查：符号包、build id、PDB/dSYM UUID、模块基址、编译优化、帧指针、省略符号和第三方库版本。
- 必做：用模块偏移、稳定调用帧、导入/导出、反汇编邻域和输入字段交叉定位；结论标注置信度。
- 易漏：缺符号时硬写源码函数；把内联/尾调用导致的栈形态误判成调用链事实。
- 产出：降级后的可复核位置、需要补齐的符号材料、不能确认的帧和后续复核路径。

### 4. 输入最小化

- 先查：输入格式、魔数、长度字段、压缩/编码层、校验字段、外部资源依赖。
- 必做：逐步裁剪并记录每步是否同 bucket；保留原始样本、代表样本、最小样本。
- 易漏：裁剪破坏格式后换了崩溃；把最小样本写成可复用攻击 PoC。
- 产出：最小触发输入、字段解释、裁剪日志、bucket 一致性判断。

### 5. Crash Bucketing

- 先查：样本集合、重复率、栈稳定帧、模块偏移、缺陷类型、输入字段差异。
- 必做：按 root cause 归并，保留低置信度 bucket，标记不同根因但栈相似的样本。
- 易漏：同一栈顶吞掉多个 bug；不同平台地址差异被误判为多个 bug。
- 产出：bucket 列表、代表样本、置信度、去重规则和待人工复核项。

### 6. 可达性与影响判断

- 先查：入口是否外部可控、是否需认证/本地操作、是否默认启用、是否跨权限边界。
- 必做：写清触发路径、前置条件、影响资产、崩溃类型、缓解机制和证据缺口；可达性与可利用性分两栏。
- 易漏：把 crash 直接写成 RCE；把本地文件打开崩溃写成远程可达；忽略 sandbox/权限限制。
- 产出：可达性级别、影响边界、缓解措施状态、保守风险评级、无法证明项。

### 6.1 可利用性表述门禁

- 先查：崩溃类型、读写方向、控制数据是否受输入影响、内存权限、对象生命周期、崩溃前是否越过信任边界。
- 必做：只输出防御性判断，如“有内存破坏线索”“未证明控制流可控”“受沙箱和认证边界限制”；不得给 payload、布局、喷射、ROP 或绕过步骤。
- 易漏：把 UAF/OOB 写成必然 RCE；把 sanitizer 线索写成 exploitability 证明。
- 产出：可达性证据、可利用性未知项、防御优先级、需要补证的非武器化实验。

### 7. 防御复验与修复回归

- 先查：修复点、输入校验、边界处理、错误返回、相邻 parser/协议字段。
- 必做：旧样本复跑、最小样本复跑、边界样本复跑、sanitizer 复跑、符号化复跑、日志和退出码复核。
- 易漏：只验证不崩，不验证是否正确拒绝/降级；只测一个平台；未保存回归样本。
- 产出：修复前后对照、回归样本清单、缓解措施复核、剩余风险、建议门禁。

### 8. Root Cause 与报告验收

- 先查：root cause 是否能被输入字段、现场状态、源码/反汇编位置、sanitizer 证据或修复 diff 支撑。
- 必做：把“触发条件、错误机制、受影响版本、修复点、验证样本、不可验证项”逐项写清。
- 易漏：报告只列工具输出；影响范围没有版本边界；修复建议无法被测试复验。
- 产出：可复核 root cause、影响范围矩阵、修复验证结果、报告验收状态和剩余风险。

## 输出要求

每次崩溃分析与漏洞可达性逆向交付至少包含：

1. 授权边界、目标版本、平台架构、样本来源、输入哈希、dump/core 哈希和工具版本。
2. 崩溃类型、异常码/信号、模块、归一化偏移、栈可信度、寄存器/内存摘要。
3. 复现步骤、稳定性、最小输入、bucket 归属和同类样本去重口径。
4. root cause 证据链：错误条件、破坏点/崩溃点/触发点区分、输入字段、stack/heap 证据和源码/反汇编位置。
5. 可达性、前置条件、影响范围、已证实/推测/无法验证项。
6. 可利用性高层判断、缓解措施状态、修复建议、防御复验步骤、回归样本、sanitizer/符号化复跑结果。
7. 敏感数据处理说明：哪些证据已脱敏，哪些原始材料不能外发。
8. 报告验收结论：通过/不通过、阻塞缺口、复验命令摘要、证据存放位置和剩余风险。

## 验证门禁

- crash dump、core、minidump、ASAN/UBSAN 或复现输入至少拿到一种真实样本；只有文字描述、截图或日志片段时，只能列待补证项。
- 复现门禁：原始样本能在记录的版本、平台、命令/动作下触发；不可复现时，不输出确定根因、bucket 合并或影响评级。
- 符号门禁：符号完整才允许源码级定位；缺符号、优化构建、栈损坏或模块清单缺失时，结论降级到模块偏移、稳定帧、输入字段和置信度。
- 最小化门禁：最小输入必须证明仍属同一 bucket；若裁剪后异常码、模块偏移、sanitizer 类型或稳定帧变化，必须重新分桶。
- 可达性门禁：可达性必须有入口、前置条件、触发频率和环境限制；可利用性单独列未知项，不能从 crash 类型直接推导。
- 根因门禁：root cause 必须能解释输入如何到达错误状态、错误状态如何导致 stack/heap/寄存器现场；不能只引用栈顶函数或 sanitizer 标题。
- 修复回归门禁：原始样本、最小样本、边界样本和相邻字段样本至少覆盖一轮；只“不崩”但无正确拒绝/降级证据，不算通过。
- 防御复验门槛：修复后需补 sanitizer/符号化复跑、日志/退出码复核、缓解措施状态确认和剩余风险；未覆盖平台或缺证据要明示不通过项。
- 报告验收门禁：报告必须列清授权边界、证据链、影响范围、修复验证和安全边界；含 exploit 生成步骤、敏感明文或未证实高危断言时不通过。

## 二轮真实验收门禁

- 样本门禁：必须说明拿到的是 core、minidump、full dump、sanitizer 日志、复现输入或组合证据；只拿到截图、崩溃摘要、issue 描述、聊天转述时，结论只能是“待取证”。
- 采集门禁：core/minidump 必须记录采集工具、采集时机、线程数、模块列表、内存区段裁剪、生产数据脱敏状态和原始文件哈希；缺任何关键项都降低现场置信度。
- Symbol 门禁：符号包、build id、PDB/dSYM UUID、二进制哈希和版本必须互相匹配；错配符号按无符号处理，不允许输出源码行级结论。
- Stack 门禁：调用栈必须标注可信帧、可疑帧、缺失帧和栈破坏证据；尾调用、内联、异常展开、信号处理和跨 ABI 栈形态要单独说明不确定性。
- Heap 门禁：UAF/OOB/double free/overflow 必须有对象边界、allocator 状态、分配/释放栈、访问方向和邻接内存证据；只有崩溃地址时不能下 heap 根因。
- ASAN/UBSAN 门禁：sanitizer 标题只是线索，必须复核 shadow、对象生命周期、类型转换、运行时选项、符号化完整性、抑制规则和同输入稳定性。
- Triage 门禁：优先级必须来自可复现性、外部可控入口、权限/沙箱边界、默认暴露面、受影响资产、版本范围、是否已有修复和回归成本。
- Root cause 门禁：根因必须同时回答触发条件、错误机制、破坏点、崩溃点、输入字段、受影响版本和修复点；任一缺失时写成假设或待补证。
- Repro 门禁：复现必须记录命令/动作摘要、环境、依赖、随机种子、线程数、超时、频率和失败样本；非确定性 crash 不能按稳定漏洞收口。
- 影响范围门禁：影响必须绑定版本、平台、配置、入口、认证状态、默认启用状态和权限边界；不允许从单一 crash 泛化到全版本全平台。
- 修复验证门禁：修复通过必须同时满足原始样本不崩、最小样本不崩、边界样本正确拒绝/降级、合法样本不误拒、sanitizer/符号化复跑无同类证据。
- 结论降级门禁：无样本、不可复现、缺符号、minidump 裁剪、栈损坏、错配版本、生产数据脱敏过度或 sanitizer 无法复跑时，结论必须降级并列下一步取证。

## 安全边界

- 允许：授权防御分析、崩溃排障、漏洞 triage、修复验证、教育/CTF 中不伤害第三方的分析。
- 拒绝：武器化 exploit、真实目标利用、线上打崩、批量扫描、shellcode/ROP/JOP、绕过 ASLR/DEP/CFI/Sandbox 的利用步骤。
- 拒绝：提取或泄露 dump 中的 token、私钥、用户数据、商业源码、凭据和敏感路径。
- 遇到用户要求 exp、可利用性开发、缓解绕过或真实目标复现时，改为提供防御性 triage、修复建议和验证门禁。
- 遇到授权不清、样本归属不清、生产数据不可处理或输出会暴露敏感信息时，先停在 intake 和脱敏建议，不继续深挖。

## 高频 Bug 反例库

- 无样本哈希。对法：先固定原始输入和 dump 哈希。根因：无法复核同一现场。
- 只报绝对地址。对法：映射模块基址和文件偏移。根因：ASLR 让地址不可比较。
- 栈顶即根因。对法：检查 earlier corruption 和输入处理点。根因：崩溃点常是受害点。
- Sanitizer 直译。对法：复核对象生命周期和触发字段。根因：报告是线索不是完整根因。
- Bucketing 只看函数名。对法：结合缺陷类型、偏移和输入字段。根因：同栈可能多 bug。
- 最小化换了 bug。对法：每步验证 bucket 一致性。根因：格式破坏会触发新路径。
- Crash 等于高危。对法：分可达性、影响和可利用性不确定项。根因：崩溃不等于可利用。
- 缺符号硬下结论。对法：降级到模块偏移、稳定帧和输入字段。根因：源码级根因没有证据。
- 缓解措施只列名。对法：说明 ASLR/DEP/CFI/沙箱/权限边界对影响的限制。根因：风险评级缺上下文。
- Dump 明文外发。对法：脱敏和受控留存。根因：内存里常有敏感数据。
- 修复只测不崩。对法：验证正确拒绝、降级和边界输入。根因：吞错可能掩盖数据损坏。
- 输出利用路线。对法：只给防御复验和修复门禁。根因：利用细节可被攻击复用。
- 无授权边界。对法：先补授权范围、允许动作和停止条件。根因：crash 样本可能来自第三方或生产数据。
- Minidump 当 full dump。对法：标注内存裁剪范围和不可见对象。根因：缺页会误导 heap 结论。
- 符号包版本错配。对法：核对 build id/PDB/dSYM UUID。根因：错符号比无符号更危险。
- Heap 证据只看崩溃地址。对法：复核 allocator 元数据、对象大小和分配/释放栈。根因：破坏点常早于崩溃点。
- 影响范围不列版本。对法：绑定受影响版本、配置、平台和默认暴露面。根因：无法安排修复优先级。
- 修复验证缺负例。对法：增加合法输入、边界输入和相邻字段。根因：修复可能误拒或引入兼容问题。
- 报告写成漏洞营销。对法：分已证实/推测/未知并保守评级。根因：过度断言会误导响应。

## 相邻技能边界

- Fuzzing 与逆向联动/fuzzing-reverse-engineering（slug: fuzzrev）：负责 fuzz harness、corpus、coverage、长期 fuzz 策略；崩溃分析与漏洞可达性逆向只接收 crash 结果做 triage、bucketing、最小化和复验。
- 动态调试与运行时观察逆向/debug-reverse-engineering（slug: debugrev）：负责动态调试、断点、运行时观察；崩溃分析与漏洞可达性逆向在需要运行时补证时调用它，但结论仍以 crash 现场和复现证据收口。
- 通用二进制逆向/binary-reverse-engineering（slug: binrev）/ 汇编与指令集逆向/assembly-reverse-engineering（slug: asmrev）/ IR 与数据流高级静态分析逆向/irrev（slug: irrev）：负责二进制结构、汇编和 IR 深挖；崩溃分析与漏洞可达性逆向只抽取支撑崩溃根因的最小证据。
- 文件格式与私有格式逆向/file-format-reverse-engineering（slug: fmtrev）/ 授权私有协议逆向/protrev（slug: protrev）：负责文件格式和协议结构还原；崩溃分析与漏洞可达性逆向只标出触发字段和样本最小化证据。
- 补丁 Diff 与版本差异逆向/diff-reverse-engineering（slug: diffrev）：负责补丁前后差异；崩溃分析与漏洞可达性逆向使用差异验证修复是否覆盖原 crash。
- 测试验证/test-engineering（slug: tst）/ 代码审计/code-audit（slug: aud）：负责回归测试和最终审计；崩溃分析与漏洞可达性逆向提供样本、门禁和剩余风险。
