# 加密算法识别与实现审计逆向

## 定位 / 适用范围

加密算法识别与实现审计逆向（cryptographic-reverse-engineering，兼容 slug: cryptrev）负责授权样本中的加密算法识别、参数还原、实现审计和兼容排障。重点是把“疑似加密逻辑”拆成可复核证据：算法族、实现来源、常量、S-box、轮函数、模式、填充、IV、nonce、salt、AAD、随机数、密钥使用路径、签名原文、编码规范化、协议/格式边界和跨版本兼容差异。

覆盖对象：AES、DES/3DES、RC4、RSA、ECC、SM2/SM3/SM4、MD5/SHA/BLAKE、HMAC、PBKDF/scrypt/Argon2、XOR、查表算法、轮函数算法、TEA/XTEA 类算法、业务自定义混淆和编码/压缩/序列化外壳。

适用场景：授权安全审计、逆向样本中的算法识别、签名失败定位、协议/文件互操作排障、弱算法风险评估、密钥生命周期审计、随机数风险审计、合法兼容实现验证、CTF/教学和防御研究。

不适用场景：密钥窃取、口令爆破、未授权解密、DRM/许可证绕过、破解授权、支付/账号重放滥用、凭据攻击、绕过访问控制、把算法结论复用于攻击第三方服务。

## 铁律

1. 未确认授权、样本来源、数据范围、敏感字段和停止条件，不进入真实样本分析。
2. 先分层：编码、压缩、序列化、封包、加密、签名、MAC、哈希、校验和不能混为一类。
3. 密钥、私钥、token、cookie、seed、IV、nonce、salt、用户数据默认脱敏，只记录来源类型、生命周期和使用路径。
4. 只交付算法识别、参数路径、实现风险、兼容证据和防御修复建议；不交付密钥提取、爆破脚本、绕过流程或可复用攻击链。
5. 任何“算法确定”“实现有风险”“兼容不一致”结论必须绑定静态证据、动态证据、样本对照或官方/库行为证据。
6. key path 只做风险审计：记录生成、派生、存储、传输、缓存、日志和销毁路径，不协助提取、还原、导出或滥用真实 key。
7. 发现破解授权、绕过付费、DRM 绕过、攻击复用、生产重放、凭据滥用意图时，拒绝并改给合规审计或修复建议。

## 授权与安全边界

- 进入任务前必须写清：资产所有者、样本来源、允许的静态/动态动作、是否允许运行样本、是否允许联网、是否允许导出脱敏 fixture、停止条件和联系人。
- 只允许防御审计、互操作排障、兼容验证和修复建议；即便用户拥有样本，也不提供真实密钥恢复、私钥导出、口令爆破、授权绕过、DRM 绕过或生产服务重放步骤。
- 需要密钥材料才能验证时，只能使用测试 key、公开测试向量、用户提供的脱敏测试参数或本地临时生成参数；禁止要求用户贴真实生产 key。
- 报告中可以描述 key lifecycle 风险和轮换建议，但不得给出可用密钥、seed、token、cookie、私钥片段、完整带 key URL 或可直接复用的攻击参数。

## 快速总则

1. 建档：样本哈希、版本、平台、入口、调用方、输出目的、授权边界和脱敏规则。
2. 分层：先排除 Base64/hex/urlencode、gzip/zlib、protobuf/json、CRC/checksum，再判断加密或签名。
3. 识别：查库导入、函数名、OID/ASN.1、常量、S-box、轮常数、block size、输出长度、错误码和异常路径。
4. 追参：跟踪 key、iv、nonce、salt、mode、padding、aad、timestamp、counter、随机数和签名原文来源。
5. 复核：用脱敏 fixture、测试 key、公开向量或授权样本比对输入输出、失败模式和跨平台差异。
6. 交付：把已证实、推测、无法验证分开；风险必须说明触发条件、影响范围和补证路径。

## 证据门禁

- 算法识别证据分四类：静态结构、常量特征、动态调用、输入输出。确定结论至少两类吻合；只有一类时只能写候选和置信度。
- 静态结构：导入/API、函数名、OID/ASN.1、证书结构、block size、digest/tag 长度、错误码、状态机位置。
- 常量特征：AES S-box/Rcon/T-table、DES S-box/IP/FP、SM4 FK/CK/S-box、SHA/MD IV 和 round 常量、RC4 256 字节状态、TEA delta、曲线参数。
- 轮函数证据：轮数、key schedule、SubBytes/ShiftRows/MixColumns、Feistel、rotate/shift/add/xor、counter 更新、tag 校验路径。
- 输入输出证据：同输入同参数是否稳定、长度变化、padding/tag 错误行为、公开测试向量、脱敏 fixture、跨库对照。
- 编码/压缩/格式优先排除：Base64、hex、URL encode、gzip/zlib、protobuf/json、TLV、CRC/checksum 没有密钥语义时不能写成加密。
- 协议/格式边界必须说明：若主要问题是帧、握手、重放窗口、header、length、checksum、parser，不把它伪装成算法审计。
- 真实验收门禁：算法识别必须能被另一位审计者用证据编号、脱敏样本、工具版本和复核步骤复现；不能复现时只能写推测。
- 实现审计门禁：发现风险必须对应可观察触发点、影响范围、修复建议和回归验收；只有风险名词没有触发证据时不得写高危。

## 算法与实现审计要点

- 算法画像必须同时记录算法、mode、padding、key length、block/stream 边界、IV/nonce/salt/AAD/tag/counter、KDF 参数、RNG 来源、错误处理和库/实现版本。
- 常量/表识别要区分标准表、预计算表、白盒表、混淆表和业务查表；常量命中后必须继续找 round 函数、key schedule、状态更新、输入输出或库调用。
- KDF 审计要记录 salt 是否唯一、迭代次数/内存成本/并行度、输出长度、上下文绑定、版本迁移和弱参数兼容分支。
- key lifecycle 审计覆盖生成、派生、注入、存储、缓存、使用、日志、传输、轮换、吊销、销毁和跨租户隔离；只写路径与风险，不写真实值。
- 实现缺陷审计覆盖：ECB/CBC 无认证、GCM nonce 复用、tag 截断过短、padding oracle、验签缺失、MAC-then-encrypt 误用、错误码泄露、弱曲线、非恒定时间比较、异常分支兼容绕过。
- 自研或魔改实现要标出标准骨架、改动点、兼容影响、测试向量覆盖情况和不能互操作的边界；不能把“相似”写成“等同标准算法”。
- 协议上下文要绑定算法用途：字段位置、会话阶段、方向、重放窗口、版本协商、错误码和降级分支；脱离上下文的算法名不能代表真实安全结论。
- 结论降级优先于补猜：证据缺 mode/padding/KDF/RNG/key lifecycle 任一关键路径时，把“确认”降为“候选/待验证”，并写明下一条补证动作。

## 强制流程

1. 授权确认：记录资产、样本、接口/文件、用户许可、敏感字段、允许动作、禁止动作和停止条件。
2. 样本画像：记录文件类型、架构、语言/运行时、第三方库、混淆/壳、网络/文件/本地存储入口。
3. 分层判定：给每个疑似字段标注编码、压缩、序列化、校验、哈希、签名、加密或混淆层级。
4. 算法识别：用 API、导入、字符串、常量、S-box、轮函数、OID、ASN.1、长度和错误码形成候选，并给证据强度。
5. 参数追踪：沿数据流追 key、iv、nonce、salt、mode、padding、aad、seed、counter、timestamp 和签名原文，只记录脱敏路径。
6. 实现审计：检查弱算法、ECB、固定 IV、nonce 重复、随机数来源、硬编码、日志泄露、密钥生命周期、tag 校验和兼容分支。
7. 兼容验证：使用脱敏 fixture、公开测试向量或授权样本验证成功/失败路径、错误码、版本差异和平台差异。
8. 结论降级：按已证实、强推测、弱推测、无法验证标注证据等级；缺少关键参数或验收证据时主动降级。
9. 风险收口：输出证据、影响、修复建议、回归验收和剩余问题，确认未泄露密钥材料或绕授权步骤。

## 场景执行卡

### 1. 分层与候选算法识别

- 适用：看到高熵字段、不可读数据、签名参数、token、license 字段或私有二进制块。
- 必查：编码/压缩/序列化外壳、输入输出长度、错误码、调用栈、库导入、字符串、常量和协议/格式字段。
- 证据：字段样本、函数/类名、导入表、反编译片段位置、运行日志、长度变化和失败样本。
- 门禁：不能只凭“不可读”判定为加密；不能只凭一个常量就下算法定论；不能把 Base64、gzip、protobuf、CRC 或 license 格式壳误判为加密。
- 降级：只有高熵或长度异常时写“疑似编码/压缩/加密候选”，不得直接写算法名。
- 产出：分层图、算法候选、证据强度、仍需补证的字段。

### 2. 对称加密与流密码

- 覆盖：AES、DES/3DES、SM4、RC4、ChaCha20、TEA/XTEA 类实现。
- 必查：mode、padding、block size、IV/nonce/counter、AAD、tag、key schedule、错误码、库版本和兼容分支。
- 识别点：AES T-table/S-box/Rcon、DES S-box/Feistel、SM4 FK/CK/S-box、RC4 KSA/PRGA、ChaCha quarter round、TEA delta、轮数、异或链和计数器更新。
- 风险点：ECB、固定 IV、IV 可预测、nonce 重复、RC4 复用、padding oracle 迹象、CBC 无认证、GCM/CCM tag 未校验或截断过短。
- 验收：至少用公开向量、脱敏 fixture 或跨库对照确认 mode、padding、IV/nonce/tag 行为；只跑成功路径不算闭环。
- 产出：算法族、模式/填充、参数来源、复核样本、风险和修复建议。

### 3. 非对称、证书与签名

- 覆盖：RSA、ECC、SM2、证书链、ASN.1/DER、JWK/JKS/P12、PKCS 系列、ECDSA/EdDSA。
- 必查：key type、key size、curve、padding、hash、签名原文、字段排序、编码、时间戳、nonce、证书链和验签入口。
- 识别点：OID、BEGIN/END 标记、DER 结构、RSA padding 常量、曲线名、SM2 user id、签名长度和错误码。
- 风险点：PKCS#1 v1.5 使用场景、弱曲线、验签缺失、签名原文不一致、空值/排序/编码差异、时间窗口过宽、nonce/k 复用。
- 验收：签名结论必须绑定签名原文规范化、hash/padding/curve、证书或公钥来源、成功和失败样本。
- 产出：签名/验签流程、证书/公钥来源、规范化规则、兼容差异和失败样本。

### 4. 哈希、MAC 与 KDF

- 覆盖：MD5、SHA-1/2/3、SM3、BLAKE、HMAC、CMAC、PBKDF2、scrypt、Argon2、HKDF。
- 必查：用途、salt、迭代次数、输出截断、key 来源、比较方式、编码和存储格式。
- 识别点：初始化常量、IV、round 常量、digest 长度、HMAC ipad/opad、PBKDF 参数和错误路径。
- 风险点：MD5/SHA-1 用于安全边界、无 salt、迭代不足、MAC 截断过短、比较非恒定时间、KDF 参数弱。
- 边界：不做口令爆破、哈希还原、撞库、批量验证或凭据攻击。
- 验收：KDF/MAC 必须记录 salt/上下文绑定/输出截断/比较方式；缺这些参数时只给迁移建议，不给已安全结论。
- 产出：算法和用途、参数强度、存储/比较路径、风险分级和迁移建议。

### 5. XOR、自定义混淆与魔改算法

- 覆盖：XOR、滚动 key、查表替换、字节置换、轮函数、CRC 伪装、压缩后加扰、业务自定义封装。
- 必查：输入输出对、常量表、S-box、轮数、状态更新、key schedule、endian、长度字段、魔改分支和版本分支。
- 识别点：重复 key 周期、固定表、异或链、rotate/shift/add 混合、Feistel/SPN 痕迹、初始化向量和最终混合。
- 魔改判断：先找标准算法骨架，再标注改动点，如常量替换、轮数变化、S-box 重排、padding 私有化、endian 变化、前后置扰动。
- 证据要求：至少用两个样本或一个样本加动态调用链验证；不能把未验证推测写成确定算法；不能把“像 AES/TEA”写成已确认。
- 验收：常量表和 round 函数必须互相印证；只有查表或只有伪代码相似时，结论降为“结构相似”。
- 产出：伪代码级流程描述、字段假设、样本对照、兼容 fixture 和无法验证项。

### 6. 密钥使用路径与随机数风险

- 必查：key/iv/nonce/salt/seed 来源、派生路径、存储位置、传输路径、日志路径、缓存生命周期和清理策略。
- 常见来源：配置、资源、Keychain/Keystore、环境变量、服务端下发、用户输入、硬件安全模块、随机数 API、时间戳、设备指纹。
- RNG 必查：是否使用 CSPRNG、是否手动 seed、seed 熵来源、fork/多进程行为、启动早期熵、测试开关、伪随机库误用。
- 风险点：硬编码密钥、私钥打包、日志泄露、固定 seed、弱 PRNG、nonce 重复、时间戳当随机数、密钥跨租户复用、调试后门泄露参数。
- 证据边界：只记录来源类型、调用位置、脱敏片段或 hash；不贴真实密钥、私钥、token 或可用凭据。
- 验收：key lifecycle 必须覆盖生成/派生、存储、使用、轮换和销毁中至少实际可达路径；缺口写成待补证，不推断真实值。
- 产出：密钥生命周期图、随机数来源证据、风险评级、修复路径和验证门禁。

### 7. 协议/格式边界与误判排除

- 适用：算法逻辑和协议帧、文件格式、压缩编码、校验字段混在一起。
- 必查：magic/header/version/length/TLV/checksum、握手状态、序列号、重放窗口、压缩标记、base64 变体和字段 canonicalization。
- 分流：协议帧和抓包状态机为主转 `protrev` 或 `protocol-analysis`；文件格式和 parser 兼容为主转 `fmtrev`。
- 门禁：只有密钥、模式、填充、IV/nonce、签名/MAC 或算法实现证据时，才把核心结论归入 cryptrev。
- 验收：报告必须说明算法在协议中的阶段、方向、版本和错误路径；说不清上下文时只输出边界判定和转交建议。
- 产出：边界判定、保留给 cryptrev 的算法问题、应转交相邻技能的问题和补证清单。

### 8. 兼容排障与互操作验证

- 适用：同一算法不同端输出不一致、签名失败、老版本数据无法解密、跨语言实现不兼容。
- 必查：字符集、换行、字段排序、空值处理、JSON canonicalization、base64 变体、hex 大小写、endian、mode、padding、IV/nonce、tag 长度。
- 证据：成功样本、失败样本、输入原文、脱敏参数表、库版本、平台版本、错误码和最小 fixture。
- 门禁：只能用授权测试数据或脱敏数据；不能把验证变成生产接口重放。
- 产出：差异矩阵、最小复现、兼容结论、修复建议和回归样本。

### 9. 测试向量与回归验证

- 适用：需要证明识别结论、兼容实现或修复建议可复核。
- 必查：公开标准向量、库自带向量、脱敏 fixture、good/bad/edge 样本、错误路径样本和版本矩阵。
- 向量记录：算法、mode、padding、key length、IV/nonce/salt/AAD/tag、明文/密文长度、编码、库版本和预期错误。
- 门禁：真实业务 key、私钥、token、cookie、seed 不得进入向量；生产样本必须脱敏、最小化和低副作用。
- 降级：缺公开向量或脱敏 fixture 时，只能写识别证据和待验证项，不能声称互操作或修复验收完成。
- 产出：测试向量清单、覆盖缺口、跨库结果、失败样本、回归门禁和无法验证项。

### 10. 侧信道与运行时风险提示

- 适用：签名、MAC、KDF、认证解密、padding 错误、远程错误码、移动端或嵌入式实现审计。
- 必查：恒定时间比较、分支/表查找是否依赖 secret、padding/tag 错误是否区分、计时差异、缓存/功耗/日志/崩溃信息泄露和调试开关。
- 边界：只给防御审计、风险解释、复现实验设计和修复建议；不提供可攻击真实服务的测量脚本、爆破流程或绕过步骤。
- 降级：缺实验环境、噪声控制或可观察条件时，只能写侧信道风险提示，不写可利用结论。
- 产出：侧信道风险假设、可观察条件、影响面、低风险验证方案、修复建议和剩余不确定性。

### 11. 报告验收与交付收口

- 报告必须包含：授权范围、样本账本、证据编号、分层结论、算法/参数表、key lifecycle、RNG/KDF、实现缺陷、测试向量、兼容矩阵、风险评级、修复建议和拒绝边界。
- 每条结论标记已证实、强推测、弱推测或无法验证；每条高风险必须有触发条件、影响范围、复核证据和修复验收方式。
- 报告不得包含真实密钥材料、可用凭据、破解步骤、绕授权步骤、生产重放参数或可直接攻击第三方服务的流程。
- 验收口径：能让另一位授权审计者用脱敏材料复核结论；不能复核的内容必须写成假设或待补证。

## 结论降级规则

- 已证实：至少两类独立证据吻合，且有脱敏样本、公开向量或动态调用链可复核。
- 强推测：常量/结构/调用链高度吻合，但缺完整参数、向量或失败路径；必须列待补证。
- 弱推测：只有高熵、长度、单一常量、函数名或相似伪代码；只能作为候选，不给安全结论。
- 无法验证：授权、样本、参数、运行环境或脱敏材料不足；停止深挖，输出缺口和合规补证方式。
- 遇到破解授权、密钥导出、未授权解密或攻击复用意图时，不做降级分析，直接拒绝可用步骤并转防御建议。

## 验证门禁

- 授权、样本、入口、敏感字段、脱敏规则和停止条件齐全。
- 至少完成分层判断，明确哪些是编码、压缩、序列化、校验、哈希、签名、加密或混淆。
- 算法识别至少有 API/导入/常量/结构/OID/输入输出/运行证据之一；关键结论需要两类证据交叉印证。
- 常量/S-box/轮函数命中必须补调用链、轮数、输入输出或公开向量之一，否则只能作为候选。
- mode、padding、IV、nonce、salt、AAD、tag、counter 缺任一关键参数时，不能声称兼容实现已闭环。
- KDF/RNG/key lifecycle 缺路径、参数或可达证据时，只能写风险假设和补证项，不能写已确认安全或已修复。
- 实现缺陷必须绑定触发条件、失败路径、错误码/日志/调用链和修复验收；缺一项就降级为待复核。
- 协议上下文必须包含字段位置、会话阶段、方向、版本和错误路径；缺上下文时不能把算法结论扩展为协议结论。
- key/iv/nonce/salt/seed 来源只记录类型、生命周期和脱敏证据，禁止输出可用密钥材料。
- RNG 风险必须说明具体来源、seed、重复条件或平台行为，不能只凭函数名下结论。
- 兼容结论必须有成功/失败样本、版本、平台、库参数和错误码。
- 测试向量必须优先使用公开或脱敏数据，覆盖正常、错误、边界和跨版本路径；缺向量时不能声称修复已闭环。
- 侧信道风险必须写清观察条件和防御建议，不输出攻击第三方服务的计时脚本或绕过流程。
- 输出不包含密钥窃取、爆破、未授权解密、授权绕过、破解、重放滥用或攻击复用步骤。

## 输出要求

1. 授权范围、样本信息、入口、数据类型、敏感字段、脱敏规则和停止条件。
2. 分层结论：编码/压缩/序列化/校验/哈希/签名/加密/混淆分别是什么证据。
3. 算法识别：算法族、实现来源、常量/S-box/轮函数/OID/API/输入输出证据。
4. 参数路径：mode、padding、IV、nonce、salt、AAD、tag、key 来源、随机数来源和生命周期。
5. 边界判定：哪些属于协议/文件格式/编码压缩，哪些才是加密算法或签名/MAC 问题。
6. 兼容证据：成功/失败样本、错误码、库版本、平台差异、规范化差异和最小 fixture。
7. 风险结论：弱算法、固定参数、随机数、密钥暴露、签名缺陷、重放窗口和修复建议。
8. 置信度：已证实、强推测、弱推测、无法验证和需要补充的证据。
9. 测试与验收：公开向量、脱敏 fixture、good/bad/edge 样本、跨库/跨版本结果和回归门禁。
10. 安全交付：明确拒绝项、已脱敏字段、未输出密钥材料、未提供绕授权或攻击复用步骤。

## 安全边界

允许：

- 授权审计、防御验证、兼容排障、合法互操作、教育/CTF、修复建议、脱敏证据整理。

拒绝：

- 密钥窃取、私钥提取、token/凭据收集、口令爆破、哈希撞库、彩虹表、批量验证、未授权解密、解密绕过、绕过访问控制、绕过授权/许可证/DRM、破解软件、支付或账号接口重放、攻击第三方服务、批量滥用、把审计发现改造成可复用攻击流程。

遇到拒绝场景时，给出合规替代：如何做授权审计、如何轮换密钥、如何修复随机数/IV/nonce、如何迁移算法、如何构造脱敏兼容测试。

## 高频 Bug 反例库

1. 把 Base64 当加密。对法：先分层，编码只说明表示形式。
2. 把 gzip/protobuf/TLV/CRC 当加密。对法：先确认是否存在 key、mode、MAC/signature 或算法调用。
3. 看到 AES 就判安全。对法：继续查 mode、padding、IV、nonce、tag 和 key 来源。
4. 只凭 S-box 定算法。对法：补轮函数、调用链、输入输出或库 API 证据。
5. 魔改算法直接套标准名。对法：写标准骨架、改动点、证据强度和兼容限制。
6. 忽略签名原文规范化。对法：核字段排序、空值、字符集、换行、body 原文和 base64 变体。
7. MD5 命中即高危或无害。对法：看用途、可达性、安全边界和替代方案。
8. 随机数只看函数名。对法：查 seed、熵源、重复性、fork/多进程行为和平台差异。
9. 贴出真实 key/token。对法：只写来源类型、脱敏片段、hash 或生命周期图。
10. 自定义算法乱命名。对法：按“疑似 Feistel/SPN/XOR 链/查表混淆”加置信度。
11. 兼容验证变生产重放。对法：只用授权测试环境、脱敏 fixture 和低副作用样本。
12. 把文件格式问题归为加密问题。对法：若核心是 magic/header/length/checksum/TLV，转 `fmtrev`。
13. 把协议状态机问题归为加密问题。对法：若核心是握手、心跳、序列号、重放窗口或抓包字段，转 `protrev` 或 `protocol-analysis`。
14. 用户要求“帮我解密/破解/爆破”。对法：拒绝可用攻击步骤，改给授权审计、迁移、轮换和脱敏测试方案。
15. 只看 API 名称不看参数。对法：补 mode、padding、IV/nonce、tag、AAD、KDF 和错误路径；根因是库默认值常随语言和版本变化。
16. 忽略 KDF 参数。对法：记录 salt、迭代/内存/并行度、输出长度和迁移版本；根因是同名算法参数弱也会失效。
17. 把 nonce 当普通随机字段。对法：检查唯一性、计数器、重启复用、多进程和跨租户；根因是 AEAD 安全依赖 nonce 约束。
18. 只验证成功路径。对法：补 bad/edge 向量、tag 错误、padding 错误、空输入、长度异常和旧版本样本；根因是缺陷常在失败路径暴露。
19. 把侧信道写成可攻击流程。对法：只写观察条件、风险和修复建议，不给真实目标测量脚本或绕过步骤。
20. 报告只有结论没有证据编号。对法：每条结论绑定样本、函数、调用链、向量或日志；根因是无法复核。
21. 用生产 key 做互操作测试。对法：改用测试 key、公开向量或脱敏 fixture；根因是把审计验证变成敏感材料扩散。
22. 发现授权绕过路径后继续深挖。对法：停止可用绕过细节，转成风险描述、修复建议和复核门禁。
23. 把库默认值当已知参数。对法：记录语言、库版本和显式参数；根因是默认 mode/padding/tag 行为会随版本变化。
24. 只写“存在侧信道”。对法：补观察条件、受影响路径、噪声限制和修复建议；根因是风险提示和可利用结论不同。
25. 只看加密函数不看协议阶段。对法：补字段位置、方向、会话状态和错误路径；根因是算法安全不等于协议安全。
26. 测试向量缺失败路径。对法：补错误 tag、错误 padding、空输入、截断输入和旧版本样本；根因是实现缺陷常在异常路径暴露。
27. KDF 只写算法名。对法：补 salt、成本参数、输出长度、上下文绑定和迁移版本；根因是同名 KDF 强度取决于参数。
28. 常量表命中后跳过 round 函数。对法：补轮数、状态更新、key schedule 和输入输出；根因是常量可被复用、混淆或诱导。
29. 报告把强推测写成已证实。对法：用已证实/强推测/弱推测/无法验证分级；根因是证据等级不透明。
30. 修复建议没有验收方式。对法：写回归向量、库版本、配置参数、错误路径和复核步骤；根因是建议不可落地。
