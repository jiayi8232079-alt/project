# 动态调试与运行时观察逆向

## 定位 / 适用范围

动态调试与运行时观察逆向（debug-reverse-engineering，兼容 slug: debugrev）负责授权样本的动态调试和运行时观察。核心任务是用 x64dbg、gdb、lldb、WinDbg、Frida 等工具，在隔离环境中最小化附加、最小化断点、最小化副作用，观察寄存器、内存、调用栈、函数参数、返回值、线程状态、模块映射、日志和崩溃现场，把运行时证据回填到静态地址、文件偏移、函数边界和复现步骤。

适用：授权二进制/闭源组件/崩溃样本的运行路径确认、参数来源追踪、调用栈复核、解析流程观察、兼容排障、CTF/教学、防御审计和补证。

不适用：普通应用 debug、业务代码断点排错、只读学习调试器、恶意注入、反调试/反虚拟机/EDR 绕过、破解授权、外挂辅助、凭据窃取、真实目标攻击。

## 铁律

1. 未确认授权、样本边界、隔离环境、允许动作、数据留存和停止条件，不运行样本、不附加进程、不注入脚本。
2. 默认只读观察：断点、单步、寄存器、内存摘要、调用栈、参数、返回值、日志和 dump；不改内存、不 patch、不劫持控制流。
3. 断点最小化：每个断点必须有观察目标、触发条件、预期证据和撤销方式；禁止随机扫断点、长时间无计划单步。
4. 证据可复核：记录样本哈希、工具版本、系统版本、模块基址、运行地址、文件偏移、输入、动作、时间线和日志编号。
5. Frida 仅用于授权范围内的参数/返回值/调用频率观察和脱敏导出；不用于绕过、篡改、批量注入、窃密或持久化。
6. 遇到保护、反调试、崩溃或环境检测时，记录阻塞证据和影响范围，不提供绕过方案。
7. 反调试、反虚拟机、RASP、EDR、License、风控或完整性校验造成阻塞时，默认降级为 dump、日志、系统事件、离线 core、静态证据、复现脚本和环境差异对比，不写隐藏、禁用、绕过或中和步骤。
8. 工具能力不能覆盖授权边界：Frida、WinDbg、gdb、lldb、x64dbg 只能服务观察目标，不能把任务改写成注入、绕过、破解或攻击复用教程。

## 调试前门禁

- 授权：确认授权方、样本来源、使用目的、允许工具、允许附加/启动方式、禁止动作和结束条件。
- 隔离：使用 VM/容器/测试机，快照可回滚，权限最小化，网络默认阻断或白名单，禁止连接真实生产账号和真实生产目标。
- 范围：只观察授权样本、授权进程、授权输入和授权账号态；父子进程、插件、驱动、系统服务、浏览器扩展或移动 App 需单独列入范围。
- 数据：运行时可能出现 token、cookie、证书、私钥、PII、客户数据和商业密钥；默认只记录类型、长度、哈希、掩码片段和值域。
- 留存：样本、dump、日志、截图、脚本和导出值放入证据目录；敏感参数只保留摘要、长度、类型、哈希或脱敏片段。
- 变更：默认不改内存、不改文件、不改返回值、不启用持久化 hook；确需干预时先停止并转授权复核。
- 停止：越界进程、未知联网、凭据暴露、破坏性行为、生产环境影响或保护阻塞升级时立即停止运行观察。

## 真实验收门禁

- 不能只写“已验证”：必须给出样本哈希、环境快照、工具版本、输入、启动/附加方式、断点计划、证据编号和 readback/复跑结果。
- 隔离验收：确认运行主机不是生产机，网络策略已记录，快照或还原点可用，样本输出目录和日志目录可清理。
- 动态验收：至少有一个可复核观察点命中记录，包含断点/watchpoint/trace 的位置、条件、字段、触发次数、撤销方式和时序影响。
- 符号验收：写清符号来源、加载状态、缺失影响和地址映射；符号不完整时只能给 RVA/候选函数/置信度，不给确定命名。
- 工具边界验收：LLDB/GDB/WinDbg/x64dbg 只给观察、dump、trace 和映射证据；Frida 只给观测型 hook、采样上限和脱敏导出，不给隐藏、绕过或篡改步骤。
- 敏感数据验收：报告、日志、trace、截图和脚本输出不得保留完整 token、cookie、私钥、证书、PII 或客户数据；必要时只留类型、长度、哈希、掩码和值域。
- 保护阻塞验收：反调试、反虚拟机、完整性校验、RASP/EDR/License 阻塞只记录触发条件、现象、日志、影响和替代证据，不写绕过保护的操作链。
- 复现验收：复现脚本或步骤只能启动授权样本、设置输入、收集只读日志和校验哈希；不能包含注入、持久化、规避检测、篡改返回值或连接真实目标。

## 快速总则

1. 先定边界：样本、进程、主机/VM、网络策略、允许工具、允许观察点、敏感数据处理、停止条件。
2. 先复现再断点：固定输入、账号态、配置、启动参数、操作步骤和预期现象。
3. 先粗后细：日志、dump、模块映射、符号状态、异常点、API 边界优先；必要时再下到指令级。
4. 先读后写：内存窗口、寄存器、栈、参数、返回值和调用栈优先；任何修改都默认不做，必须有单独授权和影响说明。
5. 先映射再结论：运行地址必须映射到模块基址、RVA/偏移、符号/函数和静态证据。
6. 先互证再交付：动态观察要和反编译、日志、抓包、dump、core、minidump 或崩溃复现互相印证。

## 强制流程

1. 授权确认：写清样本来源、哈希、授权方、目标进程、环境、允许动作、禁止动作和停止条件。
2. 环境准备：快照、最小权限、受控网络、符号/源码/日志路径、工具版本、时间同步和证据目录。
3. 复现入口：启动方式、输入样本、命令行参数、账号态、触发动作、预期结果和失败表现。
4. 断点计划：列出函数/API/地址/异常/日志点、断点类型、触发条件、观察字段和撤销方式。
5. 运行观察：记录寄存器、内存摘要、栈、调用栈、参数、返回值、线程、模块、文件/网络/日志摘要。
6. 崩溃复核：保留 dump/core/minidump、异常码、崩溃地址、线程、输入、最小复现和符号状态。
7. 证据映射：把动态地址映射为模块基址、RVA、文件偏移、符号/函数和静态位置。
8. 结论分级：已验证、合理推测、无法验证分别列出，并写明副作用、缺口和下一步补证。

## 最小断点策略

- 先选边界点：入口、导出函数、parser/decoder、I/O、日志点、错误分支、异常处理器、崩溃前一跳；避免全模块扫断点。
- 优先条件断点、一次性断点、硬件/访问断点、watchpoint 和异常断点；每轮只保留能回答当前问题的少量断点。
- 每个断点/watchpoint 记录：位置、类型、条件、触发次数、观察字段、预期证据、撤销动作、是否改变时序。
- watchpoint 只用于已知地址/结构/字段的读写确认；必须先说明地址来源、生命周期、线程范围和误报来源，禁止把大范围内存监控当默认手段。
- 断点命中后只取必要摘要：参数类型/长度/哈希、寄存器关键值、栈顶窗口、调用者、返回值、线程和模块。
- 连续单步只用于确认短路径或崩溃前后指令；超过预期步数时回到静态分析或日志证据，不靠盲目单步推进。

## Trace 与符号策略

- trace 先从日志、系统事件、调用栈采样、异常链和函数边界开始；指令级 trace 只用于短窗口、明确问题和可控输入。
- 每次 trace 记录采样范围、开始/停止条件、过滤条件、丢样可能、时序影响、文件路径、大小、哈希和解析脚本版本。
- trace 输出按证据编号保存原始文件和脱敏摘要；报告只贴关键片段、调用顺序、分支条件和无法解释的空洞。
- 符号状态必须写清：完整符号、导出符号、strip、PDB/DWARF/dSYM、map 文件、供应商符号、签名版本和加载失败原因。
- 符号不完整时，结论降级为地址/RVA/函数候选；不得把猜测符号名写成已验证事实。
- 地址换算统一保留运行 VA、模块基址、RVA、文件偏移、节区、加载偏移和 ASLR/PIE 状态。

## 证据记录粒度

- 参数：来源、类型、长度、编码、边界值、脱敏样例、转换前后关系和调用者。
- 内存：地址、模块、RVA、权限、窗口范围、摘要/哈希、结构猜测置信度；不完整导出敏感缓冲区。
- 调用栈：线程、栈帧、返回地址、模块、符号状态、调用方向和静态位置。
- 时间线：T0 环境准备，T1 启动/附加，T2 输入/操作，T3 断点/日志命中，T4 异常/返回，T5 dump/清理；每条写时间、动作、工具、证据编号和结论。
- 崩溃：至少复核两次或说明无法复核原因；区分稳定复现、偶发、环境相关和被调试影响。

## 工具执行卡

### x64dbg / Windows 用户态

- 用于授权 PE/DLL/服务进程的最小断点、异常点、API 边界、调用栈、寄存器和内存观察。
- 优先断在入口、导出函数、可疑 API、日志点、错误分支、异常处理器或崩溃前一跳。
- 证据必须包含模块基址、RVA、文件偏移、断点条件、触发次数、寄存器/栈摘要和截图/日志编号。
- 硬件断点/watchpoint 只用于确认特定字段读写；记录线程、访问类型、命中上下文和是否受调试器时序影响。
- 不输出 DLL 注入、进程劫持、补丁破解、反调试绕过或保护规避步骤。
- 若附加触发保护、退出或异常，只记录现象、事件日志、异常码、模块和时间线，降级到 dump/日志/静态互证。

### gdb / Linux 用户态

- 用于 ELF、so、core、信号、线程、syscall 边界、参数和值域观察。
- 重点记录命令行、环境变量、ASLR/PIE 状态、映射表、符号状态、信号、backtrace、寄存器和内存摘要。
- 断点/watchpoint/tracepoint 需限定函数、线程、条件和采样字段；符号缺失时保留 build-id、maps、RVA 和候选函数证据。
- 崩溃复核要保留 core、触发输入、线程栈、崩溃地址、可复现命令和最小样本。
- 不把 ptrace 限制、seccomp、namespace、反调试阻塞改写成绕过教程；先写受限结论和替代证据。

### lldb / macOS 与跨平台

- 用于 Mach-O、dylib、Swift/ObjC/C/C++ 运行路径、异常、线程和参数观察。
- 重点记录系统版本、entitlements/签名状态、模块加载、符号状态、断点条件、调用栈和返回值。
- watchpoint 和短窗口 trace 必须说明对象生命周期、ARC/Swift bridging 影响、线程队列和符号解析置信度。
- 移动 App 专项、越狱/Root 绕过、证书绕过等不在本技能内，转 mrev/msec 并遵守授权边界；debugrev 只保留跨平台调试证据。

### WinDbg / dump 与复杂 Windows 现场

- 用于 minidump/full dump、异常、线程、模块、符号、堆栈、内存破坏和系统组件交互复核。
- 必须记录 dump 路径、符号源、OS build、模块版本、异常码、线程、stack、register、loaded modules 和分析限制。
- live debug 仅限隔离测试机和授权进程；优先 dump/minidump/ETW/EventLog/Procmon 类只读证据，避免生产机交互式调试。
- Windows 驱动、Verifier、IRQL、WDF/WDK 细节交给 windows-driver-development；debugrev 只接授权运行时观察和 dump 证据。
- 不给内核提权、驱动绕过、PatchGuard/EDR 规避或生产机 live debug 操作建议。

### Frida / 运行时观察

- 用于授权范围内观察函数参数、返回值、调用频率、调用者、线程上下文和脱敏样本值。
- 仅写观测型 hook，禁止修改返回值、绕过校验、隐藏环境、拦截凭据、批量注入、远程控制或持久化。
- Frida 脚本只保留观察点、字段选择、脱敏逻辑、采样上限和停止方式；不提供隐藏、反检测、绕过完整性、注入滥用或持久化流程。
- 输出要说明 hook 点、字段脱敏策略、采样范围、误差来源、脚本副作用、卸载/停止方式和是否改变时序。

## 场景执行卡

### 1. 参数来源追踪

- 入口：用户输入、文件字段、协议字段、配置、环境变量、IPC、API 参数或返回值。
- 观察：断在 parser、decoder、validator、crypto、I/O、error branch 和关键调用者。
- 输出：参数来源、转换链、值域、边界条件、调用栈、日志编号和无法确认项。

### 2. 调用栈与控制流复核

- 入口：静态反编译不可信、间接调用、虚表、回调、插件加载、异常处理或动态库边界。
- 观察：调用者、被调函数、返回地址、线程、模块、符号、RVA 和条件分支。
- 输出：运行时调用链、静态位置映射、触发条件和需要 asmrev/binrev 补证的点。

### 3. 崩溃复核

- 入口：dump/core/minidump、日志崩溃点、异常码、ASAN/UBSAN 报告或用户复现步骤。
- 观察：崩溃线程、寄存器、栈、异常地址、内存访问、模块版本、输入和复现稳定性。
- 输出：最小复现、可达性证据、影响初判、未验证项；可达性、利用性、修复验证转 crashrev。

### 4. 日志与运行证据补强

- 入口：线上日志、客户复现、兼容问题、动态库加载异常、配置差异或版本差异。
- 观察：模块加载、路径、权限、错误码、返回值、线程、文件/网络摘要和关键参数。
- 输出：时间线、日志片段编号、环境差异、已排除项和下一步验证。

### 5. 保护或检测阻塞

- 入口：调试器附加失败、进程退出、异常行为、环境检测、符号缺失或样本自毁风险。
- 观察：只记录触发条件、阻塞现象、日志、异常码、影响范围、可见反调试/反虚拟机/完整性检查线索和替代只读证据。
- 降级：改用离线 dump/core、系统日志、崩溃报告、静态反编译、导入/字符串、可控输入差异、无调试器运行日志或供应商符号。
- 输出：分析受限结论，不给绕过、隐藏、禁用、中和、规避或检测对抗实现。

### 6. 可复现报告交付

- 入口：需要给研发、供应商、审计或法务复核动态证据。
- 观察：固化样本哈希、环境快照、工具版本、输入、操作步骤、断点计划、trace/dump/log 编号和脱敏策略。
- 输出：最小复现、证据索引、地址映射表、结论置信度、无法复现原因、风险边界和下一步授权补证。

### 7. 复现脚本边界

- 复现脚本只允许封装环境检查、样本启动、输入投喂、日志/dump/trace 收集、哈希校验和清理动作。
- 脚本内必须显式写出样本路径、输入路径、输出目录、网络策略假设和停止条件；缺任一项时只能给人工步骤。
- 脚本输出默认脱敏，敏感字段只输出摘要；禁止把运行时缓冲区、凭据、证书、私钥或客户数据完整落盘。
- 脚本不得包含绕过调试检测、隐藏调试器、禁用完整性校验、修改内存、篡改返回值、注入持久化或真实目标连接。

## 证据门禁

- 授权、隔离、样本哈希、工具版本、系统版本、网络策略和停止条件齐全。
- 每个断点都有目的、位置、条件、观察字段、触发步骤和撤销方式。
- 每个 watchpoint/trace 都有范围、采样条件、输出位置、时序影响和撤销方式。
- 寄存器、内存、栈、调用栈、参数和返回值只记录必要摘要；敏感数据已脱敏。
- 运行地址已映射模块基址、RVA/文件偏移、符号/函数和静态证据。
- 崩溃证据包含输入、dump/core/minidump、异常码、崩溃地址、线程、栈和复现状态。
- 报告可复现：同一输入、同一版本、同一环境策略下能复跑；不能复跑时写清环境差异和缺失证据。
- 输出不包含绕过检测、破解授权、恶意注入、凭据窃取、外挂或攻击复用步骤。

## 输出要求

1. 授权与环境：样本哈希、目标进程、系统、工具版本、网络策略、允许动作、停止条件。
2. 复现步骤：输入、命令、账号态、配置、操作时间线、预期和实际结果。
3. 断点计划：工具、断点类型、地址/函数/API、条件、观察字段、撤销方式。
4. 运行证据：寄存器、内存摘要、栈、调用栈、参数、返回值、线程、模块、日志编号。
5. 映射关系：模块基址、RVA、文件偏移、符号/函数、静态证据位置。
6. 结论分级：已验证、推测、无法验证、分析受限原因、副作用和补证建议。
7. 时间线：按证据编号串联启动、输入、断点、日志、异常、dump、清理和复核动作。
8. 复现包索引：样本哈希、配置、输入、工具版本、trace/dump/log 文件、脱敏说明和校验哈希。

## 安全边界

- 只支持授权调试、防御审计、兼容排障、崩溃复核、CTF/教学和证据补强。
- 默认只读、非破坏、最小附加、最小断点、最小日志导出。
- 不提供反调试绕过、反虚拟机绕过、RASP/AV/EDR 规避、DLL 注入滥用、远程线程注入、进程劫持、外挂、破解授权、凭据窃取或真实目标攻击。
- 涉及可能改变行为的内存修改、patch、返回值篡改、hook 干预时，默认拒绝；如属授权防御复验，必须另列范围、影响、回滚和审计证据。

## 高频 Bug 反例库

- 反例 1：无授权附加进程。错法：直接 attach 第三方生产进程。对法：先确认授权、环境和停止条件。根因：动态调试会影响运行和数据。
- 反例 2：断点无目标。错法：随机下断点和长时间单步。对法：每个断点写观察字段和触发条件。根因：不可复跑的观察不能当证据。
- 反例 3：只写 VA 不写偏移。错法：报告里只贴运行地址。对法：补模块基址、RVA、文件偏移和符号。根因：ASLR/PIE 让地址不稳定。
- 反例 4：把 hook 当观察。错法：修改返回值后直接下结论。对法：默认只读观察，任何干预另列授权和影响。根因：干预会改变真实路径。
- 反例 5：保护阻塞就写绕过。错法：给反调试隐藏流程。对法：记录阻塞条件和替代证据。根因：安全保护不能转成规避教程。
- 反例 6：Frida 导出敏感值。错法：完整打印 token、cookie、PII。对法：只记录脱敏摘要和值域。根因：运行时参数常包含敏感数据。
- 反例 7：单次崩溃定性。错法：一次 crash 就判漏洞可利用。对法：保留输入、dump 和复现稳定性，转 crashrev 复核。根因：可达性和影响需要互证。
- 反例 8：普通业务 debug 误触发。错法：把 Web/API/前端断点排错归 debugrev。对法：转对应开发或测试技能。根因：本技能只处理逆向运行时观察。
- 反例 9：trace 无边界。错法：长时间全量指令 trace 后挑片段下结论。对法：限定窗口、过滤条件和丢样说明。根因：trace 会改变时序且难以复核。
- 反例 10：符号猜测当事实。错法：把自动命名函数写成真实 API。对法：标注符号来源和置信度。根因：strip/混淆/优化会误导命名。
- 反例 11：watchpoint 大撒网。错法：对大块内存持续访问监控。对法：只监控已知字段并记录生命周期。根因：误报和性能扰动会污染证据。
- 反例 12：反调试识别后继续对抗。错法：写隐藏调试器或禁用检测步骤。对法：记录保护线索、影响和替代证据。根因：防御记录不能升级成绕过教程。
- 反例 13：报告说已验收但无 readback。错法：只贴截图或口头说明。对法：给原始证据编号、复跑结果和限制条件。根因：动态调试结论必须可复核。
- 反例 14：隔离环境写得含糊。错法：只写“本地测试”。对法：列 VM/容器/测试机、快照、网络策略和账号边界。根因：运行样本的副作用需要可控。
- 反例 15：WinDbg live 生产机。错法：为快直接附加生产进程。对法：优先 dump、EventLog、ETW、Procmon 或隔离复现。根因：交互式调试会影响真实业务。
- 反例 16：LLDB/GDB 命令当成结论。错法：贴一段 backtrace 就定性。对法：补符号状态、输入、线程、地址映射和互证证据。根因：单个工具视图容易误导。
- 反例 17：Frida 脚本越界。错法：在观察脚本中顺手改返回值或隐藏环境。对法：只采样参数、返回值和调用频率并写脱敏策略。根因：观测与干预必须分开。
- 反例 18：复现脚本变成攻击模板。错法：脚本带注入、绕过、持久化或真实目标连接。对法：只保留授权样本启动、输入、日志收集和校验。根因：复现包不能扩大滥用能力。
