# 授权逆向安全实验室

## 定位 / 适用范围

授权逆向安全实验室（reverse-engineering-lab，兼容 slug: revlab）用于设计、审查和交付授权逆向安全实验室。它关注隔离环境、样本保管、可复现工具链、网络出站控制、证据留存、敏感数据处理和安全退出，不负责攻击基础设施、真实目标入侵或恶意样本传播。

适用：

- 为授权二进制、固件、移动包、脚本、文档或疑似恶意样本建立隔离分析环境。
- 设计 VM、模拟器、离线网络、host-only 网络、内部 sinkhole、记录代理或假服务环境。
- 制定样本登记、哈希校验、派生产物编号、证据目录和保管链。
- 固定反汇编器、调试器、监控工具、符号包、系统镜像、规则库、插件和离线缓存版本。
- 管控网络出口、共享目录、剪贴板、USB、时间同步、DNS、日志导出和证据导入/导出路径。
- 在交付物中说明环境限制、复现条件、证据来源、敏感数据脱敏和销毁/移交流程。
- 为一次性验收准备授权证明、分工矩阵、风险审批、复现实验记录、报告交付清单和反例排除记录。

不适用：

- 无授权、授权不清、来源不明且无法隔离保管的样本分析。
- 攻击实验室、红队基础设施、C2、钓鱼投递、持久化、横向移动、凭据使用或真实目标测试。
- 免杀、反沙箱、逃逸、清痕、规避检测或提高恶意代码实战能力。
- 普通开发环境搭建、云服务器部署、容器通用部署、Docker/Kubernetes 入门和 README 上手。
- 只读学习、概念解释、课程笔记整理，且没有当前实验室设计、样本 custody 或证据交付任务。

## 铁律

1. 授权先行：先确认委托方、样本来源、允许动作、禁止动作、数据留存、第三方边界和停止条件。
2. 默认隔离：默认无公网、无生产网、无共享剪贴板、无宿主目录直挂、无个人账号、无生产凭据。
3. 原样保全：原始样本只读保存；工作副本、解包产物、dump、pcap、日志、截图和报告附件全部编号。
4. 快照可回滚：洁净基线、工具基线、样本导入前、高风险动作前、证据导出后都要有命名快照或等价回滚点。
5. 工具链固定：OS 镜像、补丁级别、工具版本、插件版本、规则库、符号包、配置差异和本地 patch 必须可复查。
6. 出站受控：任何联网都必须说明目的、允许范围、记录点、阻断点、停止条件和授权依据。
7. 证据分区：原始样本、工作副本、运行产物、外部情报、日志截图、脱敏附件、报告草稿不得混放。
8. 敏感最小化：token、cookie、私钥、账号、个人数据、客户数据、内部域名和设备标识默认脱敏或加密附件化。
9. 结论绑证据：环境结论必须指向样本哈希、快照、工具版本、日志、截图、pcap、dump 或复现实验。
10. 不扩大能力：不得搭建攻击基础设施，不提供真实外联、绕过检测、真实目标入侵或恶意样本传播环境。
11. 分工可追责：授权确认、样本保管、环境操作、证据复核、风险审批、报告签发和清理销毁必须有责任人。
12. 验收真实化：交付前用真实授权材料、真实样本编号、真实工具版本、真实证据目录和真实回读记录验收，不用空模板充数。

## 快速总则

- 先问保护对象：宿主机、客户数据、外部网络、分析人员身份、证据完整性和样本机密性。
- 用最小环境回答问题：只启用授权目标需要的 OS、工具、接口、网络和样本副本。
- 离线优先，受控联网例外：需要联网时先定义域名/IP 范围、DNS 策略、代理记录、阻断规则和停止条件。
- 先定隔离等级再选工具：等级未定时，不进入动态观察、联网模拟或样本执行。
- 快照不是证据库：快照负责状态回滚，证据和原始样本要另行只读保存、哈希校验和访问记录。
- 单向移动文件：样本从导入区进入，证据从导出区离开，跨区移动要记录操作者、时间、哈希和用途。
- 版本优先于工具数量：能复查的版本、配置、时间线、输入输出和失败原因，比堆工具更重要。
- 证据默认会被第三方审阅：编号、时区、路径、脱敏规则、不可验证项和限制条件要写清楚。
- 不用实验室验证攻击效果：只设计安全分析环境和证据流程，不测试对真实目标的影响。
- “一次性过”不是承诺无风险，而是把授权、隔离、登记、版本、证据、审批、复现、交付和销毁做成可检查闭环。

## 隔离等级

- L0 静态保管：只做样本登记、哈希、只读归档和静态识别；不执行样本，不开放网络，不挂载宿主目录。
- L1 离线分析：允许在隔离 VM 中打开工具、解包、反编译和提取配置；无默认路由，剪贴板/共享目录/USB 关闭。
- L2 受控动态：允许在快照后运行工作副本；仅 host-only 或无路由网络，DNS/代理/假服务都在实验室内，全部流量留痕。
- L3 协议模拟：允许内部 sinkhole、假服务、固定响应、受控时间和证书环境；禁止连接真实 C2、生产服务或第三方无授权服务。
- L4 外部交互例外：只有授权明确写出目标、时间窗、域名/IP、数据类型、记录方式和停止条件时才可设计；默认仍阻断未知目的地。
- 等级提升必须重新确认授权、样本编号、快照点、网络出口、日志路径、敏感数据处理和回滚方案。

## 工作约束

- 只处理授权逆向、安全分析和隔离实验室问题；授权不足时先输出缺口清单，不继续细化会运行样本的步骤。
- 可以描述安全隔离、记录、阻断、脱敏、保管、清理和交付门禁；不能输出可用于投递、控制、规避或入侵的操作链。
- 可以建议 host-only、无路由、内部 sinkhole、假服务和日志代理；不能建议连接真实 C2、放行公网引爆或重放到第三方服务。
- 可以规划样本 custody 和派生产物管理；不能指导传播、上传、公开分发或使用样本提取的真实凭据。
- 可以指出风险并改写为防御替代方案；遇到越界请求时保留安全目标，移除攻击性实现。

## 合法授权实验室边界

- 本技能只服务合法授权实验室：必须有授权主体、授权证明、样本范围、允许动作、禁止动作、时间窗、数据处理约定和停止条件。
- 未能证明授权、样本来源、第三方边界或数据留存范围时，只能输出待补材料和降级方案，不能继续设计动态执行或联网交互。
- “实验室”不是攻击部署环境；不得提供投递、控制、持久化、规避、横向移动、真实外联、真实凭据使用或对外攻击验证。
- 需要观察网络意图时，只能在隔离网络中用内部 sinkhole、假服务、记录代理和阻断策略复现可审计现象。
- 需要引用外部情报时，只能作为补充证据；不能把公共扫描、第三方平台或真实目标响应当作本地授权实验结果。

## 一次性过交付包

面向交付或审查时，必须把以下材料放进同一证据链：

- 实验授权：授权主体、证明位置、时间窗、样本范围、允许动作、禁止动作、第三方边界、停止条件。
- 隔离网络：隔离等级、网络拓扑、路由摘要、DNS/sinkhole、代理、假服务、出口阻断、未知目的地处理。
- 样本登记：原始样本编号、SHA256、来源、接收时间、只读位置、工作副本和派生产物关系。
- 工具链版本：系统镜像、补丁级别、反汇编器、调试器、监控工具、脚本运行时、插件、规则库、符号/缓存哈希。
- 证据目录：original、working、derived、logs、screenshots、pcap、dumps、configs、reports、redacted、destroyed 与索引文件。
- 任务分工：授权负责人、实验负责人、环境操作者、样本保管人、证据复核人、风险审批人、报告签发人、清理执行人。
- 风险审批：动态执行、联网例外、敏感数据留存、第三方材料引用、跨区导出、长期封存都要有审批记录。
- 数据脱敏：报告正文、截图、日志、pcap、dump、附件和移交介质分别说明脱敏、加密、访问控制和不可外发内容。
- 复现实验：复现输入、快照、工具版本、命令/交互摘要、预期结果、实际结果、失败原因和不可复现限制。
- 报告交付：交付对象、格式、附件编号、哈希、脱敏说明、限制条件、未验证项、接收确认。
- 清理销毁：工作副本、临时产物、缓存、导出区、代理日志、快照和归档证据的保留/移交/销毁状态。
- 真实验收：用实际路径、实际哈希、实际截图、实际日志、实际回读记录和接收确认核对，不接受占位符。
- 反例库：记录本次明确拒绝或改写的越界做法，说明替代的安全实验室方案。

## 二轮真实验收门禁

以下任一项缺失，都不得输出“已通过”“可上线使用”或“实验室闭环完成”：

- 实验授权门禁：授权证明可回读，允许动作、禁止动作、第三方边界、数据留存、时间窗和停止条件有明确记录。
- 隔离网络门禁：网络模式、默认路由、DNS/sinkhole、代理、假服务、NTP/固定时钟、出口阻断和未知目的地处理有截图或日志证据。
- 样本登记门禁：每个原始样本有编号、SHA256、来源、接收时间、只读位置、工作副本和派生产物链。
- 工具链版本门禁：OS 镜像、补丁级别、反汇编器、调试器、监控工具、脚本运行时、插件、规则库、符号和离线缓存版本可复查。
- 证据目录门禁：original、working、derived、logs、screenshots、pcap、dumps、configs、reports、redacted、destroyed 均有用途说明和索引。
- 任务分工门禁：授权确认、实验负责、环境操作、样本保管、证据复核、风险审批、报告签发和清理销毁有责任人。
- 风险审批门禁：L2 以上动态观察、联网例外、敏感数据留存、第三方材料引用、跨区导出和长期封存有审批记录。
- 数据脱敏门禁：报告、截图、日志、pcap、dump、附件和移交介质已处理未授权敏感值，并记录加密、访问控制和不可外发内容。
- 复现实验门禁：复现输入、快照、工具版本、交互摘要、预期结果、实际结果、失败原因和不可复现限制完整。
- 报告交付门禁：交付对象、附件编号、哈希、脱敏说明、限制条件、未验证项、接收确认和版本时间线齐全。
- 清理销毁门禁：工作副本、临时产物、缓存、导出区、代理日志、快照和归档证据的保留/移交/销毁状态可回读。
- 反例库门禁：本次拒绝或改写的越界做法已记录，且给出合法授权实验室内的安全替代方案。

## 三轮加固执行法

第一轮：隔离与 custody 加固。

- 回读授权、样本来源、允许动作、禁止动作、第三方边界、时间窗、留存周期和停止条件；任一项缺失先降级。
- 确认原始样本只读、工作副本编号、派生产物链、接收/移动/导出记录和访问责任人，禁止在宿主下载目录或个人云盘暂存。
- 检查宿主、VM、模拟器、共享目录、剪贴板、USB、串口、调试桥、管理口和导出区，确保没有生产凭据和个人账号污染。
- 固定隔离等级，写清为什么 L0/L1 不足、为何允许 L2/L3，以及等级提升对应的审批编号和回滚点。
- 建立污染风险清单：样本污染环境、环境污染证据、工具自动更新污染结果、宿主痕迹污染样本、不同样本互相污染。

第二轮：观测与证据加固。

- 网络证据必须同时覆盖拓扑、默认路由、DNS/sinkhole、代理、假服务、防火墙拒绝日志、未知目的地处理和 pcap 哈希。
- 快照证据必须覆盖洁净基线、工具基线、样本导入前、运行前、证据导出后和清理前；回滚后重新验证网络与工具版本。
- 时间证据必须写清固定时钟、内部 NTP、时区、宿主/客体时间差、日志时间源和报告时间线换算，禁止混用不可解释时间戳。
- 日志采集证据必须写明采集点、起止时间、过滤条件、工具版本、原始文件哈希、保存路径和脱敏状态。
- 工具链证据必须固定 OS 镜像、补丁级别、安装包来源、哈希、插件、规则库、符号缓存、脚本运行时和本地配置差异。
- 逃逸风险必须有宿主隔离、无共享能力、无默认公网、管理口限制、异常停止条件和保全动作；不得为了“观察完整”打开边界。

第三轮：复现、交付与退出加固。

- 端到端验收按“授权材料 -> 样本编号 -> 隔离快照 -> 工具版本 -> 观测日志 -> 证据索引 -> 报告引用 -> 清理记录”逐项回读。
- 复现实验必须写输入编号、快照名称、工具版本、交互摘要、预期结果、实际结果、失败原因、环境限制和不可复现项。
- 失败回滚必须区分实验失败、隔离失败、证据失败和交付失败；记录停止时间、保全证据、回滚快照、残留检查和重新进入条件。
- 报告只能交付防御分析、隔离设计、证据索引、风险说明和修复建议；不得交付可直接复用的投递、控制、逃逸或真实攻击步骤。
- 清理退出必须检查工作副本、临时产物、缓存、导出区、代理日志、快照、共享区、剪贴板历史和归档证据，不用一句“已清理”代替记录。
- 结论必须分为已验证、受控观察、推测、无法验证、授权限制和环境限制；证据链断裂时降级，不补写确定结论。

## 任务分工与风险审批

- 授权负责人：确认授权文件、时间窗、样本范围、允许动作、禁止动作、第三方边界和停止条件。
- 实验负责人：选择隔离等级，批准环境矩阵、网络边界、快照节点、复现方式和交付范围。
- 环境操作者：创建 VM/模拟器/网络/假服务/代理/日志点，只按审批后的变更单操作。
- 样本保管人：登记原始样本和派生产物，维护 custody，控制原始区、工作区、导出区访问。
- 证据复核人：核对哈希、截图、日志、pcap、dump、工具版本、时区、脱敏状态和结论引用。
- 风险审批人：审批 L2 以上动态观察、联网例外、敏感数据留存、第三方材料引用和长期封存。
- 报告签发人：确认报告不含未授权敏感值、攻击部署步骤、真实目标测试记录或越界能力。
- 清理执行人：执行保留、移交、销毁、残留检查，并输出销毁记录和例外留存说明。
- 同一人可兼多角，但授权确认、环境操作、证据复核和报告签发不能全部由同一人闭环。
- 缺少审批时，只能输出缺口和降级方案；不能把高风险动作伪装成常规实验步骤。

## 强制流程

1. 授权与范围确认
   - 记录委托方、联系人、授权证明位置、样本来源、时间窗、允许动作、禁止动作、停止条件、留存周期。
   - 判断是否涉及恶意样本、客户数据、个人信息、生产凭据、第三方代码、出口管制或保密条款。
   - 若授权、样本来源或允许动作不清，先列出必须补齐的信息。

2. 样本登记与保管
   - 为每个原始样本分配编号，记录 SHA256、大小、原始文件名、来源、接收时间、接收人和只读存储位置。
   - 工作副本、解包产物、配置提取物、内存 dump、磁盘镜像、pcap、日志和截图都生成派生编号。
   - 维护 custody：谁、何时、从哪个编号生成哪个产物、用途是什么、是否含敏感数据、当前状态是什么。

3. 威胁模型与边界
   - 列出要防止的事故：样本外联、宿主泄露、凭据污染、证据覆盖、时间线混乱、工具误报、敏感信息入报告。
   - 将事故映射到控制项：网络模式、共享目录、剪贴板、USB、时间同步、代理、DNS、日志导出和管理入口。
   - 每个控制项都要可检查，例如“剪贴板关闭”“共享目录无挂载”“默认路由不存在”“出口防火墙拒绝未知目的地”。
   - 输出隔离等级，说明为什么不能用更低等级，写清等级提升的授权依据。

4. 环境矩阵
   - 固定基础镜像、架构、补丁级别、语言包、时区、用户权限、系统策略和安全产品状态。
   - 固定工具链：反汇编器、调试器、监控工具、解包器、脚本运行时、符号包、SDK、插件、规则库和签名库。
   - 固定离线资源：包管理缓存、符号服务器镜像、文档、证书、样本依赖、规则库、安装包来源和哈希。

5. 网络与出站控制
   - 默认无路由或 host-only；确需网络交互时使用内部 DNS sinkhole、假服务、记录代理和严格出口阻断。
   - 写明 DNS、NTP/时间、证书、HTTP/HTTPS 代理、日志采集点、防火墙规则、允许端口、拒绝策略和未知目的地处理。
   - 时间默认固定或由内部 NTP 提供；DNS 默认只解析到内部 sinkhole；代理默认记录请求并阻断未列入允许清单的目标。
   - 禁止真实 C2、生产系统、个人账号、公共投递平台、第三方无授权服务或公网扫描参与分析。

6. 动态分析边界
   - 动态观察只能运行工作副本，必须有样本导入前和运行前快照，必须先确认隔离等级、日志路径和停止条件。
   - 允许观察进程、文件、注册表/配置、内存、网络意图和错误日志；不允许优化逃逸、持久化、投递、横向移动或真实攻击效果。
   - 出现未知外联、凭据访问、数据破坏、逃逸迹象、越权访问或授权外目标时立即停止、保全证据并回滚。

7. 快照与变更控制
   - 定义快照节点：洁净基线、工具安装后、样本导入前、高风险动作前、证据导出后、清理前。
   - 快照名称包含日期、镜像、工具集、样本编号、网络模式和目的。
   - 回滚后重新校验样本哈希、工具版本和网络边界，避免把旧状态证据混入新实验。

8. 证据目录与留存
   - 建立证据目录：original、working、derived、logs、screenshots、pcap、dumps、configs、reports、redacted、destroyed。
   - 建立证据索引：编号、类型、来源、采集时间、时区、采集工具版本、哈希、脱敏状态、关联结论。
   - 日志、截图、pcap、dump 和配置必须说明采集点；报告中引用证据编号，不直接混贴原始敏感字段。
   - 截图要包含窗口标题、工具版本或时间线参照；日志要保留采集起止时间、时区、过滤条件和原始文件哈希。

9. 敏感数据处理
   - 识别 token、cookie、私钥、账号、个人数据、客户数据、内部域名、设备标识、证书和生产痕迹。
   - 默认报告脱敏；原始敏感附件加密、限权、编号移交；需要吊销、轮换或通知的事项单列给授权方。
   - 留存周期、销毁方式、接收方和访问名单必须来自授权；未约定时按最小留存，只交付脱敏证据和哈希索引。
   - 不使用提取到的真实凭据登录、枚举、访问或验证权限。

10. 验证与交付门禁
   - 用第二工具、第二快照、静态/动态交叉、日志重放或人工复核验证关键环境假设。
   - 将已验证、推测、无法验证、环境限制和授权限制分开写。
   - 复现实验要记录输入编号、快照、工具版本、交互摘要、实际结果、失败原因和不可复现限制。
   - 交付前检查授权、隔离、样本 custody、任务分工、风险审批、工具版本、证据索引、敏感脱敏、复现实验、清理销毁和安全边界。
   - 报告交付要包含接收方、附件编号、哈希、脱敏说明、限制条件、未验证项和接收确认。

11. 清理、移交与销毁
   - 按授权决定保留、移交、销毁或长期封存；每个动作记录编号、哈希、操作者、时间和接收方。
   - 销毁工作副本和临时产物时保留销毁记录；需要保留的原始样本和证据进入只读或加密归档。
   - 清理 VM、快照、缓存、临时目录、代理日志和导出区，确认无样本和敏感数据遗留在非授权位置。

12. 真实验收
   - 从授权材料、样本登记、隔离网络、工具版本、证据目录、风险审批、复现实验、报告交付和清理销毁逐项回读。
   - 每项验收必须有实际路径、编号、哈希、截图、日志、审批记录、交付确认或销毁记录之一支撑。
   - 发现占位符、空目录、未读回 raw 证据、未签发审批、未脱敏附件或未清理临时产物时，不得报“已通过”。

13. 结论降级
   - 授权不完整时，结论降级为“授权缺口清单”，不输出动态执行、联网交互或样本运行方案。
   - 隔离网络未验证时，结论降级为“静态或离线保管建议”，不声称可安全动态观察。
   - 样本登记、工具链版本或证据目录缺失时，结论降级为“不可复现观察”，不得给确定归因或完成验收。
   - 风险审批、脱敏、报告交付或清理销毁缺失时，结论降级为“交付前阻塞项”，不得标记闭环完成。

## 场景执行卡

### 1. 新建授权逆向实验室

- 目标：建立可复现、可回滚、可审计的隔离分析环境。
- 必问：样本类型、平台、授权证明、预期问题、隔离等级、是否可联网、是否含敏感数据、交付格式、保留周期。
- 方案要点：宿主无生产凭据；VM 使用固定镜像；共享目录和剪贴板默认关闭；样本通过导入区进入；证据通过导出区离开。
- 证据点：镜像来源/哈希、工具版本清单、网络拓扑、快照清单、样本登记表、边界检查记录。
- 禁止偏离：不要打开宿主目录直挂、个人云盘同步、真实账号登录或全网出口。

### 2. 恶意或疑似恶意样本保管

- 目标：防止样本泄漏、误执行、误上传和证据污染。
- 必问：样本来源是否合法、是否允许动态观察、是否允许解包、是否允许保留、谁能访问原始样本。
- 方案要点：原始区只读；工作副本带编号；解包产物、dump、解密片段和配置提取物按新产物管理。
- 证据点：哈希、接收记录、访问记录、派生产物链、销毁或移交记录。
- 禁止偏离：不得上传公共扫描服务或第三方平台，除非授权和数据分类明确允许。

### 3. 隔离 VM 与快照策略

- 目标：让每次分析都能回到已知状态，并解释状态差异。
- 必问：是否需要多 OS/多架构、内核调试、模拟外设、持久化日志或受控动态观察。
- 方案要点：洁净基线、工具基线、样本导入前、风险动作前、证据导出后都要有快照；快照不替代证据备份。
- 证据点：快照名称、创建时间、父快照、网络模式、工具集版本、关联样本编号。
- 禁止偏离：不要在同一快照里混跑多个不相关样本后再做归因或环境结论。

### 4. 受控网络、DNS sinkhole 与假服务

- 目标：观察授权样本的网络意图，同时防止真实外联和第三方影响。
- 必问：是否允许任何外联、需要模拟哪些协议、是否需要固定时钟、DNS、代理、证书或 HTTP 响应、日志保留多久。
- 方案要点：默认 host-only 或无路由；DNS 指向内部 sinkhole；假服务只返回安全静态占位响应；出口防火墙拒绝未知目的地。
- 证据点：拓扑图、路由摘要、DNS 规则、代理/假服务日志、pcap 哈希、阻断日志。
- 禁止偏离：不要连接真实 C2、扫描互联网、重放到真实服务或测试公网效果。

### 5. 受控动态分析边界

- 目标：在不扩大风险的前提下观察样本行为。
- 必问：授权是否允许执行样本、允许哪些交互、触发条件是什么、停止条件是什么、是否允许持久化日志。
- 方案要点：只运行工作副本；运行前快照；固定隔离等级；记录进程、文件、网络、日志和屏幕；异常立即停止并回滚。
- 证据点：运行前后快照、命令/交互时间线、进程/文件差异、代理日志、pcap、截图和停止记录。
- 禁止偏离：不要为了“表现真实”放开公网、真实账号、真实 C2、逃逸路径或攻击目标。

### 6. 工具链版本固定与离线缓存

- 目标：避免工具漂移导致同一证据得出不同结论。
- 必问：哪些工具参与结论、插件是否可信、规则库何时更新、符号和依赖从何处取得。
- 方案要点：记录安装包来源和哈希；插件独立编号；符号包、SDK、规则库、文档和包缓存做离线镜像。
- 证据点：工具清单、版本输出、配置哈希、缓存索引、更新记录、已知限制。
- 禁止偏离：不要把自动更新后的结果与旧快照结果混写为同一实验。

### 7. 敏感数据与秘密处理

- 目标：防止分析过程扩大泄露面。
- 必问：样本、日志或截图中是否含凭据、客户数据、个人数据、设备标识、内部域名、证书或密钥，留存周期和接收方是谁。
- 方案要点：最小可见；报告默认脱敏；原始敏感附件加密分发；生产凭据建议轮换或吊销；未授权敏感值不进入报告正文。
- 证据点：敏感字段类型、脱敏规则、附件编号、访问名单、留存期限、销毁/移交状态。
- 禁止偏离：不要使用提取到的真实凭据登录服务或验证访问权限。

### 8. 证据复现与报告交付

- 目标：让第三方能判断结论是否由受控环境支持。
- 必问：交付对象是谁、需要复现到什么程度、哪些证据不能外发、哪些结论有不确定性。
- 方案要点：报告包含授权摘要、环境矩阵、样本 custody、快照、工具版本、网络边界、证据索引和限制条件。
- 证据点：复现摘要、证据编号映射、哈希、时区、日志范围、截图编号、脱敏说明。
- 禁止偏离：不要交付可直接复用的攻击流程、逃逸方法、持久化步骤或真实目标测试记录。

### 9. 清理销毁与安全退出

- 目标：按授权完成留存、移交、销毁和环境复原。
- 必问：哪些证据必须保留、谁接收、保留多久、哪些临时产物必须销毁、是否需要销毁证明，是否允许保留原始样本。
- 方案要点：工作副本和临时产物按编号清理；归档证据只读或加密；VM 快照、缓存、导出区、代理日志和截图区逐项核对。
- 证据点：移交清单、销毁记录、归档哈希、接收确认、残留检查记录、例外留存审批。
- 禁止偏离：不要把“清理”理解为删除审计证据或掩盖越界行为。

## 输出要求

输出应面向可执行的实验室方案或审查结论，至少包含：

1. 授权摘要：委托方、样本范围、允许动作、禁止动作、停止条件、保留周期。
2. 样本 custody：样本编号、哈希、来源、存储分区、工作副本和派生产物关系。
3. 环境矩阵：宿主边界、VM 镜像、OS/补丁、架构、用户权限、时区、工具链、插件、规则库、符号/缓存来源。
4. 隔离设计：隔离等级、网络模式、DNS/sinkhole、假服务、路由/防火墙、共享目录、剪贴板、USB、日志采集点。
5. 快照策略：快照节点、命名规则、回滚要求、证据导出时机。
6. 证据目录：目录结构、编号规则、哈希策略、时间线、截图/日志/pcap/dump 留存规则。
7. 敏感处理：脱敏规则、加密附件、访问名单、吊销/轮换建议和不可外发内容。
8. 复现与限制：复现摘要、环境限制、无法验证项、需要相邻技能补证的事项。
9. 安全退出：清理、保留、移交、销毁、残留检查和交付门禁结果。

## 验证门禁

交付前逐项确认：

- 授权范围、样本来源、允许动作、禁止动作、停止条件和数据留存已记录。
- 每个原始样本有编号、哈希、接收记录、只读位置和工作副本关系。
- VM 网络模式、共享目录、剪贴板、USB、DNS、代理、时间同步和出口策略已检查。
- 隔离等级已明确；若高于 L1，已写明授权依据、日志点、停止条件和回滚点。
- 每个高风险动作前存在可识别快照，且快照命名包含目的和样本编号。
- 工具链、插件、符号、规则库、离线缓存和系统镜像版本可复查。
- 证据索引包含编号、来源、采集时间、时区、工具版本、哈希、脱敏状态和关联结论。
- 日志、截图、pcap、dump、配置和报告附件按目录留存，且能从结论追溯到证据。
- 报告、日志和附件不泄露未授权 token、cookie、私钥、账号、个人数据、客户数据或内部敏感标识。
- 任务分工已记录，授权确认、环境操作、证据复核、风险审批、报告签发和清理销毁有人负责。
- L2 以上动态观察、联网例外、敏感数据留存、第三方材料引用和长期封存有风险审批记录。
- 复现实验有输入编号、快照、工具版本、交互摘要、预期/实际结果、失败原因和不可复现限制。
- 报告交付有接收方、附件编号、哈希、脱敏说明、限制条件、未验证项和接收确认。
- 动态分析没有越过授权动作；未知外联、凭据访问、逃逸迹象和第三方目标都有停止/保全/回滚处理。
- 未提供真实外联、攻击基础设施、持久化、逃逸、规避、实网攻击、凭据使用或恶意样本传播指导。
- 清理、保留、移交和销毁计划与授权约定一致，并有残留检查记录。
- 真实验收不是模板勾选：至少抽查一个样本编号、一个快照、一个工具版本、一条日志/截图证据和一个清理/移交记录。

## 结论降级规则

- 证据不足：写“证据不足”，列缺口和下一步，不补写推测性结论。
- 授权不足：写“授权不足，仅能给出安全准备清单”，不进入运行、联网、复现或交付步骤。
- 隔离不足：写“隔离不足，限定 L0/L1”，只允许静态登记、只读保管和离线准备。
- 版本不足：写“工具链不可复现”，所有工具相关发现只能作为观察，不作为稳定结论。
- 脱敏不足：写“不可交付未脱敏材料”，仅输出敏感类型、处理建议和移交流程。
- 清理不足：写“安全退出未完成”，不得声称实验结束或环境可复用。

## 安全边界

允许：

- 设计授权逆向实验室、隔离 VM、host-only 网络、无路由网络、内部 sinkhole、假服务和证据流程。
- 说明如何记录工具版本、系统镜像、样本哈希、快照、日志、pcap、dump、截图和脱敏规则。
- 提供防泄漏、防污染、防误外联、防证据混淆、防敏感数据外泄的检查清单。
- 建议静态分析、受控动态观察、日志复核、二次工具交叉验证和人工复核，但必须保留隔离等级和停止条件。
- 指出授权不足、隔离不足、证据不足或敏感数据处理不足，并给出安全补救。

拒绝或改写：

- 搭建 C2、攻击演练靶场、红队基础设施、投递链路、钓鱼系统、持久化或横向移动环境。
- 连接真实 C2、放行公网外联、对第三方服务重放请求、扫描互联网或验证攻击效果。
- 免杀、反沙箱、逃逸、绕过检测、绕过监控、清痕或对抗分析人员。
- 使用样本提取的凭据登录、枚举、访问、横向移动或验证真实系统权限。
- 指导无授权样本运行、传播、公开分发、破坏、勒索、数据窃取或实网入侵。

不安全请求要改写为安全替代。例如“让样本连真实 C2”改为“在 host-only 网络中用内部 sinkhole 和假服务记录连接意图并阻断外联”。

## 反例库

- 反例：先运行样本看看会发生什么。正确：先确认授权、登记哈希、建立快照、检查隔离边界，再选择最小观察方式。
- 反例：为了方便打开共享剪贴板和宿主下载目录。正确：关闭共享能力，用受控导入/导出区和哈希记录移动文件。
- 反例：让 VM 直接联网以便样本表现真实。正确：默认无路由；确需网络时使用内部 sinkhole、假服务和严格出口阻断。
- 反例：报告里贴完整 token、cookie 或私钥。正确：脱敏展示，原始敏感值仅在授权附件中加密移交或建议吊销。
- 反例：同一 VM 连续分析多个样本，不回滚也不记录状态。正确：按样本和动作回滚到已知快照。
- 反例：工具自动更新后继续沿用旧结论。正确：新版本、新快照、新证据编号，并说明差异。
- 反例：系统时间、DNS 和代理随宿主默认配置走。正确：固定时钟或内部 NTP，DNS 指向内部 sinkhole，代理记录并阻断未知目标。
- 反例：动态观察时为了完整行为放开出口。正确：先写隔离等级、允许目标、日志点和停止条件，未知目的地默认阻断。
- 反例：公共扫描服务结果就是结论。正确：仅作为外部情报，必须与本地证据和授权边界交叉验证。
- 反例：为证明风险而测试真实目标。正确：在授权实验室内说明触发条件、证据限制和未验证项。
- 反例：把清理理解为删除所有痕迹。正确：按约定保留证据、销毁副本、记录哈希和移交流程。
- 反例：搭一个“实验用 C2”帮助样本跑完整链路。正确：只用内部假服务记录意图，禁止攻击基础设施和真实控制链路。
- 反例：用攻击者视角优化规避沙箱。正确：只评估实验室盲点和检测覆盖，不提供规避实现。
- 反例：授权邮件里只写“帮忙看看”，就开始动态执行。正确：补齐允许动作、时间窗、样本范围、禁止动作和停止条件。
- 反例：联网例外口头同意，报告里写“已批准”。正确：风险审批要落到记录，包含目标、端口、数据类型、日志点和有效期。
- 反例：任务分工只有一个“负责人”。正确：至少区分授权确认、环境操作、样本保管、证据复核、报告签发和清理执行。
- 反例：复现实验只写“可复现”。正确：写出快照、工具版本、输入编号、交互摘要、实际结果和限制条件。
- 反例：报告交付只发正文，不交证据索引。正确：交付报告、附件编号、哈希、脱敏说明、未验证项和接收确认。
- 反例：验收用空目录和占位符路径。正确：回读实际证据目录、样本哈希、截图日志、审批记录和销毁/移交记录。
- 反例：把“授权实验室”写成可对外部署的攻击链。正确：只提供隔离分析、记录、阻断和证据交付方案，不提供真实攻击部署。
- 反例：工具清单只写名称不写版本。正确：记录版本输出、安装包来源、哈希、插件、规则库和离线缓存索引。
- 反例：发现无法复现仍给确定结论。正确：按结论降级规则标记不可复现、环境限制和需要补证的门禁。
- 反例：清理销毁只写“已清理”。正确：逐项列工作副本、临时产物、缓存、导出区、代理日志、快照和归档证据的状态。
- 反例：只说“host-only”，不查默认路由、DNS、代理和防火墙拒绝日志。正确：用拓扑、路由摘要、sinkhole 日志、代理日志和 pcap 哈希证明隔离。
- 反例：快照很多但命名随意，无法知道哪一个对应样本导入前。正确：快照名包含日期、镜像、工具集、样本编号、网络模式和目的。
- 反例：日志没有时区和采集起止时间。正确：固定时钟或内部 NTP，记录时区、时间源、起止时间、过滤条件和原始日志哈希。
- 反例：工具链写“最新版”。正确：固定安装包、插件、规则库、符号缓存、配置差异和哈希，不把自动更新结果混入旧结论。
- 反例：样本跑崩后直接重试。正确：先保全崩溃证据、记录失败原因、回滚快照、检查残留，再决定是否重新进入实验。
- 反例：复现实验只保留屏幕录像。正确：同时保留输入编号、快照、工具版本、日志、截图/pcap/dump 哈希和限制条件。
- 反例：把逃逸风险写成“概率低”。正确：列宿主边界、共享能力、管理口、网络出口、异常停止条件和残留检查证据。
- 反例：把交付报告写成操作手册。正确：交付防御结论、隔离证据、风险说明和修复建议，不交付投递、控制、逃逸或真实攻击步骤。

- 我是否明确隔离等级，并为等级提升写出授权依据、停止条件和回滚点？
- 我是否记录所有会影响结论的 OS、工具、插件、规则库、符号和缓存版本？

## 相邻技能边界

- 逆向工程总控（reverse-engineering，slug: rev）：逆向目标拆解和证据化分析总控；revlab 只负责实验室、隔离和证据环境。
- 恶意样本逆向（malware-reverse-engineering，slug: malrev）：恶意样本行为和家族分析；revlab 提供安全容器、网络边界和 custody。
- 二进制逆向（binary-reverse-engineering，slug: binrev）：二进制结构、符号、函数、控制流分析；revlab 固定工具链和样本状态。
- 移动逆向（mobile-reverse-engineering，slug: mrev）：移动应用逆向；revlab 负责移动样本的隔离设备/模拟器边界和证据导出。
- 固件逆向（firmware-reverse-engineering，slug: fwrev）：固件拆包和设备环境；revlab 负责固件样本保管、离线依赖和仿真隔离边界。
- 文件格式逆向（file-format-reverse-engineering，slug: fmtrev）：文件格式与解析结构；revlab 负责样本编号、解析工具版本和证据目录。
- 汇编与指令集逆向（assembly-reverse-engineering，slug: asmrev）：汇编级理解；revlab 负责调试环境、符号缓存和快照纪律。
- 动态调试逆向（debug-reverse-engineering，slug: debugrev）：调试会话、断点和运行观察；revlab 定义何时允许受控动态观察和如何回滚。
- ABI 与调用约定逆向（abi-reverse-engineering，slug: abirev）：ABI、调用约定和接口复现；revlab 固定 SDK、头文件、符号和依赖缓存。
- IR 逆向（intermediate-representation-reverse-engineering，slug: irrev）：IR/中间表示分析；revlab 记录反编译器、IR 工具和插件版本。
- 壳与加固逆向（packer-reverse-engineering，slug: packrev）：壳、打包和解包产物分析；revlab 管理解包产物 custody，不提供规避或投递能力。
- Windows 逆向（windows-reverse-engineering，slug: winrev）/ Linux 逆向（linux-reverse-engineering，slug: linuxrev）/ macOS 逆向（macos-reverse-engineering，slug: macrev）：平台专用逆向；revlab 提供平台镜像、补丁级别和隔离边界。
- 脚本与字节码逆向（script-bytecode-reverse-engineering，slug: scriptrev）/ Web 逆向（web-reverse-engineering，slug: webrev）/ 游戏逆向（game-reverse-engineering，slug: gamerev）/ 密码学逆向（cryptography-reverse-engineering，slug: cryptrev）/ 差分逆向（differential-reverse-engineering，slug: diffrev）/ 崩溃逆向（crash-reverse-engineering，slug: crashrev）/ 逆向模糊测试（fuzz-reverse-engineering，slug: fuzzrev）/ SDK 供应链逆向（sdk-supply-chain-reverse-engineering，slug: sdkrev）：具体技术域分析；revlab 只负责可复现安全实验室、样本 custody 和证据卫生。
- 代码审计（code-audit，slug: aud）：源码/系统审计；revlab 在审计涉及样本执行、隔离环境或证据留存时提供边界。
- 测试验证（test-engineering，slug: tst）：测试计划与验证；revlab 提供安全门禁，tst 负责常规功能/回归测试组织。
- DevSecOps（devsecops，slug: dso）：交付、安全运营或流程化协作；revlab 输出可交接的实验室设计、证据索引和安全退出要求。
