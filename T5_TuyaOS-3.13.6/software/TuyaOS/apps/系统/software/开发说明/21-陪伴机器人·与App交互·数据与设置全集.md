## 0. 范围与边界（V4.3 对齐）

### 0.1 本期范围
**机器人 ↔ App 的全部交互 + 数据契约 + App/后台设置项。** 不含纯硬件/固件内部实现（见 `09`/`16`）。

### 0.2 V4.3 两条范围修正（重要，覆盖旧口径）
1. **视觉跌倒检测纳入安全闭环**：V4.3 商业计划书明确“AI 视觉跌倒检测已落地”。本篇不展开算法实现，但需要把跌倒事件接入设备事件、App 强提醒、视频复核、社区/人工处置、审计和演练指标。
2. **SOS 与跌倒默认升级策略**：机器人 SOS 键或视觉跌倒事件触发后，全部绑定家属 App 收到强提醒；30 秒内无任一家属响应时，默认升级到社区/人工中台或签约应急流程。是否直接呼 120 需按本地合规、用户授权和合作机构能力单独配置。

### 0.3 三条数据通道（贯穿全篇）
| 通道 | 用途 | 说明 |
|---|---|---|
| **涂鸦云中转** | 音视频 / DP / 设备事件 / OTA / 智能体 | 机器人不直连后端，经涂鸦云（`02`/`09`） |
| **`/mcp`（MCP）** | 机器人 AI 调平台能力 | 老人语音 → 智能体 → MCP → 业务（`08`） |
| **REST + WebSocket** | App ↔ 后端 | App 查询/设置走 REST；事件推送走 socket.io + FCM/APNs |

> 机器人 ↔ App **不点对点直连**（除视频走涂鸦 WebRTC P2P）；其余交互都"**机器人↔涂鸦云↔后端↔App**"中转，后端是唯一事实源。

## 3. 交互场景详解

> 每个场景统一格式：**触发 → 数据流 → App 表现 → 数据落点 → 边界/细节**。

### 3.1 配网与绑定
- 触发：家属在 App 点"添加机器人"。
- 数据流：App 调涂鸦 IoT SDK 扫码配网拿到 `tuyaDeviceId` + 授权码 → `POST /devices/bind`（绑老人 `serviceTargetId` + 家庭 + 租户）。
- App 表现：配网向导（找设备→连 WiFi→绑定老人→完成）。
- 落点：`device`(`tuya_device_id` 唯一)、`device_binding`。
- 细节：一台机器人绑一位老人（主），可多家属共管；解绑 `DELETE /devices/bindings/:id` 需鉴权；换绑要清/迁记忆人格（涉隐私，二次确认）。

### 3.2 设备状态同步
- 触发：设备 DP 上报 / App 进入设备页。
- 数据流：设备→涂鸦云→(Pulsar)→`device.recordDp()` upsert 快照 → WS 推 App / App `GET /devices/:id`。
- App 表现：在线状态、电量、信号、当前勿扰开关、最近活跃时间。
- 落点：`device_dp_snapshot`、`device_online_history`。
- 细节：离线超时由心跳 cron 判定（`lastHeartbeatAt`）；低电量提醒推家属。

### 3.3 SOS 紧急呼叫与视觉跌倒处置 → 见 §6 专章（最重要）

### 3.4 AI 对话同步
- 触发：老人和机器人对话。
- 数据流：语音→智能体→`/mcp`→业务；对话全量留存 `ai_dialog_log`；会话结束 LLM 生成 `summary`。
- App 表现：`/ai-dialogs` 看最近 7 天对话**摘要**（不给家属看逐字，隐私）；危机标记高亮。
- 落点：`ai_dialog_session`(crisisScore/qaStatus)、`ai_dialog_log`(emotion/crisis_words/tool_calls)。
- 细节：家属看摘要而非全文（隐私分级，§5）；危机词命中按规则提醒（不疲劳告警）。

### 3.5 家属远程"投喂" → 详见 [`20` §6](./20-陪伴机器人·功能路线图与待开发清单.md)
- 触发：家属在 App 下发关怀指令（"提醒我妈喝水""替我说生日快乐"）。
- 数据流：App `POST /family/family-message` → 队列 → 在线即时下行播报 / 离线写 `companion_memory(kind=family_message)` 下次开场带出。
- App 表现：投喂入口 + 回执（已转达/老人反应）。
- 细节：仅绑定家属可发；限频+勿扰+内容安全（§6 同款护栏）。

### 3.6 视频探视
- 触发：家属在 App 发起视频。
- 数据流：涂鸦 WebRTC 信令 → 机器人接听（可设免打扰/自动接听）→ P2P 音视频。
- App 表现：拨号/接通/挂断；弱网降码率；Pro 版分钟超量计费。
- 细节：老人侧可一键接听（适老）；隐私——是否允许家属"静默查看"需老人/授权设置（默认需老人应答）。

### 3.7 健康数据回流
- 触发：老人口述体征 / 蓝牙血压计测量 / 服药打卡 / 对话情绪。
- 数据流：MCP `record_health_metric`/`record_medication_taken` 或蓝牙外设→设备→后端 → App 看板。
- App 表现：健康首页/档案/周报；情绪曲线（P1-10）。
- 落点：health/medication 相关表 + `ai_dialog_log.emotion` 聚合。
- 细节：健康数据**必须**回平台+家属看板（平台命脉，见 `19` 双平面）。

### 3.8 用药提醒闭环
- 触发：到达用药计划时间点。
- 数据流：后端 `medication-notification` 定时 → 涂鸦下行 → 机器人播报+屏显 → 老人语音确认 → `record_medication_taken` → 未确认升级 → WS/推送通知家属。
- App 表现：依从率、漏服提醒。
- 细节：只提醒不改方案（医疗红线）；漏服升级阈值可配。

### 3.9 记忆/人格管理
- 触发：家属在 App 查看/编辑老人的人格设置与记忆（按授权）。
- 数据流：App REST → `companion_persona`/`companion_memory`（见 `19`）。
- App 表现：给机器人起名/选性格/看"它记住了什么"/纠错/删除。
- 细节：人格/陪伴记忆默认家属不可见，需老人或代理授权（§5 隐私）。

### 3.10 内容点播与定时 → 详见 [`20` §7](./20-陪伴机器人·功能路线图与待开发清单.md)
- 触发：老人语音点播 / 家属在 App 设定时播放。
- 数据流：MCP `play_content` → 端侧播控；App `POST` 定时任务 → 下行。
- App 表现：内容库、定时播放（如每天下午放越剧）、音量。
- 细节：版权授权源；睡前渐停。

### 3.11 远程设备控制
- 触发：家属在 App 控制机器人。
- 数据流：App `POST /devices/:id/dp` / `self-control` / `ota/upgrade` → 涂鸦下行。
- App 表现：音量、勿扰时段、亮度、重启、表情、OTA 升级、人脸追踪开关。
- 落点：`device_config_log`。
- 细节：指令幂等（idempotencyKey）；危险操作（重启/OTA）二次确认。

### 3.12 通知中心
- 触发：任意事件（SOS/告警/用药漏服/对话危机/低电量/家属投喂回执/视频未接）。
- 数据流：后端事件 → `realtime.gateway`（socket.io + Redis adapter）→ App 横幅 + FCM/APNs（杀后台也收）→ App 通知中心列表。
- App 表现：全局横幅 + 通知中心（已读/未读/分类）。
- 细节：当前 App 仅告警横幅、**无通知中心列表**（待开发）；推送 `/app/device-token` 待补。

## 4. 数据契约

### 4.1 上行：机器人 → 平台
| 数据 | 形态 | 通道 | 落点 |
|---|---|---|---|
| 上下线/电量/信号/勿扰 | DP | 涂鸦云→Pulsar | `device_dp_snapshot` |
| **SOS 触发** | DP `sos=1` | **直推后端 alert（不经 LLM）** | `alert_log` |
| 对话内容 | 文本+情绪+工具调用 | MCP 留存 | `ai_dialog_log` |
| 体征/打卡 | MCP 写工具 | `/mcp` | health/medication |

### 4.2 下行：App/平台 → 机器人
| 指令 | 触发方 | 通道 |
|---|---|---|
| 播报家属留言/投喂 | App | REST→队列→涂鸦下行 |
| 音量/勿扰/亮度/重启/表情 | App | `/devices/:id/dp|self-control` |
| OTA 升级 | App/后台 | `/devices/:id/ota/upgrade` |
| 内容播放/定时 | App/老人 | REST/MCP→端侧播控 |
| 记忆简报/人格 | 智能体开场 | `recall_memory`/`get_persona`（`19`） |

### 4.3 推送事件：平台 → App（WebSocket + 推送）
| eventType | 触发 | App 行为 |
|---|---|---|
| `alert.sos` | SOS 键 | **紧急弹窗 + 30s 倒计时（§6）** |
| `alert.fall` | AI 视觉跌倒检测 | 紧急弹窗 + 视频复核入口 + 社区/人工升级 |
| `alert.medication_missed` | 漏服升级 | 通知 |
| `dialog.crisis` | 对话危机词 | 提醒家属 |
| `device.offline` / `device.low_battery` | 掉线/低电 | 通知 |
| `family_message.acked` | 投喂已转达 | 回执 |
| `video.incoming/missed` | 视频 | 来电/未接 |
> 事件统一经 `realtime.gateway`；离线靠 FCM/APNs 兜底。

### 4.4 看板数据：家属 App 看护盘
在线状态 · 最近对话摘要 · 情绪趋势 · 用药依从率 · 体征趋势 · 近期告警 · 待办（投喂回执/未接视频）。

## 6. SOS 与视觉跌倒处置专章（V4.3 安全闭环，最关键）

> 与"救命链路不经 LLM/不经记忆"一致（`08` §10）：SOS 物理键和视觉跌倒事件均直推后端，**全程不依赖智能体**，由规则引擎驱动。

### 6.1 精确流程（状态机）
```
[老人按 SOS 键 / 视觉算法识别疑似跌倒]
  → 固件中断 report_dp("sos",1) / 设备上报 alert.fall → 涂鸦云直推后端（不经 AI/MCP）
  → alert.service：写 alert_log(severity=critical, eventType=alert.sos|alert.fall)
  → realtime.gateway 推送【所有绑定家属】App：socket.io 横幅 + FCM/APNs（杀后台也收）
  → App 弹紧急弹窗 + 30s 倒计时：
       [立即呼120/联系社区]   [我来处理/已联系]   [误触·取消]   [视频复核]
  → 机器人侧同时语音安抚："您别慌，我已经通知您家人了。"
  ┌─ 30s 内有家属响应 ──────────────────────────────┐
  │  · 选"我来处理"   → 取消自动呼120，记录处理人      │
  │  · 选"立即呼120/联系社区" → 触发升级流程（见 6.2）  │
  │  · 选"误触取消"   → 谨慎关闭（需老人侧确认，见 6.4）│
  └────────────────────────────────────────────────┘
  ┌─ 30s 内【无任一家属响应】──────────────────────┐
  │  → 系统自动触发社区/人工中台升级（见 6.2）+ 升级通知 │
  └────────────────────────────────────────────────┘
  → 全程状态回传 App（已通知/已响应/已呼120/已取消）+ 落 alert_log
```

### 6.2 自动升级实现方式（⚠️ 需你拍板 + 法务确认）
程序"自动拨打 120"在国内有**合规与技术限制**（120 是急救中心）。V4.3 默认应先做“家属强提醒 + 社区/人工中台升级”，直接呼 120 仅作为明确授权后的可选策略：
| 方案 | 说明 | 风险 |
|---|---|---|
| A. 平台代呼外呼 | 用语音外呼服务自动拨 120 并 TTS 播报老人姓名/地址/症状 | 误报打扰急救资源；需老人地址(`home_address`) |
| B. 强提醒家属 + 一键呼 | 不自动拨 120，而是把全部家属升级为"强弹窗+响铃+电话外呼家属"，家属一键呼120 | 家属全部失联时兜底弱 |
| C. 转社区/管家中台 | 自动通知签约社区/健康管家人工介入再判断是否 120 | 依赖机构网络（你有合作机构） |
> 建议：**B + C 组合**（家属强提醒兜底 + 社区/管家中台），把"自动呼120"做成"自动升级到人工应急中台"，更稳更合规；纯 A 谨慎用。

### 6.3 关键细节
- **多家属并发去重**：谁先响应谁接管，置 `alert_log.handledBy`，避免多人重复呼120。
- **离线兜底**：FCM/APNs 确保杀后台家属也收；全部离线→走 6.2 自动升级。
- **无绑定家属**：直接走 6.2 应急中台/外呼兜底。
- **地理位置**：呼援需 `service_target.home_address`（加密列），设置里必须先填全。
- **审计**：全链路落 `alert_log`（触发→通知→响应人→是否呼120→关闭），severity=high 进审查。

### 6.4 误触处理
- 机器人语音确认："是不是不小心按到啦？没事就跟我说一声。"老人明确说"没事/按错了"→可由家属或老人**双确认**后降级关闭。
- **安全优先**：宁可误报也不漏报；老人无应答时**不**自动降级。

### 6.5 SOS 设置项
| 设置 | 默认 | 谁可改 |
|---|---|---|
| 自动呼援阈值 | 30s | 家属/后台 |
| 通知范围 | 全部绑定家属 | 家属 |
| 自动呼援方式 | B+C（建议） | 后台/家属 |
| 老人地址 | 必填 | 家属 |
| 勿扰豁免 | SOS 永不勿扰 | 固定 |
