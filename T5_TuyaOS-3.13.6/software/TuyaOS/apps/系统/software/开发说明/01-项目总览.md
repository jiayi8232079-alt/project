## 1. 业务定位

**陪了个伴** 是一套面向**居家养老 / 慢病老人 / 陪诊陪护**场景的综合服务平台，把四件事合到一个后端里：

1. **医疗陪诊调度**：用户下单（陪诊 / 体检 / 住院 / 咨询）→ 平台派单 / 护工抢单 → 服务时间线 → 服务报告单 → 评价结算。
2. **老人健康管理**：服务对象（老人）档案、健康问诊、用药计划与打卡、体征记录、健康周报、处方风险。
3. **AI 陪护机器人**：T5-E1 桌面机器人 + AI 视觉跌倒检测，提供语音陪聊、声纹成员判断、用药提醒、跌倒 / SOS 告警、家属视频通话、家庭任务和社区消息播报；AI 通过 **MCP 网关**调用平台业务能力。
4. **分层多租户 + 三门户**：平台 / 政府（民政）/ 社区机构 / 企业 B 端 多级租户，按行政层级聚合数据，三类门户看不同视图。

一句话：**「给老人配个会聊天、会提醒吃药、会喊救命的机器人；给家属一个随时能看的 App / 小程序；给机构和政府一个能管能看的后台。」**

## 2. 系统组成（四端 + 硬件 + 后端）

| 组成 | 目录 | 技术 | 主要使用者 | 状态 |
|---|---|---|---|---|
| 微信小程序 | `UniApp/` | 微信小程序原生 + TypeScript + Skyline | 用户 / 老人 / 家属 / 护工 / 机构 | ✅ 功能最全（≈79 页 / 22 分包） |
| Flutter App | `mobile/` | Flutter 3.10 + go_router + Provider + Dio | C 端（老人 / 家属 / 下单用户） | 🟡 C 端核心闭环已通，设备/支付待接 |
| 管理后台 | `admin/` | Vue 3 + Element Plus + Vite + Pinia | 平台运营 / 财务 / 客服 / 机构 / 企业 | ✅ 视图丰富（含三门户大屏） |
| 陪护机器人 | `T5 E1 模组/`（资料）/ `firmware-companion-t5/`（规划） | 涂鸦 TuyaOS + Wukong AI 3.0（C） | 老人侧 | ❌ 固件未开发，资料齐 |
| 后端服务 | `backend/` | NestJS 11 + TypeORM + MySQL 8 + Redis | 上述全部客户端共用 | ✅ 主力，38 模块 |

> 设计原则：**一套后端、四个前端**。小程序与后台已成熟，App 在补 C 端闭环，机器人靠涂鸦云中转、后端 `device` + `ai-gateway` 已就绪（mock）等接 SDK。

## 3. 技术栈总览

| 层 | 技术 | 版本 / 说明 |
|---|---|---|
| 后端框架 | NestJS | 11（TypeScript 5.7，ESM） |
| ORM / DB | TypeORM 0.3 + MySQL 8.0 | 时区锁定 `+08:00`；可选读写分离 |

| 消息队列 | BullMQ 5（`@nestjs/bullmq`） | 削峰、异步事件 |

| 鉴权 | JWT + Passport（passport-jwt） | 载荷含 `tenantId` |
| 限流 | `@nestjs/throttler` + 自研 Redis 存储 | 默认 600/min/IP，跨实例共享 |
| 定时任务 | `@nestjs/schedule`（@Cron） | 漏服扫描 / 逾期跟进 / 掉线检测等 |
| 对象存储 | 腾讯云 COS（`cos-nodejs-sdk-v5`） | PDF / 录音 / 图片 |
| 短信 | 腾讯云 SMS | 验证码 / 告警外呼 |
| AI | OpenAI 兼容（DeepSeek / 豆包 / Ollama 本地） | 问诊 / 分诊 / 对话；可配置 |
| 安全 | helmet、字段级加密、svg-captcha | 见 `02 架构` 横切层 |
| 管理后台 | Vue 3.5 + Element Plus 2.13 + ECharts 6 + echarts-gl | Vite 5 + Pinia 3 + vue-router 4 |
| 小程序 | 微信原生 + TS + Skyline | 自定义 tabBar + 22 分包 |
| App | Flutter（Dart 3.10）+ go_router 17 + Provider 6 + Dio 5 | secure_storage、socket_io_client、sign_in_with_apple |
| 硬件 | 涂鸦 T5-E1 模组 + Wukong AI 3.0 | 屏幕 + 双麦 + 摄像头 + 云台 |

## 5. 关键角色（谁在用）

| 角色 | 主要入口 | 能做什么 |
|---|---|---|
| **用户 / 下单人** | 小程序 / App | 下单陪诊、查订单、加家庭、看健康、买会员 |
| **老人 / 服务对象** | 机器人 / 老人端极简页 | 语音陪聊、用药提醒、SOS、被照护 |
| **家属 / 监护人** | 小程序 / App（看护盘） | 看老人状态、收告警、看 AI 对话摘要、远程关怀 |
| **护工 / 陪诊员** | 小程序 workbench 分包 | 抢单 / 接单、排班、签到、服务时间线、费用、钱包 |
| **机构管理员（社区/养老院）** | 管理后台（社区门户） | 管本机构居民设备、告警值班、上门工单 |
| **企业 B 端采购方** | 管理后台（企业门户） | 数据看板、SLA 报表、合同续约、对账单 |
| **政府 / 民政** | 管理后台（政府门户） | 按行政层级看辖区聚合数据大屏 |
| **平台运营 / 财务 / 客服 / 超管** | 管理后台（平台门户） | 全量订单 / 客户 / 护工 / 财务 / 配置 / 审计 / 租户 / 计费 / AI 质检 |

## 6. 术语表（高频缩写）

| 术语 | 含义 |
|---|---|
| **服务对象 / target** | 被照护的老人（`service_target`），区别于「下单用户 user」 |
| **陪诊 / escort** | 陪同就医服务 |
| **DP** | 涂鸦设备的「数据点」（Data Point），设备状态/指令的最小单位 |
| **MCP** | Model Context Protocol，AI 智能体调用平台工具的协议（见 `08`） |
| **租户 / tenant** | 多租户隔离单元，可分层（平台→政府→社区→机构） |
| **三门户** | 政府 / 社区 / 企业 三类租户门户（+ 平台总后台） |
| **TenantAwareEntity** | 带 `tenant_id` 的实体基类，实现行级多租户隔离 |
| **告警双链路** | 跌倒/SOS 走规则引擎（不经 LLM）；闲聊/查询走 AI/MCP（见 `08`/`09`） |
| **Wukong AI** | 涂鸦的端侧语音 AI 固件框架（机器人侧） |
| **COS** | 腾讯云对象存储 |
