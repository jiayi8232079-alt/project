## 2. 各端覆盖度小结

- **后端**：38 模块 / 66 实体，业务最完整；债务在「老 service 租户过滤、order god class、设备真实接入、真实支付」。

- **机器人**：后端 device + ai-gateway 就绪（mock），固件未开发，硬件资料齐全；V4.3 新增的声纹成员、长期家庭记忆、社区内容播报、视觉跌倒处置闭环仍需落地。

## 3. 关键缺口清单（按优先级）

### P0（上线必备）
- 当前工作树大量源码处于 Git 删除状态，先确认是迁移预期还是误删；否则无法进行真实运行验证。
- 老业务 service 渐进加租户过滤（防跨租户泄漏）。
- 设备：指令幂等、心跳掉线 cron、跌倒去抖 30s。
- App 推送（FCM/APNs）+ 后端 `/app/device-token`。
- SOS 与视觉跌倒事件：家属强提醒、30s 响应、社区/人工升级、视频复核、审计与演练。
- AI 用量套餐余额检查（防刷额度）。

### P1（硬件打通 / 放量）
- 涂鸦 OpenAPI + Pulsar 真实接入（替换 device mock）。
- App 涂鸦 IoT SDK 原生桥接（配网/视频/OTA）。
- 固件 `firmware-companion-t5`（表情/动作/SOS 安全链/TF 卡降级）。
- 声纹成员链路：录入、识别置信度、误识别纠正、成员权限路由和访客模式。
- 长期家庭记忆与任务编排：`companion_memory`、`companion_persona`、家庭留言、指定成员提醒、任务回执。
- 社区内容触达：后台发布/审核/撤回、分组下发、机器人播报、App 同步、触达回执。
- 生活服务与合作医院协同：服务商履约、医院合作配置、转诊/复诊/随访流程与合规授权。
- order.service 拆分、event_logs 分区归档、Docker+K8s、Prometheus 监控。
- billing 接真实支付（微信/Apple 内购）。

### P2（规模化，10 万+ 触发）
- 微服务化（device/ai-gateway/billing）、PostgreSQL、分库分表、跨地域容灾。

## 4. 量产路线图（摘要）

| 阶段 | 目标 | 大致内容 |
|---|---|---|
| 阶段 1（~2 周） | 稳定服务千~1 万用户 | Redis/队列/读写分离(已落地)+ 租户过滤 + 真登录 + 健康检查 |
| 阶段 2（~2-3 周） | 真设备可用 | 涂鸦 OpenAPI/Pulsar + App SDK 桥接 + 固件 + 推送 |
| 阶段 3（~3 周） | 可放量 | 容器化 + 可观测 + 分区归档 + order 拆分 + 灰度 |
| 阶段 4（10 万+触发） | 规模化 | 微服务 + Pulsar 生产化 + PostgreSQL + 分库分表 + 双活 |

**上线最小集** = 阶段 1 全部 + 阶段 2 的设备与推送。固件与容器化可在灰度运营期并行。
详见 [`02-系统架构.md`](./02-系统架构.md) §6/§7 与 [`11-部署与运维.md`](./11-部署与运维.md) §7。
