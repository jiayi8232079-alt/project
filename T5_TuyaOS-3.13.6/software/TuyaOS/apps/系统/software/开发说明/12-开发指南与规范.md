## 1. 本地起各端

| 端 | 命令 | 访问 |
|---|---|---|
| 后端 | `cd backend && cp .env.example .env && npm i && NODE_ENV=development npm run start:dev` | `http://localhost:3000`，Swagger `/api-docs` |
| 后台 | `cd admin && npm i && npm run dev` | `http://localhost:5173`（接本地后端） |
| 后台(看线上) | `cd admin && npm run dev:online-preview` | 接 `api.qiaoguo.vip`（只读为宜） |
| 小程序 | 微信开发者工具打开 `UniApp/` | 改 `config.ts` 切基址 |
| App | `cd mobile && flutter pub get && flutter run` | `--dart-define=API_BASE_URL=...` 覆盖基址 |

后端开发库靠 `synchronize=true` + 启动 bootstrap 自动建表 / seed，无需手动跑 SQL。

## 2. 编码约定

### 2.1 后端（NestJS）
- 新表继承 `TenantAwareEntity`（自带 `tenant_id`）；命名小写下划线；时间字段交给 BaseEntity。
- 新接口默认 `@UseGuards(JwtAuthGuard, TenantGuard)`；公开接口用 `@SkipTenant()` 并谨慎评审。
- 查询统一 `applyTenantFilter`/`withTenantWhere`（层级 `applyTenantScope`），**不要裸 `repo.find()`**。
- 写操作自动审计（无需手写）；敏感字段用列加密（见 `backend/docs/column-encryption.md`）。
- DTO 用 `class-validator`；对外响应统一包络；错误用合适 HTTP code。
- 复用横切设施（Redis/队列/实时/上下文），不要另起炉灶。

### 2.2 后台（Vue3）
- 新页面：`api/` 加接口 → `views/` 写页面 → `router/index.ts` 注册路由 + 菜单 meta → 需要时 `stores/`。
- 自动导入产物 `auto-imports.d.ts` / `components.d.ts` 勿手改。
- 大屏用 ECharts/echarts-gl + autofit；导出用 xlsx/file-saver。

### 2.3 小程序
- 新页面注册进 `app.json`（主包或合适分包）；重管理放分包，注意预加载规则。
- 基址走 `config.ts`；鉴权 Bearer JWT。

### 2.4 App（Flutter）
- 新功能放 `features/<name>/`，数据访问写 `data/repositories/` 并在 `main.dart` 注入 Provider。
- 路由加在 `src/app.dart` 的 GoRouter；遵守适老化（字号/按钮/对比度）。

## 3. 新增一个后端模块（标准步骤）

```
1) entities/xxx.entity.ts        继承 TenantAwareEntity，定义表结构
2) modules/xxx/dto/*.dto.ts      class-validator 校验
3) modules/xxx/xxx.service.ts    业务（查询用 applyTenantFilter）
4) modules/xxx/xxx.controller.ts @Controller('xxx') + Guards + Swagger 注解
5) modules/xxx/xxx.module.ts     TypeOrmModule.forFeature([Xxx]) + providers/exports
6) app.module.ts                 imports 注册 XxxModule
7) deployment/migration_xxx.sql  生产迁移（开发库靠 synchronize）
8) 测试：跨租户访问应被拒（A 租户查不到 B）
```

## 4. 联调矩阵（mock → 真实）

| 联调点 | 上游 | 下游 | mock 做法 | 切真做法 |
|---|---|---|---|---|
| App 显示设备 | 后端 device | App DeviceRepository | MockDeviceRepository | TuyaIot 实现 |
| 控制设备 | App | device→涂鸦云→固件 | 空函数/后端 mock | 后端 `/devices/:id/dp` 或涂鸦 SDK |
| 设备上报→端 | 固件→涂鸦→后端→WS | 各端实时 | admin「模拟事件/上下线」 | Pulsar 真实订阅 |
| 智能体调后端 | 涂鸦智能体 | ai-gateway | MCP Inspector 本地 | 智能体平台调试 |
| 跌倒告警 | 雷达→涂鸦→alert | 家属推送 | admin「模拟跌倒」 | Pulsar 真实订阅 |
| 视频通话 | App↔设备 P2P | WebRTC | UI 跳通 | 涂鸦 WebRTC SDK |

**原则**：先 mock 跑通业务闭环，硬件/SDK 不阻塞前后端开发。

## 5. 验收要点（节选）

- 后端：`npm run build` / `tsc --noEmit` / `eslint` 零错误；跨租户隔离单测通过。
- AI：端到端首响<2.5s；写操作 100% 二次确认；红队（危机词/越权/幻觉）通过。
- 跌倒：5s 内到家属；一键视频可达可取消。
- 合规：对话全量留存可检索；脱敏字段确认；PIPL 导出/删除可用。
完整验收要点见 [`17-产品需求精要（机器人与多租户三门户）.md`](./17-产品需求精要（机器人与多租户三门户）.md)。

## 6. Git 与协作

- 仓库根即 Git 仓库；提交信息按现有风格（中文简述「类型：内容」）。
- 大改动同步回填本文件夹对应文档与顶层活文档（ARCHITECTURE/OPS/ROADMAP）。
- 文档为活文档：每次较大开发后更新「最近整理日期」。

## 7. 给接手 AI 的提示

1. 先读 `README` + `01` + `02` + `13` 建立全局观。
2. 改后端前务必看 `03`（模块/路由）+ `04`（实体）+ `10`（多租户隔离铁律）。
3. 涉及机器人/AI 看 `08`/`09`，注意**告警双链路**（救命不经 LLM）。
4. 任何「查询」默认要带租户过滤；任何「写操作」默认要审计 + 必要的二次确认。
