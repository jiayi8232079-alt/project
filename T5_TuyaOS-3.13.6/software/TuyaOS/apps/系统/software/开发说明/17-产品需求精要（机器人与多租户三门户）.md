## 一、AI 陪护机器人 PRD 精要

### 1. 目标与边界
- 把平台的导诊/提醒/随访/家属同步能力，转化为老人可**自然对话**的陪伴体验；机器人是**家庭入口**而非平台本身。
- 安全双链路：**保命链路**（AI 视觉跌倒 / SOS 键 / 长时间无活动 → 后端 `alert` 直连，不经 LLM）；**陪聊/查询链路**（语音 → 智能体 → MCP → 业务）。

### 2. 角色与权限
老人（服务对象）、家属/监护人（可代理授权）、护工/陪诊员、机构管理员、平台运营。代理授权需留痕（PIPL）。

### 3. 硬件 / 固件 / 云平台需求
- 硬件：T5-E1 模组（详见 `16`）+ 摄像头视觉算法；毫米波、门磁、烟雾等作为后续可选安全外设。
- 固件：Wukong AI 3.0；`cmd_cb` 自控指令（表情/动作/人脸追踪）；SOS 安全链直推后端；TF 卡断网降级语音。
- 云平台：涂鸦云中转（ASR/TTS/智能体/WebRTC/OTA/Pulsar）。

### 4. 17 个功能闭环（端到端，格式：触发→流程→模块→计费→兜底）

| # | 闭环 | 要点 |
|---|---|---|
| 1 | 设备开通 | 下单/发放→扫码激活(PID/UUID)→绑定老人+家庭+租户→选订阅 |

### 5. 商业功能全景（收入线 → 模块）
硬件售卖/租赁/押金、设备订阅 SaaS（基础/Pro/家庭版）、AI 用量（次/视频分钟/Token + 用量包）、上门服务、C 端会员、To-B 机构（按床位/人数年费）、To-B 渠道（分销佣金/区域代理）、增值（报告/专家/保险）、运营（券/活动/积分）。
需建能力：①计费支付 ②分账结算 ③营销增长 ④合同资质 ⑤续费留存；To-B 平台化（机构自助开通/白标/配额；渠道 CRM/佣金/提现）。

### 6. 智能体（Agent）配置规范（关键）
- 模型：中文/方言强、长记忆、**支持 MCP** 的大模型（首选 DeepSeek 国内数据中心）；可接受 1-2s 延迟，重稳定准确。
- 人设：「陪诊助手」，像家人的陪诊小管家；温暖、慢、短句、称「您」、多关怀；避免术语/催促/责备。
- 记忆：短期 20-30 轮；长期**标签化结构化**（称呼/关系/城市/慢病标签/用药时点/偏好），不存病历/证件号；写入需复述确认。
- 安全三闭环：① 危急不做生死决策（只安抚+反复建议 120/家人+`notify_family`；自动升级由后端规则引擎）；② 身份越权靠鉴权不靠 Prompt（以 deviceId 绑定的 userId 为查询主键，只查本设备数据）；③ MCP 不可用显式降级「纯陪聊」（不装成功）。
- 写操作（下单/通知家属）强制口头二次确认；澄清式追问；幻觉控制（RAG 优先，不确定就保守）；危急词库后台可热更新；红队评测集达标方可上线。
- 平台限制（2026-06）：涂鸦设备端**仅支持绑定 1 个智能体**，多角色切换为 v2，用单智能体 Prompt 变量实现；首版只上「陪诊助手」。

### 7. 非功能与验收（节选）
- 端到端首响 <2.5s；MCP 工具成功率 ≥99%；跌倒 5s 内到家属；写操作 100% 二次确认；红队通过；对话全量留存可检索；PIPL 导出/删除可用。

## 二、分层多租户与三门户 PRD 精要

### 1. 背景与目标
解决「上级（政府/机构总部/渠道总部）看下级聚合数据」+「三类 B 端门户联动」+「硬件数据沿租户层级全链路同步」。

### 2. 业务模型
租户分层树（平台→政府→社区机构→站点；或 渠道总→二级代理）。每条数据归属最底层 tenant，向上**预计算聚合**。

### 3. 三门户功能矩阵（数据范围按层级）

**平台总后台（运营）**：全平台总览、租户管理、平台大盘（中国地图）、内容管理（智能体/危机词/知识库）、客户成功、财务对账、系统设置、监控运维、对话质检、Open API。范围=跨所有租户。

**社区端门户（按层级显示）**：
- 政府监管员：辖区监管大盘 / 机构排行 / 跌倒 SOS 监控 / 应急指挥(跨机构派单) / 监管报告 / 抽查。范围=辖区所有下属。
- 机构院长：院内大盘 / 站点对比 / 居民档案 / 护工管理 / 财务结算 / 设备运维 / 告警值班。范围=本院+下属站点。
- 站点管理员：站点首页 / 居民管理 / 设备控制(DP/OTA/重启) / 实时告警 / 排班 / 服务报告 / 居民签到。范围=本站。

**企业 B 端门户（渠道）**：
- 渠道总裁：全国业绩大盘 / 二级代理排行 / 区域分布图 / 佣金管理 / 合同管理 / 拓客 CRM。范围=全部下属代理。
- 二级代理：业绩看板 / 客户档案 / 客户业绩 / 佣金账单 / 拓客 CRM / 培训资料。范围=本代理。

### 4. 数据汇总机制（向上聚合）
实时 JOIN 所有下属会打挂 DB → **预计算 stat 表 + cron 异步聚合**：
- `stat_daily`（按日运营指标）、`stat_hourly`（小时级，如在线率）、`stat_realtime`（5min 刷新最新快照）。
- 查询时按 `tenant.path` 展开子树 tenantId 集合后聚合（对应代码 `resolveScopeTenantIds` / `applyTenantScope`，见 `10`）。

### 5. 硬件设备数据全链路同步（重点）
设备事件（在线/DP/跌倒/对话）按设备绑定的 tenant 落库，并沿租户 path 链向上可见；机构/政府门户按层级看到本级及下属设备数据；配置下发沿 path 链生效（设备生效配置自动沿 path 查询继承）。

### 6. 权限矩阵 / 数据模型 / API / UI
- 权限：基于 `tenant_role` + `tenant_permission`，按门户角色细分（见 `10` RBAC）。
- 数据模型：tenant 层级字段（path/depth/scopeType/regionCode/orgChain）+ stat 三表（见 `04`）。
- API：`/tenants/tree|descendants|ancestors|breadcrumbs|move`、`/dashboard/*`（门户大盘）。
- UI：四门户大屏（平台/政府/社区/企业），中国地图下钻（见 `05`）。

### 7. 实施路线与验收
分批落地（层级树→stat 聚合→四门户大盘→权限细分）。验收：跨租户零泄漏、上级聚合准确、设备数据沿链路同步、大盘性能达标。
