> 上层导航见 [`README.md`](./README.md)。本篇回答：**怎么部署、怎么迁移、配什么环境变量、监控告警阈值、出事怎么演练**。

## 1. 当前部署形态

腾讯云 CVM 单机 + 宝塔面板：Nginx(SSL) → PM2 cluster(Node×N) → MySQL 8 + Redis；对象存储用腾讯云 COS。
线上 API 域名：`https://api.qiaoguo.vip`。

各端构建产物：
- 后端：`npm run build` → `dist/`，PM2 跑 `dist/main`。
- 后台：`npm run build`（vue-tsc + vite）→ `admin/dist/`，Nginx 静态托管。
- 小程序：微信开发者工具上传发布。
- App：`flutter build apk/ipa`。

## 2. 生产部署 / 升级 SOP

```bash
# 1. 备份生产库
mysqldump -u root -p qiaoguo_health > backup_$(date +%Y%m%d).sql

# 2. 按时间顺序执行迁移 SQL（首次/有新迁移时）
mysql -u root -p qiaoguo_health < deployment/migration_tenant_v1_20260603.sql
mysql -u root -p qiaoguo_health < deployment/migration_tenant_hierarchy_v1_20260603.sql
mysql -u root -p qiaoguo_health < deployment/migration_device_aidialog_v1_20260603.sql
mysql -u root -p qiaoguo_health < deployment/migration_stat_v1_20260617.sql
mysql -u root -p qiaoguo_health < deployment/migration_tenant_config_v1_20260617.sql
mysql -u root -p qiaoguo_health < deployment/migration_ai_config_v1_20260617.sql

# 3. 拉代码 + 构建 + 平滑重启
cd backend && git pull && npm install && npm run build
pm2 reload ecosystem.config.js
```

**铁律**：生产 `NODE_ENV=production`，确保 `DB_SYNCHRONIZE` 未开（否则 TypeORM 可能自动改表）。开发库才靠 `synchronize` + 启动 bootstrap 兜底。

### 2.1 全新环境
导入干净库 `deployment/qiaoguo_health_clean_20260308.sql` + 索引迁移 + 上述各迁移，再启动。

### 2.2 回滚
PM2 切回上版本；DB 回滚执行各 `migration_*.sql` 末尾的 ROLLBACK 段（drop 列/表）。

## 3. 环境变量索引（后端）

| 类别 | 变量 |
|---|---|
| 运行 | `NODE_ENV` `PORT` `DB_SYNCHRONIZE` |
| MySQL | `DB_HOST/PORT/USERNAME/PASSWORD/DATABASE`；读写分离 `DB_SLAVE1_HOST/PORT/USERNAME/PASSWORD` |
| Redis | `REDIS_HOST/PORT/PASSWORD` |
| 鉴权 | `JWT_SECRET` `JWT_EXPIRES_IN` |
| 微信 | `WECHAT_APPID` `WECHAT_SECRET` |
| COS | `COS_SECRET_ID/KEY/BUCKET/REGION` |
| 短信 | `TENCENT_SMS_*` |
| AI 模型 | `AI_*` / DeepSeek / 豆包 / Ollama（见 `backend/docs/local-ai-model.md`） |
| MCP 网关 | `AI_GATEWAY_HMAC_SECRET` `AI_GATEWAY_TIMEOUT_MS` `AI_GATEWAY_CIRCUIT_*` `TUYA_SIGNATURE_KEY` |

以 `backend/.env.example` / `.env.local.example` 为准。

## 6. 故障演练（每月一次）

MySQL 主库宕机 → slave 接管；Redis 宕机 → 降级内存缓存；网络分区 → socket.io 多实例互通；OOM → 自动重启切流；涂鸦云宕机 → device 不阻塞业务；大模型欠费 → fallback 备用模型；DDoS → WAF+限流。

---

P0（已基本落地）：Redis 真用 / socket.io Redis Adapter / bullmq 队列 / 读写分离。

P2：跨地域容灾、PostgreSQL、微服务化、分库分表。
