## 1. 多租户模型

### 1.1 隔离方式
**行级隔离（共享库共享表）**：每张业务表带 `tenant_id`，查询自动加 `WHERE tenant_id = ?`。

- 实体基类 `TenantAwareEntity`（`tenant_id INT NOT NULL DEFAULT 1` + 索引）。
- 写入：`TenantSubscriber.beforeInsert` 从 `RequestContext`(ALS) 自动注入。
- 读取：`applyTenantFilter` / `withTenantWhere`；层级聚合用 `applyTenantScope` / `resolveScopeTenantIds`。
- 守卫：`@UseGuards(TenantGuard)`；跳过：`@SkipTenant()` 或 admin 超管跨租户。
- JWT 载荷含 `tenantId`；admin 类型 `tenantId=null`（可跨租户）。

### 1.2 默认租户与兜底
启动时（`TenantModule.onApplicationBootstrap`）自动建默认平台租户（id=1）+ 内置角色 + 权限点，并 `ensureTenantColumns()` 给历史表补列、为旧数据兜底 `tenant_id=1`。

## 2. 分层租户树（Wave2 Phase1）

`tenant` 增加层级字段：`path` / `depth` / `scopeType` / `regionCode` / `orgChain`。

示例层级（启动 seed，幂等）：
```
平台
└─ 浙江民政（政府）
   └─ 丽水民政（政府）
      └─ 阳光养老院（机构）
         └─ 莲都分院（机构）
```

层级服务 `TenantHierarchyService`：子孙 / 祖先 / 树 / 面包屑 / 移动 / 权限校验。
API（`/tenants`）：`GET /tenants/tree`、`/:id/descendants|ancestors|children|breadcrumbs`、`POST /:id/move`。
后台用 `components/tenant/TenantTreeSelect.vue` 选父租户与层级类型。

**数据范围**：上级可聚合查看其所有子孙租户数据（`resolveScopeTenantIds` 展开整棵子树后 `IN (...)`）。

## 3. RBAC 权限

| 实体 | 作用 |
|---|---|
| `tenant_role` | 角色（含平台预置：超管/运营/财务/客服/机构管理员等） |
| `tenant_permission` | 权限点字典 |
| `tenant_user` | 用户在某租户下的角色绑定 |
| `tenant_role_permissions`（关系表） | 角色↔权限点 |

API：`GET /tenants/roles`、`/tenants/permissions`、`/tenants/:id/members`（加/移除成员）。
防呆：默认租户不可停用；不能移除最后一个 owner。

## 4. 三门户（+ 平台总后台）

同一 Vue 工程，按 `tenant.scopeType` + `role` 动态渲染（不部署三套）。

| 门户 | 租户类型 | 典型视图 | 大屏 |
|---|---|---|---|
| 平台总后台 | platform | 全量业务 + 租户/计费/AI 质检 | `dashboard/portal/platform.vue` |
| 政府门户 | government | 辖区聚合（按行政层级下钻） | `government.vue` + `ChinaMap` |
| 社区机构门户 | community | 居民设备、告警值班、上门工单 | `community.vue` |
| 企业 B 端门户 | enterprise | 数据看板、SLA、合同、对账 | `enterprise.vue` |

- 门户判定：`admin/src/utils/portal.ts`；菜单：`layouts/Sidebar.vue`。
- 大屏数据：后端 `stat` 模块（`stat_daily/hourly/realtime` 预计算）→ `/dashboard/*` → `api/portal-dashboard.ts`。
- 后台页面清单见 [`05-管理后台说明.md`](./05-管理后台说明.md)。

## 5. 计费 / 订阅 / 分账（`billing`）

实体（5）：`subscription_plan`(套餐) · `subscription`(订阅) · `usage_record`(用量) · `revenue_share_rule`(分账) · `invoice`(发票)。

API（`/billing`）：
```
GET  /billing/plans                          套餐列表
GET/POST /billing/subscriptions              我的订阅 / 创建
GET  /billing/subscriptions/:id              详情
POST /billing/subscriptions/:id/renew|cancel 续费 / 取消
GET  /billing/usage                          本月用量
POST /billing/usage/records                  记录用量（admin）
GET  /billing/invoices                       我的发票
POST /billing/invoices                       申请开票
GET  /billing/invoices/admin/all             全部发票（admin/finance）
PATCH /billing/invoices/:id/issue|reject     开票 / 驳回
```

后台视图：`billing/{subscriptions,usage,revenue-share,invoices}.vue`。

### 5.1 用量计量与 AI 余额
`usage_record` 记录 AI 用量 / 通话时长。AI/MCP 工具调用前应查余额（`UsageMeterService.sumUserMetric`），超额返回 `E_RATE_LIMIT` 或降级纯陪聊（见 `08` + `OPS_RUNBOOK §P0-7`）。

### 5.2 B 端分账
`revenue_share_rule` 定义机构/渠道分成比例，用于企业门户对账单。
