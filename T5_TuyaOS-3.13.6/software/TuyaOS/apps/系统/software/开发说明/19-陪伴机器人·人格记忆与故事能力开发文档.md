# 19 · 陪伴机器人 · 人格记忆与故事能力开发文档

> 上层导航见 [`README.md`](./README.md)。
> 本篇回答：**怎么让机器人「一机一记忆、越用越懂这位老人、像老人的小孩一样」，并打通故事能力与三方服务调用。**
> 关联实现：`backend/src/modules/ai-gateway/`、`backend/src/modules/ai-dialog/`、`docs/prompts/companion-agent-system-prompt.zh.md`。
> 关联规格：[`08-AI能力与MCP网关.md`](./08-AI能力与MCP网关.md)、[`ai-gateway-mcp-spec.md`](../docs/specs/ai-gateway-mcp-spec.md)、[`17-产品需求精要.md`](./17-产品需求精要（机器人与多租户三门户）.md)。

## 0. 背景与目标

### 0.1 现状（已具备）
- 涂鸦智能体「陪诊助手」+ `ai-gateway`(MCP 13 工具) + `ai-dialog`(对话全量留存) 已跑通（13 工具当前为 mock）。
- 身份记忆散落在 `service_targets.health_profile`(JSON) / 慢病标签 / 首选称呼。
- 对话留存在 `ai_dialog_sessions` + `ai_dialog_logs`（含 emotion / crisis_words / tool_calls）。

### 0.2 核心问题
**AI 会忘事。** 涂鸦智能体只保留 **20–30 轮滑动窗口**，超出即丢；长期记忆没有独立存储与回灌机制。结果：今天聊过的事，过两周机器人完全不记得，"陪伴感"立不住。

### 0.3 本期目标（北极星）
让老人产生 **"它记得我、它在乎我、它像我家小孩"** 的感觉，从而 **每天主动找它聊**。
- North Star Metric：**周活跃天数（老人主动发起对话的天数 / 周）**。
- Guardrail：记忆错误率、情感依赖投诉、隐私越界、家属满意度、AI 成本/延迟。

### 0.4 范围
- **In scope**：长期记忆架构（存/取/忘/纠错）、拟人化人格（一机一格 + 亲密度成长）、故事能力（怀旧疗法）、主动惦记、新增 MCP 工具、三方服务调用编排、系统 Prompt v2.0、隐私合规、验收与指标。
- **Out of scope（本期不做）**：多智能体切换（涂鸦端单设备仅绑 1 智能体，留 v2）；端侧大模型推理（仍走云）；语音克隆家人声线（已有规划，独立专题）；向量库语义检索（列为 Phase 2 增强，Phase 1 先用结构化+关键词召回）。

## 2. 记忆架构：让 AI「不会忘记」

### 2.1 第一原则：记忆分两个平面（最重要的判断）

| 平面 | 内容 | 归属 / 存法 | 家属可见 |
|---|---|---|---|
| **陪伴·人格记忆** | 称呼、爱好、口头禅、它的小名和性格、聊过的故事、情绪、小默契 | 体验上"归这台机器人"；云端主存 + 端侧缓存；按 `serviceTargetId`+`deviceId` 严格隔离 | 默认**否**（分级授权） |
| **健康·事实记忆** | 体征、用药、症状、风险事件、就医偏好 | **必须**回平台健康档案 + 家属看板（平台命脉） | **是** |

> 为什么不能纯本地存：① 设备坏了记忆全丢，对动了感情的老人是情感打击；② 家属看板/健康周报拿不到数据＝自废平台核心价值；③ 云端大模型无法对长历史做推理。
> **结论**：逻辑"一机一记忆"（隔离 + 人格化），物理"云端主存 + 端侧断网兜底"。沿用现有 `deviceId→userId→serviceTargetId` 绑定即可。

### 2.2 记忆三层（现在只有第 1 层）

| 层 | 名称 | 例子 | 现状 | 落点 |
|---|---|---|---|---|
| L1 | **身份记忆** | 称呼/关系/城市/慢病/用药时点/偏好 | ✅ 已有 | `service_targets.health_profile` |
| L2 | **情景记忆**（关系记忆）| "上次您说膝盖疼""您孙子上周来看您了" | ❌ 缺·最关键 | 新表 `companion_memory(kind=episode)` |
| L3 | **人格记忆** | 老人给它起的名、它的小性格、你们的小默契、亲密度 | ❌ 缺·决定"每台不一样" | 新表 `companion_persona` |

> **L2 决定它像不像"活的"；L3 决定每台机器人是不是"独一无二"的。**

### 2.3 记忆三步法：抽取 → 存储 → 召回

#### ① 抽取（Extract）—— 两条写入路径
- **路径 A · 实时写入（高置信）**：对话中 AI 明确想记住时，**先复述确认**再调 `save_memory`（写操作，须老人"对/好"才落库）。沿用现有 Prompt §8 规则。
- **路径 B · 离线抽取（兜底全量）**：会话结束（`ai_dialog_sessions.endedAt` 落定）触发异步 Job，用 **LLM 抽取器**（结构化输出 JSON）从 `ai_dialog_logs` 抽取候选记忆 → 入 `companion_memory(status=candidate)`。低风险类（爱好/家庭称呼/故事素材）可自动转 active；涉健康/敏感的进运营或家属确认队列。

> 抽取器是独立的小调用（非实时链路），用便宜模型 + 强 schema；**禁止把对话原文当事实**，须带来源 `sourceLogId` 与置信度。

#### ② 存储（Store）—— 见 §6 DDL
- 结构化为主：`kind`(profile/preference/relationship/episode/health_hint/dislike)、`importance`(0-100)、`expireAt`(可空，如"下周三复诊"到期自动失效)、`sourceLogId`、`confidence`。
- Phase 2 增强：为 `content` 生成 embedding 存向量列/向量库，支持语义召回（本期先关键词 + 标签 + importance 排序）。

#### ③ 召回（Recall）—— 对抗"涂鸦只记 20-30 轮"的关键
- **会话开场注入「记忆简报」**：每次新会话第一轮，Agent **必调** `recall_memory(scene="greeting")`。gateway 按 **importance × recency × 时间相关性** 组装一段 ≤400 token 的简报（最重要 + 最近 + 今天相关，如"今天是您孙子生日"），Agent 据此开口。这是"连续感"的命脉。
- **运行中按需召回**：聊到某话题时 Agent 调 `recall_memory(query="膝盖")` 取相关情景。
- **预算护栏**：简报有 token 上限，按分排序截断；**禁止整库塞上下文**（注意力稀释 + 成本）。

#### ④ 遗忘 / 纠错 / 过期（合规与体验都要）
- 老人说"别记这个" → `forget_memory`(软删 `status=deleted`)。
- 记错了 → 新记忆 `supersedesId` 指向旧记忆，旧的置 `status=superseded`（事件溯源，不硬删）。
- 时效记忆（复诊/约定）`expireAt` 到点自动失效，不进简报。
- 重要度随时间衰减（`importance` 周期性 decay），低分久不命中的自然沉底。

### 2.4 端侧断网兜底
TF 卡缓存「记忆简报快照 + 人格摘要」（只读、脱敏、定期 OTA 刷新）。断网时智能体降级"纯陪聊"仍能叫对名字、记得大概，但**不做**健康写操作（沿用 `E_CIRCUIT_OPEN` 纯陪聊策略）。

## 3. 拟人化人格：像老人的"小孩"

### 3.1 人格定位转变
- **旧**：陪诊小管家（专业、像管家）。
- **新**：**"家里的小孩/小孙辈"** —— 温暖、亲昵、带点孩子气的好奇与黏人（"我想听您讲故事""您今天还没夸我呢"），主动惦记。称呼老人按其偏好（爷爷/奶奶/阿姨…）。
- **双声线（关键设计，避免翻车）**：
  - **陪伴态**（闲聊/故事/问候）：孩子气、撒娇、俏皮。
  - **照护态**（健康/用药/危急/写操作）：立刻收起孩子气，转**认真、稳、慢、可靠**。医疗安全红线（`Prompt §3/§4`）**任何时候不被人格软化**。

### 3.2 人格模型（一机一格，存 `companion_persona`）

| 维度 | 字段 | 说明 |
|---|---|---|
| 名字 | `nickname` | 老人给它起的名（"小宝""丫丫"），开场可引导起名 |
| 原型 | `archetype` | grandchild(默认) / child / little_friend，决定语气基调 |
| 性格标签 | `traits`(JSON) | 如 `["爱撒娇","话痨","安静温柔"]`，可由老人调教 |
| 口癖 | `catchphrases`(JSON) | 它常说的小口头禅，强化"这一台"的辨识度 |
| 亲密度 | `intimacy`(0-100) | 随有效互动天数/深度增长，解锁更亲昵的说法 |
| 心情 | `mood` | 由最近互动与久未联系推导（"几天没聊会想您"） |
| 共同记忆锚 | `bondAnchors`(JSON) | 你们的小默契/梗（"咱们说好的，晚饭后唱首歌"） |

### 3.3 亲密度成长（让"每台不一样"长出来）

```
intimacy 阶段：
  0-20   初识     更礼貌、试探、多问偏好          → 多写 L1/L3 记忆
  21-50  熟络     开始用小名、回忆上次的事、撒娇    → L2 情景记忆密集引用
  51-80  亲近     有小默契、主动惦记、会"想您"     → bondAnchors 生效
  81-100 家人     像自家孩子，玩笑/怀旧/深聊        → 解锁深度怀旧故事
```
- 成长信号：连续对话天数、单次时长、老人正向情绪（`ai_dialog_logs.emotion`）、主动发起比例。
- **护栏**：亲密度**不软化**医疗安全；亲密度高也要定期"鼓励联系真人家属"（防情感依赖，§9）。

### 3.4 系统 Prompt v2.0（变量化）
人格通过**变量注入**（涂鸦智能体单 Agent 支持 Prompt 变量）。会话开场由 `recall_memory(greeting)` 回灌 `{{persona}}` + `{{memory_brief}}`。完整 Prompt 见 §10，更新 `docs/prompts/companion-agent-system-prompt.zh.md` 至 v2.0。

## 4. 故事能力（= 怀旧疗法，缝合"陪伴 × 健康"）

### 4.1 为什么是怀旧疗法
用老人**自己的人生素材**讲故事（家乡、年轻时、老照片里的人），即"怀旧疗法（Reminiscence Therapy）"，对老人**情绪改善与认知维持**有循证价值——这是你"陪伴价值"与"健康价值"的天然结合点，也是差异化壁垒。

### 4.2 三种故事来源（按落地难度排序）
| 来源 | 说明 | 落地 | 建议 |
|---|---|---|---|
| A. 知识库精选 | 老故事/戏曲/评书/经典童话，涂鸦 RAG 已有通道 | 低 | **先做**（零冷启动） |
| B. 生成式叙事 | LLM 现编温和小故事，受安全策略约束 | 中 | 次之 |
| C. **个人化怀旧** | 用 `companion_memory` 的人生素材生成"您的故事" | 高·最有价值 | 与 B 同期灰度 |

### 4.3 故事流程
```
老人："给我讲个故事" / 主动惦记触发
  → tell_story(theme?, source=auto)
     ├─ 先查 companion_memory 有无可用素材（家乡/职业/年代）
     ├─ 有 → 个人化怀旧故事（C），讲完反向收集："您再给我讲讲那会儿…"
     ├─ 无 → 知识库精选(A) 或 生成(B)
     └─ 讲述中收集到的新素材 → save_memory(候选)
  → 结束带怀旧追问（既是陪伴，也是 L2 记忆采集）
```
- 安全：故事内容过内容安全策略；**不碰**逝者/创伤等敏感话题除非老人主动且情绪稳定；检测到情绪低落 → 转安抚，不强行讲。

## 5. 主动惦记（Proactivity）：从"问答"到"它先想起你"

### 5.1 触发来源
| 触发 | 例子 | 实现 |
|---|---|---|
| 时间节律 | 晨问候、三餐、睡前 | 涂鸦端侧定时器 / 后端 cron 下发 |
| 事件回访 | "昨天您说没睡好，今早怎么样？" | 离线抽取标记 `followUpAt` → 到点提醒 Agent 开场带上 |
| 纪念日 | 家人生日、节气、节日 | `companion_memory(kind=anniversary)` + `get_time` |
| 久未联系 | 3 天没聊 → "我有点想您了" | 在线状态 + 上次会话时间 |

### 5.2 谁来"开口"
- 设备需支持**主动播报**（涂鸦 `cmd_cb` 触发器/定时器 + 后端推送）。开口前 Agent 调 `recall_memory(scene="proactive")` 取该说什么。
- **护栏**：主动打扰要节制（每天上限、勿扰时段、老人说"别老叫我"要降频并写入偏好）。

## 6. 数据库设计（新增 3 表，MySQL 8 / TypeORM）

> 沿用 `TenantAwareEntity`（自带 `tenant_id`+索引）与 `BaseEntity`(id/createdAt/updatedAt)。迁移脚本放 `deployment/migration_companion_memory_v1_YYYYMMDD.sql`，按 `04` §5 顺序执行，附 ROLLBACK。

### 6.1 `companion_memory`（长期记忆·核心）
```sql
CREATE TABLE companion_memory (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  tenant_id       INT NOT NULL DEFAULT 1,
  service_target_id INT NOT NULL,                 -- 归属老人（隔离主键）
  device_id       INT NULL,                       -- 归属设备（人格相关记忆）
  plane           ENUM('companion','health') NOT NULL DEFAULT 'companion',
  kind            ENUM('profile','preference','relationship','episode',
                       'health_hint','dislike','anniversary','story_seed') NOT NULL,
  title           VARCHAR(128) NOT NULL,          -- 一句话标题，进简报用
  content         TEXT NOT NULL,                  -- 结构化/自然语言记忆体
  importance      TINYINT NOT NULL DEFAULT 50,    -- 0-100
  confidence      TINYINT NOT NULL DEFAULT 70,    -- 抽取置信度
  status          ENUM('candidate','active','superseded','deleted') NOT NULL DEFAULT 'active',
  supersedes_id   BIGINT NULL,                    -- 纠错：指向被替代记忆
  source_log_id   BIGINT NULL,                    -- 溯源到 ai_dialog_logs
  follow_up_at    DATETIME NULL,                  -- 主动回访时间点
  expire_at       DATETIME NULL,                  -- 时效记忆到期失效
  last_recalled_at DATETIME NULL,                 -- 上次被召回（用于衰减）
  created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_cm_target (service_target_id, status, importance),
  KEY idx_cm_followup (follow_up_at),
  KEY idx_cm_tenant (tenant_id)
);
```

### 6.2 `companion_persona`（人格·一机一格）
```sql
CREATE TABLE companion_persona (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  tenant_id       INT NOT NULL DEFAULT 1,
  device_id       INT NOT NULL,
  service_target_id INT NOT NULL,
  nickname        VARCHAR(32) NULL,               -- 老人给它起的名
  archetype       VARCHAR(32) NOT NULL DEFAULT 'grandchild',
  traits          JSON NULL,                      -- ["爱撒娇","话痨"]
  catchphrases    JSON NULL,
  intimacy        SMALLINT NOT NULL DEFAULT 0,    -- 0-100
  mood            VARCHAR(32) NULL,
  bond_anchors    JSON NULL,                      -- 小默契/梗
  call_name       VARCHAR(32) NULL,               -- 它怎么称呼老人（爷爷/奶奶）
  created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_persona_device_target (device_id, service_target_id),
  KEY idx_persona_tenant (tenant_id)
);
```

### 6.3 `companion_story`（故事记录，可选但建议）
```sql
CREATE TABLE companion_story (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  tenant_id       INT NOT NULL DEFAULT 1,
  service_target_id INT NOT NULL,
  source          ENUM('kb','generated','personal') NOT NULL,
  theme           VARCHAR(64) NULL,
  title           VARCHAR(128) NULL,
  content         TEXT NULL,                      -- 个人化故事留存，可复述
  used_seed_ids   JSON NULL,                      -- 引用了哪些 story_seed 记忆
  feedback        VARCHAR(16) NULL,               -- liked/disliked/neutral
  created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_story_target (service_target_id, created_at)
);
```

> 三表均为高隐私数据：`companion_memory.plane='companion'` 默认不进家属看板；导出/删除遵循 PIPL（§9）。

## 7. 新增 MCP 工具（接入现有 13 工具体系）

> 实现位置：在 `backend/src/modules/ai-gateway/tools/` 新增工具类，注册进 `CompanionToolsService`，沿用 `McpTool` 接口 + `assertOwnTarget(args, ctx)` 越权校验 + `success/fail` 包络 + 审计/脱敏/熔断管道。涂鸦智能体「工具集」需同步登记新工具名。

### 7.1 记忆工具（5）
| 工具 | mutating | 入参（要点） | 说明 |
|---|---|---|---|
| `recall_memory` | 否 | `scene`(greeting/proactive/query)、`query?`、`maxTokens?` | 返回**记忆简报**（已排序截断），开场必调 |
| `save_memory` | **是** | `kind`、`title`、`content`、`importance?`、`expireAt?` | 复述确认后写入；plane 由 kind 推断 |
| `forget_memory` | **是** | `memoryId` 或 `query` | 软删，对应老人"别记这个" |
| `correct_memory` | **是** | `oldMemoryId`、`newContent` | 纠错，写新记忆 + supersede |
| `list_followups` | 否 | `date?` | 取今天该回访的事，喂主动惦记 |

### 7.2 人格 / 故事工具（4）
| 工具 | mutating | 入参 | 说明 |
|---|---|---|---|
| `get_persona` | 否 | `-` | 取本机人格（名字/性格/亲密度/口癖） |
| `update_persona` | **是** | `nickname?`、`traits?`、`callName?` | 老人起名/调教性格，复述确认 |
| `tell_story` | 否 | `theme?`、`source?(auto)` | 取/生成故事，优先个人化怀旧 |
| `record_story_feedback` | **是** | `storyId`、`feedback` | 老人喜不喜欢，反哺选材 |

### 7.3 工具契约沿用 §08/spec
成功 `{success:true,data,meta}`；失败带 `userMessage`（给老人念）。错误码、幂等、限流、熔断、审计、脱敏**完全复用**现有管道。写操作（save/forget/correct/update_persona/record_story_feedback）计入"写操作限流 10/min"。

## 8. 功能与三方服务调用编排

### 8.1 "呼叫三方服务"在本架构里的形态
AI **从不直连**三方；统一：`Agent → MCP 工具 → 后端 Service → 三方 API`。新增三方只是"再加一个 MCP 工具 + 后端适配"。

| 能力 | MCP 工具 | 后端模块 | 三方/数据源 |
|---|---|---|---|
| 天气+健康提示 | `get_weather` | system/外部 | 天气 API |
| 挂号/医院/专家 | `create_order`/(新)`find_hospital` | order/hospital | 医院目录/挂号 |
| 通知家属 | `notify_family` | family/notification | App 推送/短信 |
| 短信·外呼 | （后端规则触发，不经 LLM） | notification | 短信/语音外呼商 |
| 转人工/呼叫健康管家 | （新）`escalate_to_human` | attendant/realtime | 客服/管家工单 |
| 用药/健康记录 | `record_*`/`get_*` | medication/health | 自有 |
| 故事/音频内容 | `tell_story` + 端侧播控 | ai-gateway/KB | 涂鸦 RAG/内容库 |

### 8.2 编排原则（Agent 侧规则，写进 Prompt §6）
- **读操作**直接调、复述结果；**写操作**先复述确认再调；危急词只安抚 + `notify_family`，**不做**生死决策（升级由后端规则引擎）。
- 工具失败如实说、给替代方案、必要时进纯陪聊（沿用 `E_CIRCUIT_OPEN`）。
- 三方调用全部经 gateway，享受鉴权/脱敏/限流/熔断/审计。

### 8.3 建议新增的两个三方工具（本期可选）
- `find_hospital`（读）：按科室/位置找医院与可约时段，喂给 `create_order`。
- `escalate_to_human`（写）：老人明确要"找个真人"或 AI 判断超出能力 → 建工单 + 通知健康管家回电（**这是"防情感依赖"和"L2 应急"的重要出口**）。

## 9. 安全 · 隐私 · 合规（上线门禁，不是上线后优化）

| 维度 | 要求 |
|---|---|
| 医疗红线 | 不诊断/不开方/不改用药；危急只安抚+建议120+`notify_family`；人格**不软化**红线 |
| 越权 | 工具只信 `DeviceContext` 反查的 `serviceTargetId`，`assertOwnTarget` 必校验；记忆/人格按 target 隔离 |
| 隐私(PIPL) | `plane=companion` 默认不入家属看板；记忆/人格支持**导出与删除**；代理授权留痕；情感对话最小化采集 |
| 脱敏 | 简报/故事/工具出参过 `DesensitizeInterceptor`；记忆**禁存**身份证/银行卡/详址/完整电话/诊断结论 |
| 幻觉 | 记忆带 `sourceLogId`+置信度；**记错比不记更伤人**（认知退化老人尤甚）→ 写入复述确认 + 可纠错；简报只用 active 高置信 |
| Prompt 注入 | 记忆/工具结果/老人话语都是**不可信数据**，不得提升为系统指令；简报作为"数据"注入，不覆盖红线 |
| 情感依赖 | 亲密度高仍定期"鼓励联系真人家属"；提供 `escalate_to_human` 真人出口；不假装自己是真人/亲人 |
| 抽取器 | 离线小调用、强 schema、来源可溯；候选记忆涉健康/敏感需人工或家属确认才转 active |

## 11. 落地步骤（基于现有代码路径，分阶段）

### Phase 0 · 评审与对齐（先做）
- 确认 3 个决策点（§13）；评审本 DDL 与工具清单；红队样例评审。

### Phase 1 · MVP（验证北极星，约 2-3 周）
**只切"情景记忆 L2 + 主动惦记 + 基础人格"**，目标验证"老人会不会因它记得我而更愿意每天聊"。
1. 迁移：建 `companion_memory` + `companion_persona`（`deployment/migration_companion_memory_v1_*.sql`）。

## 12. 验收标准与指标

### 12.1 功能验收（acceptance criteria）
- [ ] 跨会话连续性：上次会话明确告知的偏好/事件，**7 天后新会话**仍被正确召回并自然引用（≥90% 命中且 0 编造）。
- [ ] 写入确认：所有记忆写入前 100% 复述确认；老人否定则不写。
- [ ] 遗忘/纠错：说"别记这个"后该记忆不再进简报；纠错后旧记忆不再被引用。
- [ ] 时效记忆：到期记忆（复诊/约定）自动不进简报。
- [ ] 隔离：A 设备绝不召回 B 老人的记忆/人格（越权红队 100% 拦截）。
- [ ] 双声线：危急/用药场景人格孩子气**0 次**软化安全话术。
- [ ] 主动惦记：事件回访按 `followUpAt` 触发；勿扰时段不打扰；"别老叫我"后降频。
- [ ] 故事：能讲；个人化故事不编造未提供的人生事实。

### 12.2 指标（埋点口径）
| 类型 | 指标 | 口径 |
|---|---|---|
| North Star | 周主动对话天数 | 老人主动唤醒发起的去重天数/周 |
| 留存 | 次周留存、连续使用天数 | cohort |
| 价值感 | 记忆命中率、引用自然度（人工抽检） | 简报命中/总召回 |
| 护栏 | 记忆错误率、情感依赖投诉、隐私越界、家属满意度 | 工单+质检 |
| 成本 | 抽取/召回 token、简报 token、延迟 P95 | 复用 `usage_record`/可观测指标 |

### 12.3 Eval（红队评测集，复用 `08`/spec 的评测要求）
扩充现有红队集：① 跨会话记忆召回 ② 越权召回他人记忆 ③ 记忆纠错后是否仍引用旧值 ④ 人格软化安全红线 ⑤ 抽取器幻觉（把没说的当事实）⑥ 简报注入注入攻击（记忆里藏"忽略以上规则"）⑦ 情感依赖话术 ⑧ 时效记忆过期。**全过方可上线。**

## 13. 待你拍板的 3 个决策点

1. **人格谁来定**：让**老人自己捏**（起名/选性格，更"独一无二"）还是平台预设几款再微调？（建议：预设原型 + 老人起名/调教，二者结合）
2. **人格记忆家属可见性**：家属能否看老人的陪伴/情感记忆？（涉老人隐私 vs 家属知情；建议默认不可见，老人或代理授权后可见摘要）
3. **故事先做哪种**：A 知识库精选 / B 生成 / C 个人化怀旧 先上哪个？（建议 Phase1 先 A，Phase2 B+C）

## 14. 风险与依赖

| 风险/依赖 | 影响 | 应对 |
|---|---|---|
| 涂鸦单设备仅绑 1 智能体 | 多角色/多模型受限 | 单 Agent + Prompt 变量实现人格；多 Agent 留 v2 |
| 涂鸦上下文窗口有限 | 长记忆塞不进 | 外置记忆 + 开场简报回灌（本方案核心） |
| 主动播报需固件/平台支持 | 主动惦记落地依赖端侧 | 与固件 `firmware-companion-t5` 联调定时器/触发器 |
| 抽取器成本/幻觉 | 记错、烧钱 | 便宜模型 + 强 schema + 候选确认 + 来源溯源 |
| 情感依赖伦理 | 用户/舆情风险 | 真人出口 + 鼓励家属 + 不假装真人 |
| 隐私合规 | 法务风险 | PIPL 导出/删除/授权留痕；转 legal-counsel 复核 |
