# 问题单：语音设「闹钟」与实际体验不一致（云端话术与 MCP 工具语义）

## 一句话描述（问题是什么）

**用户语音要求设置「闹钟」或被告知「闹钟已设好」，但设备实际执行的是到点 TTS 口播的「提醒」，没有响铃闹钟体验——固件 MCP 调用成功、到点能说话，但用户得到的是「提醒」而非「闹钟」。**

---

## 问题影响

| 影响面 | 说明 |
|--------|------|
| **体验与承诺不符** | 用户按「闹钟」理解，预期到点 **响铃**；实际仅 **口播一句话**，易认为没设上或设备坏了。 |
| **话术误导** | 云端 TTS 明确说「**闹钟已经帮你设好了**」，与底层能力不一致，直接伤害信任。 |
| **验收困难** | 串口可见 MCP `success:true`，单看固件像成功；**端到端语音产品仍不达标**。 |
| **需云侧解决** | NLG 由涂鸦云生成，设备原样播报，**设备侧无法单独把「闹钟」改成真实响铃体验**。 |

---

## 实际案例：具体发生了什么

以下为 **`uart_log.txt` 实机复现**（`tuyaos_demo_wukong_ai`，`ENABLE_TOOLKITS_TM=y`，2026-05-23）。

**用户说：**「两分钟之后，提醒我喝水。」（口语里常理解为「设个闹钟 / 到点叫我」）

| 阶段 | 时间 | 发生了什么 |
|------|------|------------|
| 用户说话 | 14:14:44 | ASR：**「两分钟之后，提醒我喝水。」** |
| 云端调设备 | 14:14:52 | MCP `tools/call` → **`device_schedule_set`**（**口播提醒**，不是响铃闹钟）<br>参数：`message=提醒喝水`，触发时刻 14:16:00<br>返回：`success:true`，`is_error=0` |
| 云端对用户说 | 14:14:57 | TTS：**「两分钟后的闹钟已经帮你设好了，」** ← **称「闹钟」** |
| 到点实际体验 | 14:16:00 | 固件 `reminder.fire` → 仅 TTS 播报：**「提醒喝水」** ← **无响铃、非闹钟** |

**用户视角：** 听到「闹钟设好了」→ 到点只听到一句「提醒喝水」，**没有闹钟铃声**。  
**技术事实：** 云端选用的是 **`device_schedule_set`（口播提醒）**，未调用 **`device_alarm_set`（响铃闹钟）**；设备按提醒链路执行，**行为正确，但与用户听到的「闹钟」话术不一致**。

**关键日志：**

```
14:14:44  ASR: 两分钟之后，提醒我喝水。
14:14:52  tools/call → device_schedule_set (message=提醒喝水)
14:14:52  mcp tool finished name=device_schedule_set is_error=0
14:14:57  NLG/TTS: 两分钟后的闹钟已经帮你设好了，
14:16:00  reminder -> fire → TTS: 提醒喝水
```

## 2. 预期 vs 实际（本问题聚焦点）

| 项目 | 用户/产品预期 | 实际 |
|------|----------------|------|
| 用户理解 | 设置了 **闹钟**（到点响铃或至少「闹钟体验」） | 到点 **TTS 念「提醒喝水」**，无响铃 |
| 云端话术 | 与真实能力一致 | TTS：**「闹钟已经帮你设好了」** |
| 设备 MCP | 若说闹钟，应走 `device_alarm_set` | 实际走 **`device_schedule_set`**（口播提醒） |
| 固件执行 | — | `reminder.fire` + TTS，**与 schedule 工具匹配，执行正常** |

## 3. 复现步骤

1. 固件开启 `ENABLE_TOOLKITS_TM`，联网进入 AI 对话。  
2. 说：**「两分钟之后，提醒我喝水」**（或类似「设个闹钟提醒我…」）。  
3. 听回复是否出现「闹钟已设好」，等待到点，观察是 **响铃** 还是 **口播**。  
4. 保存 `uart_log.txt`，查 `tools/call`、`device_schedule_set` / `device_alarm_set`、`reminder.fire`。

---

## 4. 背景（设备侧工具区分，供云侧对齐）

| MCP 工具 | 到点体验 | 对用户应怎么说 |
|----------|----------|----------------|
| **`device_alarm_set`** | **响铃**（RINGTONE） | 可说「闹钟」 |
| **`device_schedule_set`** | **TTS 口播** `message` | 应说「提醒」，**禁止说「闹钟」** |

云端 NLG 在 `wukong_ai_skills.c` 中 **原样 TTS 下发**，设备不改写措辞。

## 7. 我方建议（供涂鸦评估）

```text
【话术与工具一致】
- 仅当 tools/call 为 device_alarm_set 时，对用户可说「闹钟 / 响铃」；
- 当 tools/call 为 device_schedule_set 时，只能说「提醒 / 到点会告诉你」，禁止说「闹钟」；
- 禁止在未调用 alarm 工具时声称「闹钟已设好」。
```

设备侧可配合：在 MCP tool description 中写明 Post-call 用语（需确认云侧是否读取）。
