## 二、按章节整理的命令与提示词方案

### 1. CC 全面教程（00:00–01:40）

**目标**：建立整体心智模型（CLI 能做什么、与 IDE 协作关系）。

| 类型     | 内容 |
| -------- | ---- |
| 终端启动 | 在项目根目录执行 `claude` 进入交互会话 |
| 查看帮助 | `/help` |
| 健康检查 | `/doctor`（安装与环境自检，可按 `f` 尝试自动修复） |
| 退出     | `/exit` 或 `/quit` |

**提示词示例**

- 「用三句话说明：Claude Code 和网页版 Claude、IDE 插件各适合什么场景？」
- 「我接下来要系统学一遍 CC，请按『安装 → 登录 → 项目初始化 → 日常开发 → 上线前检查』列一个检查清单。」

---

### 2. 认识 CC（01:40–05:25）

**目标**：理解工作方式（读写仓库、权限、工具调用）。

| 类型     | 内容 |
| -------- | ---- |
| 权限规则 | `/permissions`（别名 `/allowed-tools`） |
| 成本与用量 | `/usage`（别名 `/cost`、`/stats`） |
| 状态一览 | `/status` |

**提示词示例**

- 「说明你会在哪些情况下请求我批准：改文件、跑 shell、访问网络、用 MCP？」
- 「用本仓库举例：你会如何先做只读探索，再提出修改方案？」

---

### 3. 初步上手（05:25–06:55）

**目标**：第一次对话、让模型读懂仓库。

| 类型       | 内容 |
| ---------- | ---- |
| 项目记忆   | `/init`（生成 starter `CLAUDE.md`）→ `/memory`（编辑记忆、自动记忆） |
| 引用文件   | 输入框使用 `@文件路径` 引用单个文件（与官方交互说明一致） |
| 附加目录   | `/add-dir <path>`（会话内扩展可读目录） |

**提示词示例**

- 「先阅读 `README`、`package.json`（或对应构建文件）和主入口，总结：技术栈、运行方式、核心目录。」
- 「不要改代码。列出你理解本项目的 5 个关键模块及它们之间的关系。」

---

### 4. 安装 CC（06:55–08:03）

**目标**：安装 CLI、验证可用。

| 类型     | 内容 |
| -------- | ---- |
| 全局安装 | `npm install -g @anthropic-ai/claude-code` |
| 版本检查 | `claude --version` |
| 免全局   | `npx @anthropic-ai/claude-code` |
| 账号     | `/login`、`/logout` |
| 排错     | `/doctor`；启动级调试可查阅官方 CLI 文档中的 `claude --debug` 等说明 |

**提示词示例**

- 「我在 Windows/macOS/Linux 上安装后执行 `claude` 报错：〈粘贴报错〉。请按最可能原因排序给出排查步骤。」

---

### 5. 配置模型（08:03–21:53）

**目标**：模型切换、推理强度、计划模式、与「云端/企业后端」相关配置（若视频涉及第三方 API，请以你实际环境变量为准）。

| 类型       | 内容 |
| ---------- | ---- |
| 换模型     | `/model [model]` |
| 努力程度   | `/effort [low\|medium\|high\|xhigh\|max\|auto]` |
| 计划模式   | `/plan [描述]` |
| 设置界面   | `/config`（别名 `/settings`） |
| 全屏/渲染  | `/tui [default\|fullscreen]` |
| 主题       | `/theme` |
| Bedrock    | `/setup-bedrock`（需 `CLAUDE_CODE_USE_BEDROCK=1`） |
| Vertex     | `/setup-vertex`（需 `CLAUDE_CODE_USE_VERTEX=1`） |

**环境变量（常见）**  
官方文档与各云平台方案会列出完整列表；常见包括 `ANTHROPIC_API_KEY`、以及按部署方式设置的 Bedrock/Vertex 相关变量。**请勿把真实 Key 贴进飞书文档**，用占位符即可。

**提示词示例**

- 「当前任务需要更强推理：请先 `/plan` 给出方案再改代码。」（也可直接发自然语言要求「先计划再动手」。）
- 「在不大改架构前提下，把实现拆成最多 4 个可独立验证的步骤，每步说明要改哪些文件。」

### 6. 版本管理（21:53–25:43）

**目标**：与 Git 协作、看改动、发 PR 前自检。

| 类型       | 内容 |
| ---------- | ---- |
| 交互式 diff | `/diff` |
| 安全审查   | `/security-review` |
| 代码审查   | `/review [PR]` |
| PR 自动修复 | `/autofix-pr [prompt]`（需 `gh` 与 Web 会话能力，见官方说明） |
| 撤回/检查点 | `/rewind`（别名 `/checkpoint`、`/undo`） |

**提示词示例**

- 「基于当前未提交改动，用要点列表总结：动机、风险、需要我重点人工 review 的文件。」
- 「假设我要开 PR：请给分支名建议、`git` 提交信息（conventional commits）、以及 PR 描述模板（含测试说明）。」

### 7. 上下文管理（25:43–29:36）

**目标**：长会话下压缩、查看窗口占用、侧问不污染主线。

| 类型         | 内容 |
| ------------ | ---- |
| 上下文可视化 | `/context [all]` |
| 压缩历史     | `/compact [可选：希望保留的重点说明]` |
| 侧问         | `/btw <问题>` |
| 新开会话     | `/clear [可选会话名]`（与 `/compact` 场景不同，见官方说明） |
| 恢复会话     | `/resume [会话]` |
| 会话分支     | `/branch [name]`（别名 `/fork`，行为受环境变量影响，见官方文档） |
| 导出         | `/export [filename]` |

**提示词示例**

- 「`/compact`：请把到目前为止的决策总结成『目标 / 已确认约束 / 未完成项』三部分。」
- 「在不影响主线的前提下回答：`/btw` 这个 npm 报错通常有哪三类原因？」

### 9. 高级扩展（40:35–53:49）

**目标**：MCP、子代理、批量改动、定时/循环任务、Web/远程协作、沙箱等（视频此段通常最长）。

| 类型           | 内容 |
| -------------- | ---- |
| MCP 动态命令   | 服务器可注册以 `/mcp___` 形式出现的命令（见官方「MCP prompts」） |
| 批量/并行改动  | `/batch <描述>`（Skill，worktree + 多代理） |
| 循环任务       | `/loop [interval] [prompt]`（别名 `/proactive`） |
| 云例行任务     | `/schedule`（别名 `/routines`） |
| 远程控制       | `/remote-control`（别名 `/rc`） |
| Web 会话拉取   | `/teleport`（别名 `/tp`） |
| Ultrplan       | `/ultraplan` |
| 深度审查       | `/ultrareview [PR]` |
| 沙箱           | `/sandbox`（平台支持时） |
| Chrome         | `/chrome` |
| Desktop        | `/desktop`（别名 `/app`，macOS/Windows） |

**提示词示例**

- 「列出本仓库最适合接 MCP 的 3 个场景（例如 issue 跟踪、设计稿、内部 API），每个场景给出需要的最小工具集合。」

## 三、官方「典型工作流」速查（与视频结构高度同构）

下列与 [Commands - typical workflow](https://code.claude.com/docs/en/commands.md) 一致，可直接作为飞书里的「总流程卡片」：

1. **首次进仓库**：`/init` → `/memory` → `/mcp`、`/agents` → `/permissions`  
2. **开发中**：`/plan` → `/model`、`/effort` → `/context` → `/compact`；侧问用 `/btw`  
3. **发布前**：`/diff` → `/simplify` → `/review` 或 `/security-review`  
4. **会话之间**：`/clear` → `/resume`、`/branch`；Web/多端见 `/teleport`、`/remote-control`  
5. **异常**：`/rewind` → `/doctor`、`/debug` → `/feedback`

## 四、导入飞书文档的步骤（推荐）

1. 在飞书新建「云文档」→ 空白文档。  
2. 将本文 **全文复制粘贴**；飞书会自动识别大部分标题与表格。  
3. 若格式错乱：把本文存为 `.md`，在飞书使用 **导入 Markdown**（若组织开启该能力）。  
4. 将视频置顶「完整文档」链接贴在本文顶部「说明」区，方便同事跳转原文。
