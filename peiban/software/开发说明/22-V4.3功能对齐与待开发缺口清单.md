## 0. 结论

V4.3 已把项目从“长辈守护设备”升级为：

> **家庭智慧陪伴机器人 + 家庭 App + 社区/机构后台 + 服务协同网络**。

现有开发文档和 API 清单已经覆盖陪诊订单、健康用药、家庭、告警、设备 mock、AI/MCP、多租户和后台大屏等底座，但与 V4.3 的商业闭环相比，仍缺 6 条主线：

1. **真设备闭环**：固件、涂鸦 OpenAPI/Pulsar、App 配网/视频/OTA、推送和设备设置仍待落地。
2. **声纹成员链路**：成员声纹录入、识别置信度、误识别纠正、成员权限路由和访客模式缺后端/API/App/机器人闭环。
3. **家庭记忆与任务编排**：长期记忆、人格式机器人、家庭留言、指定成员提醒、任务回执仍停留在设计稿。
4. **社区内容触达闭环**：后台定向发布、审核撤回、机器人播报、App 同步、到达/播报/查看回执缺完整模块。
5. **生活服务与合作医院协同**：已有订单、服务目录、医院目录基础，但缺 V4.3 所需的聚合入口、服务商履约监管、医院合作配置、接口授权和转诊/随访闭环。
6. **视觉跌倒与 SOS 处置闭环**：V4.3 明确“AI 视觉跌倒检测已落地”，开发文档中仍有“跌倒移出范围/雷达成品”旧口径，需统一为“视觉算法已具备，待接入设备事件、App 强提醒、视频复核、社区处置和演练指标”。

## 3. 建议开发顺序

### P0 · 真实设备与安全闭环

- 恢复/确认源码位置，确保后端、App、后台和小程序可运行。
- 接涂鸦 OpenAPI/Pulsar，替换 `device` mock。
- App 增加推送 token、杀后台告警、SOS 紧急弹窗和 30s 处置。
- 将视觉跌倒算法事件接入规则引擎，形成“跌倒/SOS → 家属强提醒 → 视频复核/社区升级 → 审计复盘”闭环。
- MCP 13 工具至少接通健康、用药、家庭和通知真数据。

### P1 · V4.3 家庭 AI 与社区样板

- 声纹成员链路：录入、识别、纠错、权限路由和访客模式。
- 长期记忆与人格：`companion_memory`、`companion_persona`、`recall/save/forget/correct/get_persona`。
- 家庭任务与家属投喂：指定成员留言、日程提醒、任务回执。
- 社区内容触达：后台发布、审核撤回、机器人播报、App 同步和回执报表。
- 生活服务和医院协同：聚合服务入口、服务商履约节点、医院资源配置与合规授权。

### P2 · 放量与商业化

- 视频探视、云存储、4G/AI 续费、真实支付和用量计费。
- 内容生态、儿童轻量陪伴、方言增强和健康外设。
- 社区项目报表、服务监管、代理门户、SLA/对账、单城复制运营指标。

## 5. 待拍板问题

1. **自动呼援策略**：V4.3 推荐“家属强提醒 + 社区/人工升级”，是否保留直接呼 120 作为特殊配置。
2. **声纹授权模型**：老人本人、监护人、家属代录的授权边界和撤回流程。
3. **社区内容审核**：普通通知、紧急通知、健康宣教、商业内容是否采用不同审核流。
4. **合作医院展示规则**：只有真实协议有效的医院/绿色通道/权益才能展示，需配置协议有效期和授权范围。
5. **源码现状**：当前工作树大量源码删除，需确认是迁移后的预期状态，还是需要恢复后再进入实现。
