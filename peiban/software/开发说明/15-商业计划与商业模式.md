## 1. 一句话定位

> 陪了个伴，是一台为长辈打造的**家庭智能守护设备**：会陪伴、懂健康、能守护——让在外的子女，随时安心。

我们就是一台家庭智能守护设备：把**陪伴、健康、安全**三件事装进一台设备，放到长辈触手可及的地方；子女在手机 App 上随时看得见父母今天怎么样。

---

## 2. 我们是什么

陪了个伴是一台放在家里、围着长辈转的智能守护设备。它平时陪老人说话解闷，到点提醒吃药、记录身体状况；一旦发生跌倒，或老人按下求助键，第一时间通知**子女和社区**。

**一台设备，把「陪伴、健康、安全」三件事一起解决；子女在手机上随时看得见父母的状态。**

---

## 3. 痛点与市场窗口

| 谁 | 痛点 |
|---|---|
| 老人 | 独居、慢病、用药乱、孤独、突发风险无人知 |
| 异地子女 | 信息不透明、远程牵挂、出事才知道、决策难 |
| 社区 / 机构 | 想守护辖区老人，却没有「进到家里」的末端抓手 |

**为什么是现在（窗口期）**

| 窗口 | 依据 |
|---|---|
| 技术 | 大模型推理成本 18 个月降 90%+，「24h AI 健康管家」已可商业化；方言识别 / 语音情绪 / 声线合成成熟 |
| 市场 | 老龄化加速，居家养老成为刚需；家庭对「看得见、能预警」的守护设备需求上升 |
| 政策 | 长护险试点从 49 城走向全国；智慧养老、适老化改造纳入民生工程，有财政与政策预算 |

---

## 4. 核心产品：三大能力

| 能力 | 说明 | 价值 |
|---|---|---|
| **温暖陪伴** | 自然语音对话、方言、可授权家人声线、长期记忆人格 | 高频陪伴、治孤独，黏住长辈 |
| **主动健康** | 用药提醒 + 打卡 + 依从率、体征记录、健康周报、用药风险提示 | 把「被动看病」变「主动管理」 |
| **安全守护** | **SOS 一键求助 + 视觉算法跌倒检测**；事件**同步社区 + 子女**；规则引擎直连、不经 AI | 安全是信任的根，也是社区 / 机构买单的核心理由 |

**守护链路（产品信任核心）**：视觉识别到跌倒 / 老人按下 SOS → 直推后端规则引擎（不经大模型、不「猜」）→ 同时通知**全部子女 App + 签约社区** → 30 秒无人响应自动升级 → 全程留痕可查。

### 配置与定价（买断制，无月费、无服务包）

| 配置 | 含 | 定价 |
|---|---|---|
| **标准版** | 陪伴对话 + 健康管理 + SOS + WiFi | **899 元** |
| **顶配版** | 标准版全部 + **视觉跌倒检测** + **4G 独立联网** + 更多 | **1499 元** |

> ⚠️ 待拍板：899 / 1499 售价里是否**已含 N 年云 / AI / 4G 服务**。硬件买断后，AI 对话、4G 流量、云端是持续成本，建议把「含 X 年服务」写进售价，避免长期 OPEX 无来源（见 §13 风险）。

## 5. 设备的延展性（终端化）

这台设备是**进家庭的中枢**，可围绕它逐步长出更多守护，把「一台设备」升级为「一套家庭守护系统」：

- **体征监测**：心率、睡眠等（融合非接触 / 可穿戴传感）。
- **全屋适老化**：以设备为中枢，联动跌倒、呼叫、环境、门磁等，做整屋守护。
- **（可选）上门服务对接**：需要时一键对接第三方上门生活 / 照护服务，平台只做撮合调度，不自营、不单独定价。

---

## 6. 技术与平台底座（已落地）

**一套后端，连起「子女 App + 管理后台 + 设备」**——这是我们相对白牌硬件商的真正壁垒。

| 模块 | 技术 | 主要使用者 | 状态 |
|---|---|---|---|
| 后端 | NestJS 11 + TypeORM + MySQL8 + Redis（38 模块 / 66 实体） | App / 后台 / 设备共用 | ✅ 成熟 |
| 管理后台 | Vue3 + Element Plus（含**政府 / 社区 / 企业三门户大屏**） | 运营 / 机构 / 政府 | ✅ 成熟 |
| 子女 App | Flutter（看护盘 / 告警 / 健康 / AI 对话 / 下单）——**唯一用户端** | 子女 / 家属 | 🟡 核心闭环已通 |
| 设备 | 涂鸦 T5-E1 + Wukong AI 3.0 | 老人侧 | ✅ **硬件已完整落地** |

两个壁垒级设计：

- **安全双链路**：跌倒 / SOS 走**规则引擎**（不经 LLM、不会「猜」），只有陪聊 / 查询才走 AI。
- **多租户三门户**：设备的安全 / 健康数据沿「家庭 → 社区 → 机构 → 政府」层级**向上聚合**——正好是社区 / 机构批量部署后**管理辖区设备**的现成后台。

## 7. 商业模式与收入结构

**主角是硬件买断，B 端批量是放量主渠道，代理分销做规模杠杆。**

| 收入线 | 模式 | 地位 |
|---|---|---|
| **设备买断（C 端）** | 标准版 899 / 顶配 1499 | 核心 |
| **B 端批量采购** | 机构 / 社区 / 政府批量买设备，配套三门户后台管理 | 放量主渠道 |
| **渠道分销** | 区域代理 / 分销商佣金 | 规模杠杆 |

> B 端不单独 SaaS 收费——**三门户后台作为「买设备送管理平台」的一部分**，降低 B 端决策门槛，同时把数据沉淀在我们这。

---

## 8. 销售 / GTM

- **C 端**：电商 + 内容种草（子女买给父母）；子女 App 即获客与复购入口。
- **社区 / 养老院 / 机构**：批量采购守护辖区老人，配套监管大屏——智慧养老 / 适老化改造财政项目是大单来源。
- **政府 / 民政**：辖区聚合大屏 + 跌倒 / SOS 监控，进民生工程采购。
- **区域代理**：佣金分销，快速铺城。

## 10. 竞争与护城河

- **差异点**：设备背后有**一套已落地的平台 + 三门户 + 数据闭环**，纯消费硬件公司复制不了。
- **三层护城河**：① 进家庭的高频入口；② 健康 / 安全数据沉淀；③ 社区 / 政府层级的网络效应。
- **占组合稀缺位**：AI + 硬件终端 + 长期数据 + B 端协同，四者同备者极少。

## 11. 阶段路线

| 阶段 | 目标 | 重点 |
|---|---|---|
| 0–6 月 | 量产铺货 + 标杆社区 | 备货、C 端首批、1–2 个社区 / 机构样板 |
| 6–18 月 | B 端放量 + 区域代理 | 智慧养老 / 适老化项目、代理网络、数据闭环跑通 |
| 18–36 月 | 规模化 + 全屋守护 | 心率 / 全屋适老化升级、跨城复制、数据增值 |

---

## 12. 合规边界

「**协助与管理，不替代诊疗、不替代 120**」。健康 / 身份证 / 手机号字段级加密；AI 明示身份；声纹克隆需单独同意 + 显著标识；跌倒 / SOS 数据共享社区与子女需**授权留痕**（PIPL，最小必要、可导出可删除）。
> 这些边界直接约束系统设计：见 `08`（AI 安全 / 脱敏 / 审计）、`10`（数据范围 / 授权留痕）、`09`（告警链路）。

---

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 买断无复购、AI / 4G 长期 OPEX 无来源 | 售价内含 X 年服务、到期转小额续费或耗材增值；先把单台年成本算清 |
| 视觉跌倒误报 / 漏报 | 规则引擎 + 阈值可调 + 人工复核；安全宁误报不漏报；明确「协助不替代」 |
| 硬件同质化、被白牌打价格战 | 卖的是「设备 + 平台 + 数据闭环」，不是裸硬件；B 端 + 数据 + 社区绑定提门槛 |
| 数据合规（共享社区 / 子女） | 授权留痕、最小必要、字段级加密、可导出可删除 |
