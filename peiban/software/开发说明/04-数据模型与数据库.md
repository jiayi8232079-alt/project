# 04 · 数据模型与数据库

> 上层导航见 [`README.md`](./README.md)。本篇回答：**66 个实体如何分域、关键表是什么、迁移脚本在哪、加密与多租户列如何处理**。
> 代码位置：`backend/src/entities/*.entity.ts`；迁移 SQL：`deployment/*.sql`。

---

## 1. 数据库基本信息

| 项 | 值 |
|---|---|
| 数据库 | MySQL 8.0，库名 `qiaoguo_health` |
| ORM | TypeORM 0.3，`autoLoadEntities: true` |
| 时区 | 全链路锁定北京时间 `+08:00` |
| 命名 | 表/列小写下划线（如 `service_targets.tenant_id`） |
| 主键基类 | `BaseEntity`（id / createdAt / updatedAt） |
| 多租户基类 | `TenantAwareEntity`（在 BaseEntity 上加 `tenant_id` + 索引） |
| 改表策略 | 生产 `synchronize=false`；仅 `NODE_ENV=development` 或显式 `DB_SYNCHRONIZE=true` 才自动改表 |

## 2. 实体清单（66 个，按业务域）

### 2.1 多租户底座（6）
`tenant`（租户主表，含 `path/depth/scopeType/regionCode/orgChain` 层级字段）· `tenant_user`（租户↔用户）· `tenant_role`（角色，含平台预置）· `tenant_permission`（权限点字典）· `tenant_setting`（租户设置）· `admin_user`（管理后台账号）

### 2.2 用户 / 家庭 / 服务对象（5）
`user`（下单用户）· `service_target`（被照护老人）· `family_group`（家庭组）· `family_member`（家庭成员/监护人）· `review`（评价）

### 2.3 订单 / 陪诊 / 护工（6）
`order`（订单）· `order_service_plan`（订单服务计划项）· `service_plan_template`（服务计划模板）· `service_timeline`（服务时间线）· `attendant`（护工/陪诊员）· `schedule`（排班）

### 2.4 专业服务 / 医院（3）
`professional_service`（专业服务目录）· `hospital`（医院）· `hospital_doctor`（医生）

### 2.5 用药（6）
`medication_reminder`（用药提醒计划）· `medication_reminder_audit`（提醒变更审计）· `medication_execution_log`（服药打卡执行）· `medication_prescription`（处方）· `medication_notification_job`（用药通知任务）· `medicine_catalog`（药品字典）

### 2.6 健康 / 告警（7）
`health_alert`（健康告警）· `alert_rule`（告警规则）· `alert_log`（告警日志）· `alert_dispatch_rule`（告警派发规则）· `health_weekly_report`（健康周报）· `prescription_risk_report`（处方风险报告）· `drug_interaction_rule`（药物相互作用规则）

### 2.7 AI / 分诊 / 对话（8）
`ai_consultation`（AI 问诊）· `triage_session`（分诊会话）· `triage_session_message`（分诊消息）· `triage_feedback`（分诊反馈）· `ai_dialog_session`（机器人对话会话，含 crisisScore/qaStatus）· `ai_dialog_log`（对话单条，含 toolCalls/crisisWords）· `ai_agent_config`（智能体配置）· `crisis_word`（危机词库）

### 2.8 设备 / IoT（6）
`device`（设备主表：robot/radar/wearable）· `device_binding`（设备↔用户↔老人↔家庭/租户）· `device_event_log`（上行事件流水，含 dedup 去重）· `device_dp_snapshot`（DP 最新状态快照）· `device_online_history`（在线状态历史）· `device_config_log`（配置下发日志）

### 2.9 计费 / 订阅（5）
`subscription_plan`（套餐字典）· `subscription`（订阅记录）· `usage_record`（用量计量）· `revenue_share_rule`（分账规则）· `invoice`（发票申请）

### 2.10 财务 / 会员 / 咨询（5）
`finance_record`（财务流水）· `membership_card_type`（会员卡类型）· `membership_level`（会员等级）· `user_membership`（用户会员）· `consultation`（咨询预约）

### 2.11 统计大盘（3）
`stat_daily`（日统计）· `stat_hourly`（时统计）· `stat_realtime`（实时统计）

### 2.12 字典 / 系统 / 审计（6）
`system_config`（系统配置）· `audit_log`（审计日志）· `document`（文件/单据）· `complaint`（投诉工单）· `sms_send_log`（短信发送日志）· `mp_monitor_scene`（小程序监控场景）

> 合计 = 6+5+6+3+6+7+8+6+5+5+3+6 = **66**（与 `backend/src/entities/*.entity.ts` 文件数一致；`notification` 模块无独立实体）。

## 3. 关键表说明

| 表 | 关键字段 / 设计点 |
|---|---|
| `tenant` | `path`/`depth`/`scopeType`/`regionCode`/`orgChain` 支撑层级树与数据范围聚合 |
| `service_target` | 老人档案：`health_profile`(JSON)、慢病标签、首选称呼；多端共享 |
| `order` | 状态机字段、派单/抢单、定价、退款、分享 token |
| `device` | `tuya_device_id`(唯一索引)、`product_id`(涂鸦 PID)、`online`、`last_online_at`、`metadata`(JSON 兜底) |
| `device_event_log` | `dedupKey`(唯一)防 Pulsar 重投；将来按 `received_at` 分区 |
| `device_dp_snapshot` | 秒级读最新 DP，避免扫流水 |
| `ai_dialog_log` | `direction`/`emotion`/`crisis_words`/`tool_calls`(JSON) 全量留存，合规可检索 |
| `usage_record` | AI 用量/通话时长计量，billing 余额检查依赖它 |
| `audit_log` | 全量写操作 + MCP 工具调用审计，敏感级进运营审查队列 |
| `stat_*` | 大屏聚合预计算，减轻实时查询压力 |

## 4. 多租户列

- 28 个业务实体通过继承 `TenantAwareEntity` 获得 `tenant_id INT NOT NULL DEFAULT 1` + 索引。
- 5 个无基类的实体（`document` / `schedule` / `review` / `service_timeline` / `audit_log`）手动加 `tenant_id` 字段。
- 写入时 `TenantSubscriber.beforeInsert` 兜底注入；查询时用 `applyTenantFilter`/`applyTenantScope`。
- 详见 [`10-多租户三门户与计费.md`](./10-多租户三门户与计费.md)。

## 6. 字段加密

敏感列采用列级加密（`backend/docs/column-encryption.md`）：`insurance_info`、`id_card`、`phone` 等。AI/MCP 出参再经 `DesensitizeInterceptor` 脱敏（手机号中间 4 位、身份证尾 4 位等，见 `08`）。

---

## 7. 数据增长与分表（提示）

`device_event_logs`、`ai_dialog_logs`、`audit_logs` 是增长最快的表（10 万设备级别可达数十亿行/年）。
策略：按月分区 + 90 天归档 COS；10 万+ 用户时按 `tenant_id` hash 分库分表。详见 [`02-系统架构.md`](./02-系统架构.md) §6 与 [`11-部署与运维.md`](./11-部署与运维.md)。
